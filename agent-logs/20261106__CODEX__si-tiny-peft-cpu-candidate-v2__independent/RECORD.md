# Tiny random CPU Qwen with real PEFT: engineering result

Status: `TINY_CPU_PEFT_SYNTHETIC_CHECK_COMPLETED`; no research model, research adapter, CUDA context or environment was used. The one-time check constructed two fresh randomly initialized tiny Qwen base models on CPU, saved one synthetic LoRA adapter, loaded it through real PEFT and the production `SFTP0QwenPolicy._load`, placed the one-generation guard around the resulting cached model, and invoked the production policy once with a stub tokenizer/backend. The adapted product contained 4,480 parameters. This is an engineering interface result, not a performance, efficacy, or 8B memory-fit result. No rerun was performed.

The independently observed launcher child return code and outer return code were both 0; timeout was false and the original process group was not observed after direct-child exit. The parent measured 4.23 seconds elapsed and 581,140 KiB direct-child maximum RSS; this does not bound escaped descendants or unobserved resource peaks. Selected source hashes matched before/after; the imported dependency closure and native accesses were not traced. The PEFT library emitted a warning about a missing base configuration file for this constructed synthetic model. CPU-only observation reported CUDA uninitialized. A timeout or killed/unreapable parent would have different unknown-cost handling and is not tested by this successful run.

The persisted guard ledger records exactly one `claimed`, one `started` with input IDs `[1,5,6]`, and one `returned` with output IDs `[22,48,33,50]`, four output tokens. The deliberately simple stub decoded them to `T22 T48 T33 T50`; the production parser returned `action_format_violation`. This is the actual observed invalid action from the random synthetic model and is not corrected or counted as success. The operations ledger separately records each synthetic model construction, LoRA attach/save, PEFT load and policy act as started/returned. Stub tokenizer and backend mean the full production Qwen loader, real tokenizer, real adapter, real environment and device admission remain unvalidated by this check.
