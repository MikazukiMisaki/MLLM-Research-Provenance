# Independent code-read: six-unit real wiring design

**Decision: REVISE DESIGN BEFORE IMPLEMENTATION / NOT READY FOR LIVE EXECUTION.** Reviewed design SHA256 `e3256036cfa07ddf248851fcc4ebc837494924dbec730057854a7fdb887c8b26` against clean scientific commit `c90878eda6f131f96149bde8a546b0bb538637dd`. The design accurately identifies the main lack of a real campaign owner, global reservation lifecycle, explicit actor close and unique claims. Lifecycle ordering construct→load→reset→initial validation→model bundle load is consistent with `production_episode.py:182–188`; environment close in `:194–198` is cleanup after both success and failure. The six-arm order and the C-high positional confound are accurately described. Generation and environment-step ceilings and their 2-unit-per-arm / 6-unit totals are arithmetically consistent. All ceilings remain proposed until an actual independently reviewed implementation enforces them.

1. **BLOCKING: pre-owner input open can hang.** `real_bc_unit_worker.py:293–298` calls `read_bound_plan` before `_arm_owner`, including before parent-death protection. `:57–62` opens the input with `O_RDONLY|O_NOFOLLOW` but not `O_NONBLOCK`; a FIFO blocks at `open` before its later regular-file check. `fifo_pre_owner_fake_probe.py` exercised the exact function using a self-created FIFO, proved it remained blocked, and terminated/reaped only its own fake child. Probe SHA256 `abcccc6e4e470befef617cb5d677bc97757a95a68fee1f8615d1ea1efbb57ce5`; log SHA256 `e70f050d37ecc3a7cf377d4440fa283ccc1b5fb83b6039dbadf18b99c338eafa`. The design calls for owner supervision and an ACK but should require ownership/time control from OS process creation, before plan open and source validation; use nonblocking open plus fstat regular-file validation, and review any move of parent handshake and plan authentication separately. Parent-death signals do not cover time before arming and do not contain all descendants. No real worker or plan was invoked.

2. **BLOCKING: prompt-to-tensor linkage is proposed but not yet specified sufficiently.** `_PublicPromptCheckedPolicy.act` in worker `:178–188` computes and validates one public prompt, then calls `SFTP0QwenPolicy.act`, which independently computes the prompt, applies a chat template and tokenizes (`src/sft/policy.py:51–63`). `GenerationGate` observes tensor shape and generation arguments, not that prechecked prompt or rendered bytes (`production_episode.py:36–54`). The `rendered_prompt_sha256` returned by policy is only constructed in metadata after generation (`src/sft/policy.py:86–89`; journaled in `production_episode.py:114–116`). The design's desired prompt-hash reservation is therefore not currently implemented, and merely passing a previously computed hash into the gate would not prove that the actual token tensor corresponds to the approved prompt. Specify a one-use request identity and a reviewed mechanism binding the checked public prompt, exact rendered chat-template bytes and the actual token IDs/attention mask to the single model call before ACK, without changing treatment. Differentiate raw public-prompt hash, rendered-prompt hash and token-content/shape binding. Preserve tokenizer/template work and failures in cost accounting and make same-process mutation/TOCTOU uncertainty explicit; no snapshot or marker filter by itself proves semantic isolation.

3. **MAJOR: overrun accounting needs additional instrumentation.** `production_episode.py:59–65` journals `generation_call_returned` then, for invalid/oversized result shape, records only `output_shape_invalid`; it does not persist the actual returned length. The design's instruction to charge measured excess cannot be satisfied from that existing journal alone. An independent fake gate returned 19 tokens against cap 16: the call-return event existed but neither it nor the unknown event recorded the observed output length (probe SHA256 `2f2d2cb840913325ff964075020939ed71c4208c09fb1c30a2fe0c69ccda0c8a`, log SHA256 `ab0dce623bcae613cce1cb11e6924a2da7014c2cc910aeaa98b4cb61053a8cc1`). Add a safe, bounded count observation before raising when the length can be established, report it separately from validated return and retain the full reservation; after missing/truncated output, journal failure or unobservable length, physical excess remains UNKNOWN. An owner ACK may itself fail after durable reservation and must not trigger a retry or zero cost.

4. **MAJOR: hidden material and evidence custody are absent from the wiring acceptance.** `production_episode.py:69–96` collects hidden `_facts` and action groundings, and `:104`, `:135–147`, `:185` write state snapshots/groundings into the episode journal. The worker holds complete staged game inputs in the same Python process (`real_bc_unit_worker.py:227–233`). `validate_public_prompt` checks specific string markers and the action block (`src/sft/protocol.py:109–118`); it cannot prove that public feedback/action text lacks hidden information or that a same-process actor cannot access private game state. Require restrictive journal/input custody, leakage checks, upload exclusions and a separately justified actor/environment isolation claim. A prompt filter is not proof of witness or state isolation; unresolved exposure remains UNKNOWN.

5. **MAJOR: source-check and no-retry accounting need precise boundaries.** Worker `:138–150` runs `git` through inherited PATH and uses `git status --porcelain`, followed by package/runtime checks before unit claim `:203–210`. Git status can refresh index or use configured helpers; it is not necessarily a read-only, bounded source scan. Fix the reviewed executable/environment/config and disable optional locks/fsmonitor; budget helper launch, package trees, metadata and any writes, and do not treat a clean status as full byte identity. `_arm_owner` `:277–290` checks a direct PID/start tick and a GO byte but explicitly is not authenticated campaign ownership. A per-directory claim can be bypassed by a new output root or altered plan; a future durable global claim must bind the independently authorized campaign identity and canonical custody, survive restart/fail-closed recovery and remain outside worker-controlled deletion. Same-UID races, process escape and stalled fsync remain UNKNOWN. The design correctly notes these needs but its mere proposal is not proof of no retry.

The existing result categories and fail-closed intention are reasonable, provided `INVALID_SELECTION` is classified as a policy failure only under the preregistered endpoint and parser evidence; technical stops, missing return, failed close or journal/owner failure remain UNKNOWN. Call-return is not successful post-validation, and `generation_call_returned` should not be double charged as a second generation. Unit-level `journal.close()` is itself a possible failure after `unit_result` (`real_bc_unit_worker.py:247–253`); external process exit and journal integrity must both be preserved. The design is prospective and has not implemented any of these controls. No actual task content, model, CUDA or environment was opened or executed for this review.
