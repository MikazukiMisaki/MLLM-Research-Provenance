# Static compatibility review: historical ALFWorld game archive and frozen SI-U1 runtime

**Decision: compatibility unproven; no justification to insert old games into the frozen SI-U1 run.** This is source inspection and byte-level provenance only: no candidate task body read, patch execution, game extraction, TextWorld/ALFWorld/model/CUDA initialization, or experiment design. Current research code checkout is clean at evaluator commit `8532275932dabddc498c23a2b6d9a045647542f0`. Immutable versioned upstream patch source is [ALFWorld commit `beadec4de1de2485e8a260138a9ba2ac27a8865a`](https://github.com/alfworld/alfworld/blob/beadec4de1de2485e8a260138a9ba2ac27a8865a/scripts/patch_tw-pddl.py), copied as non-executable text solely for audit; SHA256 `da316f84570e71292d4f69f044422c756e8c02a26a7d60596d02e2cf3a24e415`.

## Facts established by source

1. The official merged [PR #94](https://github.com/alfworld/alfworld/pull/94) describes a command wording and feedback change, addition of help, and a patch for old games. Its version 0.4.0 release metadata points to the PR. This indicates a genuine version interface change; it does not prove a semantic difference in each particular task.
2. The pinned patch function parses an old `.tw-pddl` JSON object, creates `<file>.bak` if absent, then always starts from the backup. It appends help action text to the embedded `pddl_domain`, replaces literal grammar strings concerning `put`/`move`, placement and navigation feedback, appends a help grammar, and writes JSON back to the original filename. It selects a glob over the configured data root. Running it in the real data tree would change bytes/create backups and could touch more than a single candidate. No patch was run here.
3. The patch file's initial comment also says it separates `PutObject` into two actions; the inspected function body does not explicitly implement such a split. Its literal text replacements and additions are inspectable; absent a state-by-state validation one cannot treat the comment as proof the entire transformation, action rules or observable semantics are equivalent. Plain string replacements also do not assert that a target string was present in a given file.
4. The frozen production environment (`src/self_improvement/si_transfer_eval/live_runtime.py`, `src/self_improvement/si_p3/runtime_environment.py`) verifies exact game/trajectory/config hashes and exact task identity and then uses an isolated one-game instance. It is explicitly restricted to `train`. The frozen schedule gate in `src/self_improvement/si_transfer_eval/protocol.py` binds one exact 82-task TRAIN schedule and a three-arm plan. Existing 0.2 valid_seen/valid_unseen paths or an altered 0.2 train game cannot simply be substituted into that reviewed 853 protocol.
5. The isolated `OneHistoricalGame` overrides the stock `AlfredTWEnv.collect_game_files` to assign the supplied path directly. In the installed `alfworld` 0.4.2 source, the stock discovery method ordinarily skips movable/Sliced names, disallowed task types, missing games, missing `solvable` fields and `solvable=false` games; the overridden method bypasses those checks. Accordingly, existence of an old archive member, or exact game-path binding alone, is not proof of solvability, eligibility or current-runtime compatibility. No particular candidate was inspected for those properties.
6. `src/env/alfworld.py` returns the actual environment-provided ordered `admissible_commands`; `src/models/action_parser.py` assigns ephemeral A000… IDs by that order; `src/sft/protocol.py` renders those IDs and commands, recent action/result history and public observation into the P0 prompt. The evaluator resolves a selected bare ID using that current action map, then sends the mapped command to the environment. Wording, added commands, action ordering or feedback can therefore change the policy-visible input and/or ID-to-command mapping even if the Python prompt template, model and greedy setting remain fixed. This is a mechanism-based risk, not observed behavioral drift on a particular old task.
7. Existing local ALFWorld domain/grammar hashes are bound elsewhere and present in `FILE_HASHES.sha256`; the frozen task game itself is separately hash-bound. No assumption is made that altering global logic alone patches the embedded old game or that the official patch yields byte identity to the official current release.

## Necessary evidence before deciding whether any future experiment is viable

- Establish authorized archive source, exact original member hash, applicable terms, all recorded history/protected parent and layout exclusions, and immutable isolated input/output copies. Versioned old and transformed outputs must remain distinguishable and tied to a manifest; no overwriting originals or changing frozen 853 evidence.
- Separately review the migration implementation and exact input/version assumptions. Check transformation results and any version/solvability/eligibility contract with explicit non-content-leaking audit, including whether every expected substitution happened. Do not infer equivalence from a script comment or from a changed SHA alone.
- If a later scope permits environment-only engineering inspection, prespecify non-outcome-selected identity cases and budgets. Demonstrate loading, resets, action availability/order, observations/feedback, ID-to-command round trip, transitions and terminal/reward behavior versus suitable references; use only a separately reviewed program and account for every physical operation. Without matched old/current references for old-only members, such tests cannot by themselves prove individual behavioral equivalence or unobserved task success. Existing data or results must not be selected to obtain a desired comparison.
- Any new split, sample size or changed game treatment requires a fresh prospective scientific plan, a compatible independently reviewed runner, statistical estimand/power or precision, budget and full isolated provenance. Current assessment establishes none of these and authorizes no execution.
