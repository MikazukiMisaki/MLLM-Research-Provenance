# 两阶段恢复主线：子目标到动作的小样本观察 V1

本协议在首次模型生成之前确定。研究问题：当即时子目标由研究者给定时，Qwen3-8B 的动作选择能否选中与子目标对应的命令；将同一动作列表反转后，语义选择是否保持一致？这是对两阶段恢复**第二阶段**的受控文字观察，不运行环境，也不评估模型生成的诊断是否正确。

## 材料和比较

使用执行脚本内八个人工编写的虚构情境，每个情境含两个不同动作及分别对应的两个改写子目标，另加 `look`、`inventory` 两个干扰选项。每个情境的两个子目标分别比较：C1 按固定顺序排列四个动作；C2 反转整个列表并重新按位置分配 `A000` 至 `A003`。因此计划 8 × 2 × 2 = **32 个请求**、每键最多一次，按情境 01–08、子目标 1–2、C1 再 C2 顺序执行；固定顺序的时间漂移不可分离。

每个请求使用项目两阶段 V2 的第二阶段指令及裸 ID 格式；诊断和子目标是人工给定的文本，四个动作均为人工题面，不声称来自环境的合法动作。两个主要描述指标事前固定：每条件的正确选择数 / 8，以及每个子目标内 C1–C2 两次均格式有效时语义动作变化的配对数 / 有效配对数。每格分别列正确、错误、格式无效、截断、异常或未知；异常停批，未尝试不记作错误。配对分母为零时比例未定义，缺失及未完成原因单列。八个情境是便利样本、不是留出集，不做显著性检验或总体推断；列表反转同时改变位置与编号，无法分离两者影响。这里只测文本选择，不测成功概率、候选分布、第一阶段诊断、环境进展或终局。

## 模型、资源与停止

使用项目本地配置指向的 Qwen3-8B 缓存、单张 GPU、BF16，使用本地加载、禁用远程代码和自动下载；引用此前受信条件下的五分片摘要结果，不再次计算权重摘要。此次模型与运行环境身份依赖可信本机、配置与无不可见替换，日志或旧摘要不构成硬件鉴证。实际解释器、库版本、tokenizer 类、聊天模板摘要、EOS、设备和生成参数记录在运行日志；`enable_thinking=False` 是模板参数，不证明模型内部过程。

解码为贪心、每请求最多 16 个新增 token；输入上限 1,024 tokens，超过即停批不截断。固定 EOS 集来自实际 tokenizer 和模型生成配置并记录。保留输入 token 数、输出完整 token IDs、原始解码文本、开始和结束时间；只有完成并经严格 `A000`–`A003` 裸 ID 解析的返回才计有效，未以 EOS 终止且达到长度上限记截断。其他未能确认终止的形态或异常记错误并停止；格式无效和截断本身保留并继续。只在成功返回后通过列表映射语义，不对不完整输出猜测。

整个单批运行的外层墙钟停止触发设为 1,800 秒，Python 进程 CPU 时间上限 1,800 秒，单输出文件上限 8 MiB；逐请求自准备完成起至返回目标 120 秒（超过后不再发放下一请求；受阻调用由外层总时限终止）。选取设备启动前以及模型加载后、每次请求前后查询整卡显存，任一样本达到 43,008 MiB、查询失败或设备标识不一致时停止；查询为离散采样软触发，包含其他用户且可能漏峰，不是进程或整卡硬峰值。设备可用快照不是预约；如果存在更严格的实际设备规则，须遵守。观察不自动重试、续跑或更换任务；失败、部分输出和真实成本保留。
