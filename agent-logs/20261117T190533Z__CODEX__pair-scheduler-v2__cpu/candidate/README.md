# Pair-owned scheduler v2 — synthetic-only, research HOLD

**Not production-ready, not independently accepted, and not a scientific launch.** `fixed_product_dev/worker.py` remains byte-identical to the previous candidate and its `main()` raises `RESEARCH_HOLD` unconditionally. `scheduler_synthetic.py` always executes its own `fake_worker.py`; it has no real worker entrypoint. No true task input, model, tokenizer, ALFWorld, GPU or old batch was opened or called. All task cases, model/generation/environment effects and outcomes in tests are fictional. Earlier candidates and scientific artifacts are unchanged; previously consumed real costs are not reset.

## What changed

- The candidate parent schedules the fixed fictional versions of the four prescribed cases: a P0/CANDIDATE, b CANDIDATE/P0, c P0/CANDIDATE, d CANDIDATE/P0. It retains one fsynced global ledger and conservative token reservations, creates one shared pair materialization, verifies it before and after each fake arm, waits for each child, and only advances after a case/arm-matched close. A batch-complete marker requires all four setups and all eight closed arms.
- The stored initial public-state claim is **reset and rebound to each new case**. Within each pair, the second arm's reset claim is compared before its model-load label can be acknowledged. The positive test deliberately uses different fictional initial task IDs/observations across pairs and equal claims within each pair. These are child claims; neither true native state nor hidden-state equivalence is established.
- `process_guard.py` spawns no process itself. The fake scheduler starts each fake worker as its own direct session leader and records pid/start tick/parent/group/session. It waits for return code 0 and checks no members of that group remain **visible in the current procfs**. If a direct child times out it checks the same still-live child identity before sending SIGTERM **only to that child**, never to its process group or unrelated PIDs; observed return status is recorded. Unknown identity, incomplete procfs scan, live visible member, timeout, nonzero exit or unclear channel state stops the batch. This is not proof about processes hidden outside the container namespace, escaped descendants or GPU ownership/usage.
- The previous candidate's prepared-claim gap is narrowed: the parent rejects missing `public`/`rendered_prompt`, mismatched public-prompt hash, malformed input IDs/mask, wrong action map, and deviations from all six original fixed generation kwargs including `num_return_sequences=1`. The test explicitly rejects `num_return_sequences=2`, missing public and wrong prompt hash. It still cannot prove that rendered prompt tokenizes to the claimed IDs or that the worker/physical model used them. The four-pair fake worker synthesizes its prepared record; actual `_generation` is **not** wired or exercised by this candidate. Per-call upper bounds reserve 4096 input and 16 output tokens before ACK, without refund; these remain conservative reservations against child claims, not measured physical tokens.

Three CPU-only tests passed, real exit 0: four pairs/eight fake direct workers, direct-child cleanup timeout causing stop without budget refund or same-output retry, and malformed prepared-claim rejection. The positive test covers distinct initial states across cases. `synthetic-evidence/complete` preserves the full fake parent ledger, eight fake child journals/configs, child exit observations and fabricated inputs; `synthetic-evidence/stopped` preserves the separate cleanup-timeout ledger. In the retained timeout sample, only the owned direct fake child was signaled, its observed return code was -15, and no subsequent pair ran. Evidence-example and offline fictional ledger-chain audit both exited 0. These log checks verify the recorded bytes, not the authenticity of any physical effect.

The historical production worker/supervisor, genuine actor/producer/parser, actual native-success predicate, real task manifest, trusted process-origin/physical budget, global wall/time monitoring, GPU admission and reliable host-wide descendant cleanup remain unintegrated.
