# Independent assessment: mixed real-input, fake-edge B smoke

Reviewed the design proposal SHA256 `77b31730d702cf997db1ee4215d8b630654e498dc96767e1715fc6a56577686e`, its metering/effect addendum, the relevant `850b2a322e6285ab0d97bfad415354336523fd01` source and current operating-system capabilities. **Decision: technically plausible and useful as a bounded *engineering* step, but the proposal is not yet a runnable or independently reviewed smoke.** It cannot establish model quality, real environment performance, protected-task isolation, independent custody or scientific efficacy. No product contents, model, ALFWorld, CUDA or protected task were accessed for this review.

## Concrete input metadata and budget

The training preflight was checked against its explicit authorization. Metadata-only traversal of its base and P0 roots, plus the coordinator-provided C-high and C-low roots, found the following one-traversal logical sizes (not physical reads): base 16,397,431,693 bytes; P0 365,138,109; C-high 349,250,053; C-low 349,250,053; total **17,461,069,908 bytes = 16.2619 GiB**. The base contained 12 file symlinks whose resolved targets were inside its declared cache; the three adapter trees contained 17 ordinary files in total, no links, and no hardlinks were seen in the inspected regular-file entries. Small C-high supervisor/result receipts were read and matched their provided hashes and result/adapter lineage. Product bytes were not rehashed, and C-low and C-high roots were supplied by the coordinator rather than frozen in an actual B plan. The metadata result is a point-in-time observation, not authenticity or race-free future-open proof; source roots, symlink targets and underlying device/inode/size must be rebound at dispatch.

Including the prior reported package-tree metadata size, the known subtotal is **19,076,853,781 bytes = 17.7667 GiB** for one pass through these scopes. The proposed 24 GiB planning target has about **6.2333 GiB** of arithmetic room before accounting for repeated source/receipt reads, package entrypoints, B/domain inputs, output, setup, failed calls, audits or margin. It is not a hard limit, complete actual budget, physical I/O measurement, or proof the run fits. Count exact multiplicity from the call graph: package entrypoints and interpreter are read separately, training receipt files are hashed and read again, supervisor/outer evidence is revisited, and staged B bytes are read and copied. Sum the real prior development costs separately and avoid counting cached reads as zero.

`tree_sha256` accepts a symlink to a regular file and follows it. Therefore hash verification can read outside a named tree unless every authorized target is checked. The pre-inventory found only base links inside the explicitly declared cache, but a same-UID writer can change names after this check; non-following descriptor-relative opens or a reviewed immutable snapshot/broker would strengthen enforcement. If these are unavailable, use the observed point-in-time manifest, recheck immediately before opening, fail closed on new/changed targets and honestly retain TOCTOU/hardlink provenance as UNKNOWN. Do not scan unknown historical/held-out trees to try to prove a negative.

## What can and cannot be enforced economically

An independent synthetic check of the proposed seccomp helper (helper SHA256 `f11401e0067789975c2fe7b6f2f8162f9cc575633e36fb8876120cfd09d7d352`) confirmed EPERM for new IPv4 and IPv6 sockets, socketpair, connect and a non-FIONBIO ioctl; a deliberately preopened Unix owner channel remained usable, and the filter survived exec into a child. It ran in a disposable fake subprocess and opened no GPU. This is evidence for the exercised syscall cases, not a complete sandbox, proof of no GPU use or absence of all network paths. The current kernel returned ENOSYS to a Landlock ABI query; an unprivileged user/network namespace attempt returned EPERM; `strace` and bubblewrap were not found. NVIDIA device files are world-readable/writable at the checked metadata point. An empty visible-device variable, a fake identity record, a denied ioctl on a different device or a `nobody` UID alone cannot prove that no GPU device was opened or no CUDA/library code was reached.

The user has authorized forward progress. A practical staged engineering attempt need not first solve complete scientific custody or GPU isolation: pin and independently review the *actual* bootstrap, run owner and child in a fresh exclusive directory with explicit fake-only labels, arrange the AF_UNIX channel first, close all other inherited descriptors, then install and observe the tested seccomp filter **before** importing project code and before any effect is possible. Its blocked socket/connect/ioctl paths, inherited-descriptor list, Python and native library/import behavior, exact overrides, entrypoint, stdout/stderr and wait status need retained evidence. Bound the direct process with a monotonic outer deadline, output/CPU limits where the implementation can actually enforce them, no retry, and sampled aggregate read/exit observations. An `rchar` polling stop threshold with margin is a best-effort early stop and can overshoot; label missed descendants, mmap/native I/O, physical device reads and any unmetered tail UNKNOWN. Preserve data and stop rather than relabel incomplete observations as pass.

This supports a **qualified software smoke** only if its predeclared contract is limited to the checks actually observed: reviewed code path, selected pinned input verification, explicit fake model/environment edges and partial syscall controls. The bootstrap is not yet implemented/frozen/reviewed and no B-only plan currently exists. A hard requirement to prove that no CUDA/device/network access or no unauthorized file read *could possibly occur* cannot be met by the current observations alone; it needs a demonstrated stronger device/file/IPC boundary or suitable tracing, not a stronger wording of this smoke. Static source and monkeypatches are useful accidental-call controls but cannot by themselves prove all native behavior or same-process secrecy.

## Minimum blockers before the single attempt

1. Construct and independently review the exact B-only plan and one-use launcher; bind commit, clean checkout, interpreter/package/source identities, actual environment, all four authorized product roots, expected receipts and allowed symlink targets. Do not silently equate the old training authorization or synthetic negative plan with this new plan. For B, `stage_pinned_case` source selects only the exact named problem, grammar and public domain, but the rest of the process is not confined by that function. Never read witness or held-out paths; preserve absence as bounded code/observability evidence, not a claim of a filesystem sandbox.
2. Review the test-only activation and exactly which calls are overridden. Real P0 `act`, parser, episode, gate and owner may be exercised against fake tokenizer/model/environment while real product validators remain unmodified. Deny or fail immediately at actual tokenizer/model loading, CUDA initialization and actual PDDL/ALFWorld construction. Label identity, placement, generations, actions, observations, state and outcome as **fake** in an authoritative run envelope; the existing normal-looking event schema alone is insufficient. Bind the fake-only envelope to the same unique output and do not release raw B contents or weights.
3. Verify conservative read multiplicities, disk space, source drift, executable filter and time/resource controls before any large read. Use a predeclared admission threshold and reserve margin but describe 24 GiB as a planning target unless actual hard mediation is implemented. If the budget cannot be justified or an unexpected link, FD, protected file or effect is observed, stop and retain costs/UNKNOWN. Do not claim that a sampled process list or the currently rejected descendant-tracker candidate proves complete cleanup.
4. Launch at most one B fake-edge probe with a new identity, preserve its real return code and owner/journal records, and independently audit them. If it stops or observation fails, do not automatically retry or extrapolate zero work. C remains a separate owner/schedule problem. The low adapter's prior status remains `INNER_COMPLETED_OUTER_UNKNOWN_NO_RETRY`.
