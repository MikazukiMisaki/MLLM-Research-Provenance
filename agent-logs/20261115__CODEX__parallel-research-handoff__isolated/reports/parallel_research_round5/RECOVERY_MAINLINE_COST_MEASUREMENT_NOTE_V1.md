# 恢复主线：两阶段输入成本中的未知值

## 发现与影响范围

对现有采集代码的静态检查发现：`scripts/collect_sprint2c_paired_corpus.py` 的 `_cost_record` 将两阶段 `input_tokens` 中的 `None` 用 `or 0` 转成零，并以此计算总输入 token 和总 token；`aggregate_pairs` 随后对这些值计算均值。而 `TokenStatistics.input_tokens` 允许为 `None`，采集器的各阶段记录也分别保留 `input_tokens` 原字段。

因此，**如果**某条历史或未来记录的阶段输入数确实缺失，成本汇总可能把未知成本误报为零并影响均值。此处没有读取该实验的任何实际记录或计算该问题出现过多少次，不能据代码缺陷断言既有论文数字有误，也不能把缺失成本当成零或直接重算冻结批次。

## 处理

保留历史采集器和其冻结协议原样；[独立成本复核工具](../../src/analysis/recovery_cost_reporting_v1.py)接受调用方已获授权的内存记录，从 `recovery.stage_one.input_tokens` 与 `recovery.stage_two.input_tokens` 重建两阶段输入成本。单阶段未知保留 `None`，两阶段之和只在两者均已知时计算；汇总按恢复记录计数并列每阶段与总量的已知/缺失数量。全体记录的均值只有在所有该项数据均已知且记录数非零时才给出，避免改变分母或将缺失填零。实际为 0 的已知输入仍保留为 0。

该工具不打开文件、不运行模型或环境、不证明任务来源、执行或同次绑定。它目前没有接入历史采集器，也未用于任何真实数据；因此未修复历史文件中的数值或证明哪些结果受影响。实际复核必须先确认数据访问权限、任务身份排除要求和原协议的停止规则，不能读取方向 2 的受限窗口包或通过改名恢复已暂停分析。结果单位是恢复记录，多个恢复臂可能复用同一任务，不能误写成独立任务数。
