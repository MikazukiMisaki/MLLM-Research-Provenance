Candidate `7cf4fec0010e5d87435766e60d0a64930c3d39a3`; clean isolated worktree, complete five-file delta inspected and `git diff --check` passed. **Decision: FAIL safety review.** Its limited synthetic observations do not establish process-tree containment or GPU ownership; real entry remains closed. No real model, environment or protected task ran.

## Blocking findings

1. **Process-wide subreaper state is not restored.** `OwnedChildTracker.__init__` verifies the prior `PR_GET_CHILD_SUBREAPER` value is 0 and then sets it to 1. `finish` closes pidfds but never restores 0. A synthetic isolated supervisor with its own short-lived direct child observed before/init/after-finish values `0/1/1`. A separate injected failure immediately after the `prctl` set also leaves 1. Failures before direct registration or the caller choosing not to call `finish` leave the same open lifecycle. The flag changes future orphan adoption in the process and can affect unrelated subsequent work. Restore prior state on all initialization, normal, exception and cancellation paths, and test restoration independently; do not pretend cleanup or adoption becomes complete when an observation fails.
2. **An unproven child can be reaped.** `scan` classifies a newly observed owner child not already registered as `ADOPTED_OR_UNOBSERVED_LINEAGE`; `_reap_exited` then calls `waitid(P_PIDFD)` for every exited non-direct node regardless of this attribution. In an isolated test the owner enabled the tracker, registered its own worker, then independently created its own unrelated second child. The tracker attributed the second child as unobserved lineage and reaped it; its original owner subsequently got `ECHILD` from `waitid`. No signal was sent to that process, and all involved processes were created solely by the test. Initial no-child and single-thread checks do not enforce absence of later independently created children. Never wait/reap a node whose ownership/ancestry is not positively established; retain it as UNKNOWN and avoid stealing another subsystem's wait status. The author's test expecting unobserved adoptees to be reaped conflicts with this safety requirement.
3. **Direct-worker termination still uses a PID rather than the held pidfd.** `supervise_one` calls `Popen.terminate()`/`kill()` on timeout or failure. The active Python 3.10 `Popen.send_signal` implementation polls and then uses `os.kill(pid, signal)`, and its own source identifies the PID-reuse window between the checks and `kill`. This is a static, concrete race window, not an observed mis-signal. The tracker already has the direct child's pidfd; direct-worker signaling must also use verified pidfd identity and handle PID-reuse/failure cases fail-closed. No process outside the tests was signaled during this review.

Observed descendants are signaled through held pidfds and an initial parent/start-tick chain; that useful mechanism does not fix these defects or prove unseen descendants absent. Unknown adoptees, escaped processes, process-namespace assumptions, device cleanup and physical tail remain UNKNOWN. Any future implementation must address owner identity, own-child verification, inherited descriptors, error/double-close paths, monotonic deadlines and cleanup budget without broad process-name or process-group killing.

Independent tests used isolated Python supervisors and only short-lived children they created. Three tests demonstrated the two bugs; five existing fake tests also ran: eight tests in one subprocess, exit 0. Successful tests reproduce findings, not a safety PASS.
