This document derives from `../20261106__CODEX__si-four-causal-development-groups-v3__independent/PROTOCOL.md` SHA256 `9d946a3c4054225d9909d3aab3f57eef09a36e91e3d5d82d67af8cad1c1aaaa3`. No model, tokenizer, environment, PDDL/grammar parser or GPU was invoked; no protected task/trajectory was opened. Review this design before selecting or freezing concrete task values. Existing scientific code and prior artifacts stay unchanged.

The result, if later implemented, is **DEVELOPMENT_ONLY**. All four groups share public source and an authoring process; A has a known conceptual relationship to the earlier heat/drawer case. Internal group distinction and byte hashes do not prove independence from unknown historical tasks, evaluation data or pretraining. Those relationships remain UNKNOWN; no output may be called held-out or independent evaluation evidence.

## Fixed contract and inputs

- Version the interface `dev-alfworld-4groups-spec-v1`, renderer `dev-alfworld-render-v1` and signature scheme `dev-alfworld-role-signature-v2`. Bind implementation source SHA-256 and interpreter/runtime version in each generated manifest. A changed rendering, template, source domain or signature rule requires a new version and byte pins; this revised document defines preimplementation v1 interfaces but does not claim the draft design is unchanged; never silently regenerate old bytes under the same identity.
- A trusted caller holds a verified input directory fd, binds its `(device,inode)` identity and supplies exact per-file `(device,inode,size,SHA256)` commitments for fixed allowed leaf names. Before any read, confirm directory identity/owner/permissions, reject symlinks and nonregular/hardlinked leaves, compare no-follow leaf identity, open via that fd with `O_NOFOLLOW`, then fstat/recheck and bound byte reads. Source/spec/domain/grammar are all fixed allowed leaves; never accept arbitrary paths or read a path first and hope its later hash makes it safe. Anchor root-fd selection itself is a trust boundary: a held fd prevents ancestor symlink substitution from redirecting subsequent leaf opens, but malicious same-UID writers, source replacement between checks and fd duplication remain outside the guarantee. Caller-selected path strings are not an authority. For future public inputs verify `alfred.pddl` SHA256 `f1473041ed01da514de1f87adfd7ef0804862361f83ccf63c75e43633b0eb280` and `alfred.twl2` `c5b22f0f73309a7fd7c8e5b71de42ad4803b60766ab4a51cc2feb34162be036b`, then use those exact in-memory snapshots. Paths are local trust-anchor setup, recorded separately from portable semantic data; no hard-coded machine path, credential or protected data is committed. A missing file, invalid UTF-8, hash/marker mismatch or later changed input means no published case.
- The strict batch specification is a JSON object with exactly `schema_version`, `renderer_version`, `signature_version`, `interpreter_version`, and `cases`; its four ordered case entries have exactly `group_id`, `case_id`, `roles`, and `lineage`. The single required `interpreter_version` is the exact expected `major.minor.patch` and every case inherits it; compare that input to the active interpreter before rendering or writing. The reproducibility guarantee is conditioned on identical pinned interpreter version, source snapshot, specs and other input bytes, not across arbitrary interpreter versions. `group_id` is A, B, C or D; `case_id` and each role ID are ASCII identifiers matching `[a-z][a-z0-9_]{0,31}`. Role maps have exactly the fields in the next table; values are distinct identifiers except where a template explicitly reuses the same role. Reject non-strings, booleans used as numbers, duplicate JSON keys, unknown fields, excessive input size, all cross-role aliases after case-folding and collisions with the actor ID, PDDL keywords, types or any of the five named domain symbols. No arbitrary PDDL fragments, free-form goal text, arbitrary shell, paths, Python code or random source are accepted. The generator contains no RNG; output is a pure function of pinned input bytes, versioned source and strict spec. A seed would imply unsupported variation and is omitted. A securely pinned fixed-leaf source snapshot hash is recorded, but this alone does not authenticate the currently executing in-memory module; verified loading/external custody remain separate boundaries.
- Five named domain symbols are always declared once: `MicrowaveType`, `SinkBasinType`, `FridgeType` as `rtype`; `KnifeType`, `ButterKnifeType` as `otype`. Case-insensitive uniqueness is mandatory. Define stable internal IDs for `actor`, object/receptacle type IDs and locations mechanically from role IDs, with a namespace mapping that is injective under case-folding and checked against all user-supplied IDs and named symbols. The task's IDs are also the expected human-visible names; actual TextWorld rendering remains unverified.
- `lineage` has exactly `node_id`, `links`, `external_overlap` fields. `node_id` is the case ID; `external_overlap` is the literal `UNKNOWN`. `links` is a bounded list of objects with exactly `other_node_id`, `relation`, `evidence_sha256`; relation is one of `DERIVED_FROM`, `RENAMING`, `PARAMETER_VARIANT`, `SAME_MECHANISM`, `SAME_CASE`, and evidence is a lowercase 64-hex digest or JSON null when no document is available. Duplicate or self edges, unknown relations and invalid IDs are rejected. A's entry includes an explicitly designated conceptual-parent `DERIVED_FROM` link; absence of its independent historical content is recorded honestly, not searched. Group B–D links may be empty when no permitted link is known, with external overlap still UNKNOWN. These are provenance assertions with supporting digests when available, not a proof that an ancestry claim is true or globally complete. No user identity, machine paths, credentials or protected content enters distributable manifests.

## Frozen preconditions and absence semantics

For each generated case, validate exactly one actor; all object/receptacle role IDs and all navigable role locations are pairwise distinct except explicit same-role reuse. The actor has exactly one initial location; no `holdsAny(actor)`, no `holds(actor, x)` and no holding relation involving a task object is initially present. Each item has exactly one declared source membership and matching source location, with no competing initial receptacle/location or destination membership. A's source, sink, microwave and destination locations are explicitly four distinct locations; B fixes its worktop to **non-openable**, satisfying the source action's non-openable-or-open disjunction without an unspecified choice. B item/knife, C item_one/item_two and D item/lamp are distinct.

All individual goal conjuncts must be false under the specified closed-world initial facts: A item neither clean nor hot and not in destination; B item not sliced and not in destination; C neither item cool nor in destination; D lamp not toggled and item not in destination. Destinations declared closed/openable lack `opened`; source types and `canContain` permit the stated pickup and put. Explicitly reject any contradictory or nonexclusive facts in the IR; unique IDs alone are insufficient. These are syntactic/generator checks, not proof of production parser or runtime behavior.

## Deterministic PDDL and grammar construction

First build a typed in-memory intermediate representation (IR) from fixed templates and validated role names; do not parse unrelated PDDL or import TextWorld. The IR explicitly contains object/type declarations, initial positive facts, expected absent facts under PDDL closed-world semantics, goal conjunction, and a fixed symbolic witness. It is not itself evidence that the external parser accepts the resulting PDDL. Domain action names and predicates come from the exact pinned public domain; absent predicates mean false only under the relevant closed-world interpretation. Every `PutObject` target has explicit `receptacleType`, `objectType`, `canContain` and, where applicable, `(openable destination)`; the closed destination starts with no `opened` fact. Counter/worktop sources are not openable in these templates.

- **A IR:** one target in source, actor at source; `pickupable`, `cleanable`, `heatable`, object type; sink `SinkBasinType`, microwave `MicrowaveType`; source/sink/microwave/destination each with matching distinct location; destination type can contain target and is openable but not opened; goals `isClean(item)`, `isHot(item)`, `inReceptacle(item,destination)`. Symbolic witness: take, go sink, clean, go microwave, heat, go destination, open, move — 8 steps. Clean and heat commute in inspected effects; no invented mandatory ordering claim.
- **B IR:** target and knife are pickupable and in worktop, each `objectAtLocation` worktop; target `sliceable`, knife `objectType KnifeType`; worktop type can contain knife, destination type can contain target. Goals `isSliced(item)` and `inReceptacle(item,destination)`. Witness: take knife, slice, move knife back, take item, go destination, move item — 6 steps. Verify `holdsAny` and knife-release dependency explicitly.
- **C IR:** both distinct items initially in source, each at source location, each pickupable/coolable with a type, fridge `FridgeType`, destination type compatible with each item; actor at fridge. Goals both `isCool` and both in destination. Witness: for item_one then item_two, go source, take, go fridge, cool, go destination, move — 12 steps. Neither order is a claimed asymmetric causal requirement; single-hand capacity is shared.
- **D IR:** lamp and target initially in source at source location, lamp `toggleable`, item `pickupable`, destination compatible and closed/openable; `isToggled`, `isOn` and `opened` absent initially. Goals `isToggled(lamp)` and `inReceptacle(item,destination)`. Witness: use lamp, take item, go destination, open, move — 5 steps. Text says **use** the lamp, not that it remains on. Public grammar's feedback after repeated toggles may not describe `isOn`; do not equate that wording with actual state.

Render PDDL using canonical UTF-8, LF line endings, exactly one final newline, no nondeterministic timestamps; stable casing for schema keywords/predicates, stable section order `(define (problem ...))`, `(:domain alfred)`, `(:objects ...)`, `(:init ...)`, `(:goal (and ...))`, `(:metric minimize (total-cost))`. Sort declarations by fixed type order then ASCII ID; sort facts and goal atoms by their canonical case-folded predicate/argument tuple, except numeric `(= (total-cost) 0)` has its designated position. Preserve the PDDL distinction between typed object constants and predicates, and between a named location and a receptacle; ensure all referenced IDs are declared exactly once. Use an explicit literal writer for the finite whitelist of schema symbols and validated atom arguments, never untrusted interpolation into arbitrary syntax. Fail if an IR fact conflicts with another, a goal is initially true when the template requires it false, or the fixed witness's source-level preconditions do not hold.

Construct one task sentence per IR, with fixed versioned templates, safe role IDs and simple English conjunctions matching **all and only** goal conjuncts. A says clean and heat the item and put it in the destination; B says slice the item and put it in the destination; C says cool both named items and put both in the destination; D says use the lamp and put the item in the destination. A and D text must not assert a required action order beyond the actual goal; conjunction is sufficient. Include a final period. Do not insert semicolons, newlines, quotes, braces, hash markers or other grammar metacharacters in the task text. This matters because an earlier multi-object draft used `; ` between subtasks, while the installed TextWorld textgen literal source excludes semicolons; this design avoids that unverified failure rather than assuming the two syntaxes agree.

Start from verified public `alfred.twl2` bytes and require exactly one occurrence of `Your task is to: UNKNOWN GOAL.` in the expected quoted RHS; replace only that exact marker with the validated fixed goal sentence, preserving every other byte. Use a JSON-string-safe writer or tightly validated ASCII sentence so that a role cannot escape the grammar RHS. Verify the derived grammar differs from public input by exactly the single task replacement, the old placeholder appears zero times, and the exact new RHS `Your task is to: <goal sentence>.` occurs once. The final period is part of the sentence and must not be duplicated. The source `#intro#` contains `#look.feedback#` and `#task#`; source-level goal text consistency is not proof of runtime feedback. Never add plan, hidden state, expert action or feasibility trace to task text or policy inputs.

## Grouping and deterministic duplicate evidence

- The generator creates, from the role-level IR, an exact case signature and a group mechanism signature. Each canonical JSON document is UTF-8, keys sorted, separators `,` and `:`, ASCII encoding of non-ASCII strings, and one trailing LF; compute SHA-256 over these exact bytes. The exact signature binds declared types, positive init, explicitly expected absences, goal, witness and group version after internal deterministic role labeling; it does not depend on display names. It is a signature of the declared template, not a full semantic-equivalence proof.
- For exact role-renaming normalization, replace case-specific object IDs with their fixed abstract role names before serializing. C additionally computes both item-role permutations and chooses the lexicographically smaller serialization; fixed role classes prevent exchanging an appliance with an item. Sort conjunctions/facts as above. No unrelated distractors are allowed in v1; if future versions add them, they need an explicitly versioned relevance rule before comparison. Reject same normalized signature within a batch, even if filenames, words or object IDs differ.
- A mechanism signature records group version, predicates/goals, number and roles of goal objects, required appliance/tool and access preconditions, causal dependencies (`holdsAny` exclusivity / tool release / process prerequisites / container openness), and independent or interchangeable conjuncts. It does not use desired outcomes or run results. All parameter variants of the same mechanism group are one lineage for this protocol. If different labels yield identical normalized signature, or the predeclared causal signatures are not distinguishable, stop and report duplicate/ambiguous rather than treat them as independent groups. Record sorted pairwise group/signature comparisons, exact match decisions and fixed reasons; do not create a numerical similarity score or adaptive cutoff after any run. This is a limited within-batch structural check, not exhaustive graph isomorphism, historical search or proof of semantic independence.
- Construct lineage components as a deterministic transitive closure (union-find over undirected grouping edges) of known `DERIVED_FROM`, `RENAMING`, `PARAMETER_VARIANT`, `SAME_MECHANISM` and resolved `SAME_CASE` edges; retain directed ancestry separately. A's known earlier heat/drawer conceptual parent is linked; common public-domain use alone is not a derivation edge. Include nodes for the four proposed cases and allowed known parent references; sort node/edge IDs before serialization and give each connected component ID SHA256 over UTF-8 canonical JSON of its sorted member-ID array (sorted keys, compact separators, one trailing LF). Add a `SAME_MECHANISM` edge for every pair of the four candidate specs whose fixed mechanism signatures match; link edges from supplied provenance are normalized for grouping, while `DERIVED_FROM` direction is also retained in the audit. An unsupported edge/evidence claim is UNKNOWN rather than silently accepted as verified provenance. If two proposed groups land in one component, they are not distinct groups. An ambiguous comparison within this four-case batch yields `UNKNOWN` and stops batch qualification. Unavailable or protected historical links are `UNKNOWN`, never an instruction to search them or a negative independence assertion; lack of an observed link is not proof of independent lineage.
- Freeze exact group order A→B→C→D before any feasibility call. All four case specs are reviewed as a set; no selection/replacement based on parser, engine or model outcomes. Same authorship/public domain is shared provenance and must remain explicit.

## Artifacts and hash conventions

For each future generated case, create a new output directory using an exclusive create policy and never overwrite an existing case. Write and hash:

1. `problem.pddl` and `derived_grammar.twl2` exact bytes; public domain remains an external pinned input, not silently altered.
2. `spec.json` canonical exact versioned parameters and role-to-ID mapping; `structural_signature.json` canonical role-normalized facts/goals/trace and `mechanism_signature.json` exact canonical mechanism bytes; `case_signature.sha256` and `mechanism_signature.sha256` bind those corresponding exact bytes so an offline reviewer can recompute them. Witness actions are development-only evidence and kept separate from model-facing task/grammar.
3. `manifest.json` with schema/renderer/signature versions, source SHA, input public hashes, spec hash, output byte hashes, case and group signatures, conceptual parent, authorship category, static check status, `DEVELOPMENT_ONLY`, `held_out=false`, `history_overlap=UNKNOWN`, `pretraining_overlap=UNKNOWN`, `runtime_solvability=UNKNOWN`. No self-hash field: a manifest hash is recorded by the batch index, avoiding recursion.
4. A deterministic `batch_index.json` in frozen group order, containing the four manifest hashes, pairwise duplicate results, public input pins and generator source hash. It is created only after all four cases and batch checks succeed; a failed/interrupted generation stays a partial, explicitly unusable output and cannot be mistaken for a complete batch. `batch_index.json` SHA is recorded separately outside itself. Partial writes and filesystem durability are implementation concerns to document; an ordinary hash is not an independent provenance or custody attestation.

No outputs in this design turn are concrete case specs or generated tasks; no future claim of global uniqueness follows from comparing these four files.

## Implementation and verification handoff

After independent review of this proposal, implement in a fresh research-notes directory without modifying the authoritative worktree or previously frozen tasks. First implement pure IR/render/signature functions; use only self-created synthetic specs and temporary files in tests, not a production parser or environment. Tests must verify deterministic byte-for-byte output, schema/header/typed-object/goal/precondition invariants, all four planned action-state transitions, causal difference by group, correct Unicode/ASCII identifier rejection and collision handling, grammar replacement/semicolon rejection, malformed/duplicate JSON keys, missing/mismatched source hash, PDDL injection attempts, unique/absent goal markers, complete closed-world initial conditions, and rejection of contradictory/wrong type/alias cases, empty-hand and unique-location/receptacle invariants, every initially false goal conjunct, pairwise location separation, and transitive lineage-chain/ambiguous-pair cases. Mutating inputs or changing C's two object names/order must not evade the stated same-mechanism grouping. Test output hashes and commands; test filesystem collision/partial output and no-overwrite behavior. These are design-level/pure synthetic validations, not proof of real parsing or solvability.

Only after that generator and the resulting exact case bytes are independently examined may any separately scoped model-free parser/engine feasibility work be considered. Its proposed separate bound is from the preceding protocol: at most four parser diagnostic children and four engine children, four construct/load/reset/close attempts, 31 step starts and 35 reset-plus-step starts in total, with every normal negative, technical error or UNKNOWN stopping all later groups and no retry. A normal negative requires complete, internally consistent observed state/score/terminal evidence; missing fields, incorrect grounding or contradiction with a required source-level action effect are technical UNKNOWN. Only complete positive advances the group sequence. Up to 12 named top-level parser calls and 16 source-expected PDDL-to-SAS function calls are separately noted; actual internal/native/descendant, aggregate CPU/RAM/disk and prior costs remain UNKNOWN, and no GPU/model calls are included. This design does not itself authorize or start such calls.

Prospective feasibility implementation must request `EnvInfos(policy_commands=False, extras=[])` and no expert/walkthrough data, and reject incompatible configuration before environment work. Pinned TextWorld source can invoke `_pddl_state.replan` when policy_commands is enabled; this unbudgeted planner path is forbidden, rather than assumed absent. The direct source-expected PDDL-to-SAS calls and all unobserved internal work remain separately accounted/UNKNOWN.

## Explicit output trust and time receipt

A trusted caller supplies a separate held output-directory fd with pinned device/inode and validated ownership/permissions. Create only fixed leaf names with `openat`/`dir_fd`, `O_CREAT|O_EXCL|O_NOFOLLOW`; write and fsync each file and directory, and publish the batch index last. No overwrite, partial output stays unusable, and local fsync/write errors remain UNKNOWN: a readable final leaf after failed fsync is not proof of a durable completed batch. Same-UID writers and an untrusted caller selecting an outside directory are not prevented by fd-relative operations. A future real entry needs fixed trustworthy root selection; this design does not equate path hashes with authorization.

Deterministic spec, case manifests and batch index never contain current time, PID, machine paths or author secrets. After batch write returns, separately create `runtime_receipt.json` with exclusive write, bind its `batch_index_sha256`, capture actual system UTC at receipt creation and a caller-declared non-identifying author category, and label the clock and local custody unverified. The receipt may be later than case preparation; it is not pre-execution commitment, not a backdated statement and not an independent timestamp or power-loss attestation. A failed/uncertain write or missing receipt remains UNKNOWN.

The fixed four-template signature comparison is deliberately narrower than general dependency-graph isomorphism, semantic equivalence or arbitrary near-duplicate detection. It records structural facts, group-specific causal features and transitive known edges; comparable within-batch collisions stop qualification. Anything outside those finite templates or with ambiguous provenance must remain UNKNOWN rather than be declared distinct.
