# CPU-only coordination prototype

Status: prototype only; no research execution authority, no completed production integration, and no independent acceptance. This directory is separate from existing runs and scientific source. The tests use fictitious strings and subprocesses only. No real materialization, ALFWorld, model or GPU is invoked; no experiment is launched or restarted.

The synthetic owner creates a persistent exclusive claim, journals hash-linked reservations before starting a subprocess, fsyncs the journal, and records returned fake receipts. Limits are four setup effects and eight arm effects; one setup must return before either arm. A child failure leaves its reservation open. An existing claim prohibits a second owner or resume. The auditor detects truncated, modified, internally inconsistent, or open records. Running owner rechecks the journal before appending and stops on a discrepancy. Four fake pairs use alternating order and isolated fake child processes.

This is not a budget service ready for an experiment: it has no production runtime/IPC, secure filesystem isolation, real materialization, live GPU ownership/admission, scientific model calls, full generation/step/token/wall budgets, source-binding, actual public-state checks, process-group cleanup, real stop/signal accounting or independent reviewer approval. The synthetic setup only returns a fake receipt and does not prove real task materialization or isolation. An append failure that physically writes a record may leave its interpretation uncertain; a new owner is deliberately prohibited. The separate EOS issue and previous incurred costs remain unresolved by this prototype.

Test: `python -m unittest -v test_prototype` (7 tests, exact output and actual return code in test-output.log and test-receipt.json). Temporary inputs are generated by tests. Source and test file hashes are listed in FILE_HASHES.sha256.
