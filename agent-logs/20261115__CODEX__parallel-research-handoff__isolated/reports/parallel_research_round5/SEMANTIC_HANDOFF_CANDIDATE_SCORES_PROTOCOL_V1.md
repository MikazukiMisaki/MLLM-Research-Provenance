# 主线补充：四个动作编号的条件得分观察 V1

**首次评分前固定；属于观察到前一批 32/32 正确之后提出的探索性跟进，不是事先注册的验证。** 使用[上一批主线文字观察](SEMANTIC_HANDOFF_PILOT_RESULTS_V1.md)已暴露的 32 个虚构提示，研究把四个合法动作编号作为完整候选回答评分后，正确动作的候选条件分布在列表正序和反序下如何变化。本批是新评分，不重做此前贪心生成，也不重跑旧 120 状态 × 4 界面 × 2 模型实验。

## 固定对象和指标

输入限定为上一批已保存的 32 个 `prepared` 提示与相应 `raw_result` 中的输入 token 前缀；仅从该批虚构日志取出对应事件，按 01–08、子目标 1–2、C1/C2 原顺序评分。每个提示的候选为 `A000`、`A001`、`A002`、`A003`，用 tokenizer 对裸编号 `add_special_tokens=False` 所得 token 序列后接 EOS `151645`，对完整序列在该提示条件下的自回归对数概率求和。若候选为空、重复、含提前 EOS、超过 16 tokens，或本次提示 token 与上一批日志保存的输入前缀不一致，则停批。每个候选只评分一次，最多 **32 × 4 = 128 次教师强制前向**；不生成、不执行动作、不重试。

将四个候选对数得分在该集合内经 softmax 归一化，报告每格正确动作的归一化权重的均值和中位数，并对每个子目标报告同场景 C2 减 C1 的配对差的均值和中位数；只对两侧四个候选均成功且映射已知的配对计算，另列计划、有效与缺失分母。不计算此前暂停的非基准 TV 端点或半质量界。可观察真实贪心输出与这些规范 token 序列的编号是否一致，但两者的 token 分段可能不同，差异不自动意味着模型矛盾。每格 8 个情境、四格复用，结果仅描述这些已曝光题面，不做显著性检验或留出推广。

这四项权重只在选定的四个规范 token 序列及一个 EOS 内归一化，不覆盖其他合法 token 分段、其他回答或环境结局；它们**不是**成功概率、已校准置信度或所有可生成回复的概率。模型前向后的日志是可信执行条件下的自报，不能单凭日志恢复或验证未保存的全量 logits。

## 模型、资源和停止

本批使用项目配置指向的同一本地 Qwen3-8B 候选缓存、同一项目运行环境、单 GPU、BF16、禁自动下载及远程代码；不重新计算五分片摘要。模型和 tokenizer 及文件未被不可见替换是解释前提；即使 token 前缀相同，也不能单独证明模型权重身份。使用 `torch.inference_mode()` 和 `use_cache=False` 做前向，不引入新环境、训练、恢复算子修改或选择器。

每个提示输入最多 1,024 tokens，单批外层墙钟 1,800 秒、进程 CPU 1,800 秒、单输出文件 8 MiB；每个提示含四次评分，超 120 秒则停止后续提示，阻塞由外层总时限终止。加载前后与每个提示的四次评分前后查询整卡显存：身份不一致、查询失败或已用 ≥43,008 MiB 时停止；这些为离散软采样，不保证显存峰值或设备独占。若实际适用规则更严格则遵守。任何错配、异常、非有限得分或记录失败均停批并保留部分记录，未完成项为未知，不续跑或自动重试。

输出写入独立新建且 Git 忽略目录，逐候选记录提示键、映射、规范 token 序列、条件对数得分、输入长度及时间，并记录模型/库版本、设备样本、调用计数、进程 CPU/RSS 和墙钟；不记录配置路径或凭据。程序和本协议在执行前固定，来源日志摘要和新日志摘要供字节追踪，不能认证来源。受保护任务、方向 2 受限窗口包及其三份输入、真实轨迹与环境均不访问。
