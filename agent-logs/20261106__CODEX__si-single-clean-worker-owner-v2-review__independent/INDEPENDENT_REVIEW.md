## Concrete findings

1. **Completeness contract mismatch — reproducible on a fake worker/owner flow.** `return_evidence.py:30–31` returns `{'marker':'MISSING'}` without setting `Capture.incomplete`; line 112 therefore labels a snapshot `COMPLETE_SELECTED_FIELDS` even if a selected field was absent. The candidate README says missing capture is partial and stops as UNKNOWN. In the independent fake, reset returns a state without `_last_action` (all other fields correct). The raw reset record contains that missing marker but says COMPLETE, the worker completes six fake steps, and the replayed owner protocol also accepts COMPLETE. This does not establish that actual TextWorld omits the field or that an absent reset last action is scientifically harmful; it does show the advertised status and actual behavior diverge. Resolve explicitly: enforce the declared required-field/partial rule, or define any legitimately optional fields and their permitted stage-dependent absence, emit a truthful capture status, and test invalid missing fields stop. Do not equate a transparent MISSING marker with an unrecorded return; the issue is the completion classification and continuation rule.
2. **Owner RAW_RETURN versus OBS contradiction not checked — reproducible synthetic protocol counterexample.** `owner.py:187–195` accepts raw evidence based on operation, returned flag and status; `:149–159` separately validates OBS, but does not compare the two. Starting from a successful fake event sequence, changing only the first step RAW_RETURN `selected_identity` to false while leaving the subsequent OBS selected identity true still yields `Protocol.complete=True`. This deliberately inconsistent fake message does not demonstrate the reviewed worker naturally generates that sequence; however, `verify_worker_raw` at `:337–368` compares the worker's raw journal to its raw messages, not raw meaning to OBS, so matching raw artifacts do not close this gap. If owner validation is meant to assert actual snapshot/OBS consistency, compare the available, representation-normalized fields and stop UNKNOWN on contradiction; alternatively explicitly limit the owner claim to uncorroborated worker assertions and do not describe it as an independent semantic check. Handle legitimately absent/partial fields without inventing data.

## Verified v1-specific improvements

- In `worker.py:193–220`, completed reset/step is captured by a bounded selected-field snapshot, fsynced to local `worker_raw.jsonl` and emitted as `RAW_RETURN` before semantic validation in `run_contract`. In fake `wrong-facts` and selected-identity failure cases, selected return fields are retained and no COMPLETE is sent. Capture remains bounded/selected rather than a complete native object dump. Object-property access can fail or hang; partial markers, storage failures and owner/child death remain UNKNOWN.
- `owner.py:292–307` journals bounded raw frames before JSON parsing and semantic validation; `:325–334` records invalid frames and sends no ACK. Reproducing the original malformed OBS now shows journal entries `worker_frame_received`, `worker_frame_invalid`, and zero ACK writes. Partial/oversized wire frames have bounded-prefix UNKNOWN paths. If journal fsync itself fails, no claim of successful persistence is justified.
- START events still precede physical calls and owner fsync precedes ACK. Direct-child only limits and parent-death/pidfd logic are unchanged; fake tests do not validate actual OS behavior. Real entrypoints remain hard disabled. Inputs/source hashes are checked, but caller-supplied source pins, mutable dependencies and TOCTOU are not an independent secure boundary.

## Remaining release dependencies and scope

No cgroup tree limit, aggregate CPU/RSS/storage quota, verified descendant termination or hard bound on blocked fsync/setup/cleanup is established; per-process RLIMIT_AS is virtual address space, RLIMIT_FSIZE per file and RLIMIT_CPU per process. PID/parent-death races and same-user custody remain explicit limits. The old five-step cap does not permit a six-step case, and the four `pddl2sas` function calls on normal load+reset still require budget reconciliation. Actual static parser/compiler compatibility, full runtime origins, exact code engineering release, fresh resource checks and genuine parent/child cleanup remain unresolved. None is remedied by fake passing.
