This proves an internal entity-name byte difference, **not** a measured difference in final grammar-rendered prompt, commands, agent output or scientific effect. No environment was constructed or called in this check. Direct-engine behavior is an engineering adaptation and must not be presented as full production-ALFWorld equivalence.

2. **Close success is not proof native resources were released.** `RealPorts.close` calls `PddlEnv.close` (`direct_worker.py:207`); the installed PddlEnv class has no override and inherits `textworld.core.Environment.close`, whose body is `pass` (`core.py:264-266`, source SHA256 `439bda7539816637c05f5bcd181101e8d96d4a5c8a76e2d9245c004e0647d176`). The fake tests prove the coordinator attempts and journals a fake close, even after a synthetic close-start journal error; a future `close_returned` on this actual class only proves the no-op method returned. Resource release, subprocess/native cleanup and failure during construction require separate observation; hard death and journal failure leave effects unknown.

## Costs and decision boundary

The fake supervisor distinguishes construct/load/reset/close, model-bundle, nested backend/adapter subevents, generation and edge-step; nested subevents must not be added as separate model loads. It reserves at least one per fake operation even when an operation was not observed; any error sets fake effects unknown, and the receipt also leaves unobserved excess unbounded. These are synthetic conservative accounting fields, not measured physical costs. The local guard's single-generation claim is per run directory and does not constrain other model references or new directories. Missing/malformed records, native PDDL translations, token cost, GPU device-hours and external process effects need independent physical accounting.

No current real resource admission/continuous monitor, safe process lifecycle, semantic audit of prompt-to-action/step, trusted external anchors, real dispatch, proven 8B memory fit, or complete cross-run scientific budget exists in this candidate. These are practical prerequisites for a real one-step engineering probe, not requests for a new general user approval. Any later real code and inputs require their own exact-byte independent review; no model efficacy or held-out generalization can be inferred here.
