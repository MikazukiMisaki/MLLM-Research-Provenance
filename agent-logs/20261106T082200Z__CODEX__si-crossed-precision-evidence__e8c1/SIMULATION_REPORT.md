# Task × training-product precision: purely synthetic check

**Scope.** This is a CPU-only simulation of invented binary outcomes. No real tasks, protected material, task manifests, model weights, agents, or environments were read or invoked. It does not measure R19/SI product variability, estimate the available independent task population, establish power for the actual study, or select a budget.

**Model fixed before simulation.** In each replication sample independent standard-normal task effects T_i, shared by every product and both arms for task i. Independently sample K B and K C product effects U_Bk, U_Ck from N(0, σ²), independent across training products and from tasks. Conditional on these effects, make independent Bernoulli draws with logits −0.45 + 1.15 T_i + U_Bk and −0.70 + 0.85 T_i + U_Ck. A cell is the difference Y_Bik − Y_Cik. Pairing B and C product indices is arbitrary; all products are evaluated on all N task draws. The differing task slopes permit the effect itself to vary with task. For the fixed-product estimand, product values are drawn **once per scenario**, frozen across replicates, and inference targets their particular mean performance difference over the task distribution. The fixed products differ across the fixed-product scenarios, so those scenarios are not a longitudinal comparison of the same products.

For the random-product estimand, a fresh independent set of products is drawn for each replication; inference targets the expected difference over both the task and independent training-product populations. Parameters are illustrative and deliberately not calibrated on project data. A task is sampled independently in this model; task-family dependence or repeated training seeds, if present, require further clustering/design work.

**Procedures.** All intervals use a nominal 95% normal cutoff, with 3,000 replications per row and a reproducible seed. The naive standard error treats the N × K paired differences as independent. The task-cluster estimate treats task means as independent and conditions on the products. The illustrative two-way estimator uses sample variance of task means/N plus sample variance of product-pair means/K minus sample variance of all cell differences/(N K), with sample variance degrees-of-freedom corrections. It is a large-cluster normal approximation, not an established adequate small-K interval. Negative variance estimates are labeled invalid and omitted from the conditional coverage calculation; their fraction is separately reported below. Coverage Monte Carlo standard errors are sqrt(p(1−p)/valid repetitions), around 0.4–0.9 percentage points in the cases below. The approximate empirical-SD Monte Carlo errors shown in the JSON use a normal-data approximation and are not exact for this mixture.

The random-products population effect is about 0.0543 for σ = 0.7 and 0.0591 for σ = 0. The target for each fixed-product row is different and is recorded in `results.json`. With just one independently trained product per arm, the random-product variability is not empirically identifiable from those products alone; a task-only interval can support only the conditional fixed-product target under its sampling assumptions.

**Independent self-check.** `analytic_check.py` computes the exact variance for the crossed random-products design by separate 64-point Gauss–Hermite integration. The per-cell paired-difference variance and same-task/same-product-pair covariances combine as [Var(D)+(K−1)Cov_same_task+(N−1)Cov_same_product]/(N K). The simulated SD was within 1.1 approximate Monte Carlo SD errors of this independently calculated value in every random-products scenario. Quadrature in the simulation was additionally checked against two-dimensional quadrature and arm-swap symmetry. These checks support the computation under this specified model; they do not validate this model for the real experiment. Coverage itself is a simulation estimate, not verified by the variance identity.

**Implications.** Explicitly freeze whether the claim concerns particular fixed products or the broader training procedure. In the illustrative random-product model, additional tasks alone cannot compensate for four training products when product variation dominates; pretending N × K cells are independent badly understates uncertainty. Two-way normal intervals improve on naive intervals here, but under-cover at K=4 and remain below 95% at K=16; they are not a justified final inferential method by this check. At σ=0 the same two-way procedure can also under-cover and produce invalid estimates. Pre-specify and separately validate any chosen small-sample inference procedure against plausible simulation scenarios; report product identities/seeds and task clustering, and avoid treating the simulated parameter values as evidence for the actual budget.

**Reproduce.** Run `simulate.py`, then `analytic_check.py`, with a Python environment containing NumPy; no internet or GPU is needed. Results record Python and NumPy versions, all scenarios, and Monte Carlo errors.
