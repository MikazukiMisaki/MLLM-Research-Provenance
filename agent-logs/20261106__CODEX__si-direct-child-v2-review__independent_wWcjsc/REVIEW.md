Injecting fsync failure specifically for the claim directory and, separately, the ledger directory stopped before spawn, retained the consumed claim, and rejected a same-namespace retry. The candidate suite covers partial event writes, event fsync failure after spawn, direct-child failure/timeout and observed cleanup, leaf collisions and component substitution; these are injected failure observations, not evidence of physical crash durability.

**Ancestry and global-one-shot limitation, independently demonstrated:** after binding, both original directories were renamed outside the authenticated root and replaced with new directories under that root. The old binding still validated and wrote the synthetic claim and ledger to the moved original directory inodes, with no writes to the replacements. A fresh binding using the old expected identities rejected the replacements. A caller deliberately accepting the replacement directory identities could create a fresh binding and run the same ID again. This is the documented caller-authority and namespace-stability boundary, not an unexpected claim that the pinned fd redirected. It demonstrates that inode pinning is not proof the directory remains beneath the root or that independently rebound/restarted callers share an immutable global claim namespace. Caller authentication, external custody, mounts, inode reuse, namespace changes and ancestor renames remain unsolved for real execution.

The ledger remains local and may be partial or unsynced on failure. Parent death, host crash, loss of the monitor, child descendants, uninterruptible operations, GPU completion, actual model and data identity, runtime placement and budgets remain unverified. No independently owned recovery watcher or durable external ledger is implemented. Tests do not prove race freedom under hostile path or system mutation, and no actual GPU/model/ALFWorld/protected data was invoked.
