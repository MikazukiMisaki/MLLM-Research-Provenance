# 拟议题面 V1 的独立审阅与 V2 修改

2026-11-16，Astra 只读审阅了原始 `cases.v1.reviewed.json`，没有运行模型、环境或代码。其手工路径核对：紧／宽预算中，先拿 B 最少 2 步、先拿 A 最少 4 步、先 look／inventory 最少 3 步；清洗例中先拿 A 最少 3 步、拿 B 最少 5 步、信息动作最少 4 步。未知阻挡例中，先拿 A 有一条两种状态都可成功的 6 步路径；先拿 B 在阻挡状态下至少 8 步，在不阻挡时至少 2 步。这些判断以题面转移规则完整、取放不改变清洁状态为前提。

独审要求：

1. 宽预算的四种首动作均可在预算内完成，不能把未遵守进度偏好标为任务失败。将子目标服从、指定进度规则匹配、预算内可达、回退和非推进分别记录，允许标签重叠；必要清洗中的回退可能恰恰是可接受动作。
2. 未知例是“回退是否必要”无法判断，不代表无法选择在两种状态下均成功的稳健动作；未经指定风险和成本偏好不构造唯一正确首动作。已明确 look／inventory 不产生额外信息，避免未知事实是否可经观察消除的不确定性。
3. 为使紧／宽预算仅在预算上变化，两题使用同一动作编号及顺序；删除了输出示例中的固定 `A000`，避免为特定编号加提示。其他两例使用固定映射，这不是对随机排列总体的推断。
4. 新契约现明确即时子目标只是建议、与进度规则冲突时该规则优先，并说明拿取等准备行为可以沿完成路径推进；明确未改变事实保持不变，包括取放不改变清洁状态。

修改后的 `cases.draft.json` 和生成器仍为**未冻结草案**。本文件报告的是对 V1 的审阅和作者据此作的修改，不声称 Astra 已独立审阅 V2、物理调用或完整实验。V2 仍需对完整提示与标签进行运行前检查；研究只测四个人工情境，其中紧／宽是同一结构的预算配对，不能推断真实任务效果。

## V2 定点复核与 V3 修改

Astra 随后只读复核 `cases.v2.reviewed.json`，确认上述四项修订均已落实，既有路径未因修改失效。它指出新契约的“沿完成路径”仍允许宽预算中的 `look`：先观察、再拿 B 和放 B 只需 3 步且没有撤销进度，因此不能单凭 V2 提示把信息动作判作违反该契约。

据此，V3 新增一句明确规则：有可推进任务并改变物体状态的准备动作时，不选既不改变物体状态又不提供信息的动作。此调整是作者对 V2 复核意见的最小实现，不声称 V3 已再次独立审核；它也进一步改变了处理文本，效果只能解释为完整文本的作用。按照前述要求，follow 条件选择其指定动作是子目标执行，不能因与外部进度规则不一致就称为违反 follow 契约；进度规则、子目标执行和预算内可达分别计算。
