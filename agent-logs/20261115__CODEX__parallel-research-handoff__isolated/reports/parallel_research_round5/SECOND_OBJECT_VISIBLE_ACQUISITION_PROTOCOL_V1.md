# 第二件可见且未持有：两阶段恢复配对观察 V1

**首次模型生成前固定。** 本批研究：第一件已经放好、第二件同类物品可见且可拿、智能体双手为空时，两阶段恢复是否提出并选择拿取第二件，而非撤销第一件、`look` 或 `inventory`？这是人工文字情境中的行为观察，不是 ALFWorld 执行，也不直接解释既有真实轨迹。

## 材料与比较

手写八个虚构情境，每个任务要求将两个同类物品放入指定容器；状态明确第 1 件已放入、第 2 件在可见位置且未持有。固定四条人工候选：拿第 2 件、从目标容器取回第 1 件、`look`、`inventory`。四项按场景编号循环移位，避免正确编号始终相同。每条题面、动作及参考子目标见执行脚本；它们不是环境生成的合法动作或受保护任务。

每个场景调用第一阶段一次生成诊断和子目标；格式有效时，用其输出进行一次第二阶段动作选择，再用同一诊断及人工给定「拿取第 2 件」子目标作配对选择。若第一阶段无效，模型子目标条件不执行，人工条件用固定中性诊断；不把该对计入两侧有效配对。计划 8 次第一阶段和最多 16 次第二阶段，最多 **24 次生成**，固定情境 01–08、模型子目标后人工子目标，单键至多一次。

主要描述：第一阶段有效／8；两条件分别报告拿第 2 件、撤销第 1 件、`look`、`inventory`、格式无效、截断、未执行和未知的计数／8；两条件均为有效编号的配对中，报告语义动作改变数和从非拿取转为拿取、反向转变数。研究者逐条阅读虚构状态和第一阶段输出，说明子目标是否指向拿第 2 件；对诊断中的历史推断、歧义或缺失保持未知，不自动把格式有效当事实正确。空分母未定义，不作显著性检验或总体推广。

与前一批第二件已持有的虚构情境相比，本批改变了物品类型、所处位置、可选命令和动作目标，**不是**单变量干预或同状态配对，不能据两批结果归因于「持有与否」。模型子目标与人工子目标则只在同一情境、相同诊断及动作映射下配对；若两者含义相同，即使输出一致也不能证明人工修正对错误子目标无效。

## 运行、资源和停止

使用项目本地配置指向的 Qwen3-8B 候选缓存，单 GPU、BF16、本地加载且不信任远程代码、不自动下载，不重做五分片摘要。第一阶段最多 40 个新增 token，第二阶段最多 16 个；贪心生成、输入最多 1,024 tokens，沿用项目两阶段恢复指令及裸 ID 契约。第一阶段按两行、每行不超过 12 词且不含动作 ID 分类；第二阶段按裸 ID 严格映射，达到输出上限且没有 EOS 记截断。其他不明确终止或异常停批，格式无效和截断留存且按上述规则继续。

外层总墙钟 1,800 秒、进程 CPU 1,800 秒、单文件 8 MiB；单次请求超过 120 秒停止后续调用，阻塞由外层总时限终止。启动前、模型加载后及每次请求前后查询相同 GPU 的整卡显存，查询失败、身份不一致或任一样本达到 43,008 MiB 即停；离散采样为软保护，不能证明显存峰值或独占。适用设备规则若更严格须遵守。一次性输出目录不可覆盖，异常、超限或中断保留部分日志，不自动重试或续跑。

日志按事件记录材料、提示、映射、原始 token、解析、时间及设备样本，另记调用次数、输入／输出 token、CPU/RSS；本机日志和此前权重摘要仅在可信配置、主机及无不可见替换假设下支持解释。用户成本、系统 I/O 与未观测峰值不记为零。不得读取或分配受保护任务，不读取方向 2 受限窗口包及三份输入，不重启旧 120 状态协议，不修改冻结基线、联合算子或权重。
