## Installed-source path

1. `fast_downward/translate/pddl_parser/parsing_functions.py:62–78,100–115,191–206` represents `not` as negated literals and `when` as `ConditionalEffect`. `pddl/actions.py:103–118` separates conditional add and delete effects. `translate/translate.py:207–274` translates their conditions, combines add/delete effects per finite-domain variable and constructs SAS operator entries. This establishes the implementation path and intended handling in source; it does not show which exact SAS effects were produced for D.
2. `fast_downward/interface.py:160–216` shows `pddl2sas` parses, normalizes, translates and returns `(task, sas)` in memory. `textworld/envs/pddl/logic/__init__.py:169–185` calls it for ordinary SAS and a separate replan version and loads both into the native library. Captured D records do not preserve the generated SAS or exact native operator data.
3. `textworld/envs/pddl/logic/__init__.py:120–139` maps a native atom named `NegatedAtom ison(...)` to a TextWorld proposition named `not_ison(...)`. `textworld/logic/__init__.py:704–712` defines `not_` names as negation and switches the prefix when negating a proposition. The `not_ison` spelling therefore has a documented representation route; the raw TextWorld fact alone cannot distinguish a `NegatedAtom ison` input from every other possible native atom string that yields the same name.
4. On initialization, `PddlState` loads task initial positive facts, reads native state, maps atoms to facts and filters negative facts (`logic/__init__.py:189–215`). On a step, `PddlState.apply` allocates `op.nb_effect_atoms` slots, calls the native `apply_operator`, maps each returned slot, removes its complement and adds the mapped fact (`:245–260`). Thus an explicit `not_ison` can appear in the Python mirror after a step despite absence of that explicit proposition at reset. The Python loop has no visible conditional guard; the unknown native output, not the PDDL text alone, determines which atoms it receives.
5. `textworld/envs/pddl/pddl.py:135–165` invokes that apply path before generating feedback; `_gather_infos :72–85` puts `list(self._pddl_state.facts)` in `_facts`, while `won` comes from native `check_goal`. Therefore retained `_facts` is the Python fact mirror. This does not by itself reveal the native state or show whether it agrees with that mirror. The installed `fast_downward` tree inspected here exposes `libdownward.so` and Python interface but no native implementation source for `apply_operator`.

**Not established:** whether the relevant SAS guard/value encoded D as expected, the exact native pre/post state, the operator's effect-slot contents and order, whether slots represent fired versus merely possible effects, whether native state and Python mirror differed, or the cause of their observed output. Several explanations remain possible, including representation/update differences; the records do not select one. Neither feedback nor `not_ison` alone settles native state. The raw snapshot is not a full native action trace.

First, implement a pure-fake demonstration of the documented Python mapping/update loop with explicit invented native atom strings and effect slots, testing negation conversion and complement replacement. This has no parser/environment or real D data and proves only the wrapper's response to those invented values.

If runtime localization remains needed, use a **new self-authored minimal development-only microdomain**, distinct from D, with one synthetic object, one source location, a ToggleObject-like pair of conditional effects, and no model. Set isOn initially absent and perform exactly one fixed toggle. Before launching, freeze exact sources and a bounded supervisor; record precisely one construct/load/reset, at most one step and one close, no retries, and stop on any missing/invalid evidence. Source predicts up to four `pddl2sas` function invocations across successful load/reset; imports, parser/translation/native and any descendant work are additional observed costs or UNKNOWN. Establish explicit per-process CPU/RAM/file and wall limits; these are not aggregate process-tree guarantees.

In the same single microstep, capture, in sequence and without applying the action twice: the exact ordinary SAS text returned at load/reset, finite-domain atom/value mapping and selected grounded operator/effect guards; native `get_state` atom strings before and after; `op.nb_effect_atoms` and every native `apply_operator` output slot in returned order; Python mirror facts before/after; exact selected action, feedback, status, and raw persisted receipts. Instrument the boundary without changing action selection or effect semantics, and separately count each added native observation call; whether native observation is side-effect-free must itself be validated from available code or remain UNKNOWN. Missing/ambiguous slots, inability to bind outputs to the same action/state, an instrumentation failure, resource failure or incomplete cleanup yields UNKNOWN and stops.

Acceptance is an evidence table, not a forced success: (a) source PDDL versus generated SAS guard/value; (b) native pre/post values; (c) returned effect slots and order; (d) final Python mirror. If native state is on but returned slots/update produce an off mirror, evidence narrows the discrepancy to export/update; if SAS encodes the expected condition but native state is off, it narrows the discrepancy toward native execution; if SAS differs from source expectations, translation is implicated. These are conditional inferences only, not proofs without complete captures. A different outcome in the microdomain does not explain D by itself; the original D remains non-retried and UNKNOWN.
