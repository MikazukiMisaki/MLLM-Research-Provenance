# Reproducibility and provenance appendix: SI-U1

*Working appendix for independent review. The study's detailed task records, prompts and trajectories are controlled-access. This appendix presents provenance and limitations, not a claim of a completed replication or an instruction to execute another study.*

## A. Scope and reproducibility claims

Three distinct activities should not be conflated. First, the recorded SI-U1 outcomes and fixed statistical analysis have been independently checked arithmetically; this reproduces calculations conditional on the recorded inputs. Second, forensic verification checks hashes, run receipts, data bindings and retained output bytes. Third, an end-to-end independent repetition would require the complete accessible data, models, software/hardware environment and a separately reviewed execution; such a repetition has not been performed. Matching current files to recorded hashes is necessary for the latter but is not proof of a historical process's complete state or of future numerical reproducibility.

## B. Historical P0 and continuation training

P0 is the retained expert-supervised Qwen3-8B adapter. The balanced expert source records describe 1,200 task identities, with 1,074 assigned to training and 126 to offline validation, and 20,967 action-decision rows overall. Saved P0 training output reports two epochs, 2,354 optimizer steps and the final selected checkpoint based on offline validation loss. Dataset source attribution to hand-coded expert trajectories is supported by recorded source-file bindings and the contemporaneous report, not by an independently reconstructed generator execution for each task. The saved trainer logs do not provide task-by-task optimizer-exposure receipts. The historical initial base-model and tokenizer revisions and complete P0 launcher/runtime receipt remain unestablished. A historical Git report binds the saved final adapter directory hash; an independent recent audit confirmed the current directory matches it and that its seven saved tokenizer files match those currently in the selected checkpoint. Three of those files match a currently cached Qwen3-8B snapshot, while the saved tokenizer configuration differs and three have no separate same-named snapshot file. These comparisons support limited saved-file continuity; they do not establish the historical base weights, the full tokenizer revision actually loaded, or functional incompatibility. A canonical-JSON protocol/hash correction resolves an earlier apparent file-hash mismatch but does not prove which input bytes the old process actually loaded.

The two SI-U1 continuations started separately from the same existing P0 adapter. The executed training code was bound to commit `9bbaa12c2d8177a60ec5a74ed2f970ef29a57bce`; the frozen continuation protocol has raw SHA-256 `f72e1de1b27659f0c0cb187c276c7c60483af089d4a756fbe3c3d7819dcc5698`. The B expert and C self-success datasets each have 78 distinct parent directories, four selected input/action examples per parent, and matched family parent counts. Data identities and state distributions differ; B reuses expert training rows, while C uses selected source-actor actions from previously recorded successful episodes. Parent counts and supervised tokens do not isolate the causal effect of data origin or ensure equal input computation.

Each actual B/C run recorded 1,248 microbatches, 78 optimizer steps and 6,240 supervised tokens with a single seed. Independent post-run reviews checked recorded sample order, step-wise learning rates, output adapter structure and supervisor completion; they did not independently reproduce GPU arithmetic or establish absence of unrecorded external work. A source-data audit reconstructed selected input/completion rows and token counts, but did not independently regenerate every candidate-ranking decision. Final adapter tree hashes in the evaluation binding are A `6b13612c33d96ae9bbda041c08d33e0e1888406c4782670e90c8ebd27467b5a5`, B `9d8ce785c635db80ddd17999a981f0cee478ccf92d0aeb12eb7812978e441a36`, and C `40202cade31425b823ae4b153f2c975487d64b48461b47b922aebda226dd4c57`. These are tree-digest identities under the recorded serialization, not proof of successful training on every individual parent.

## C. Evaluation environment and recorded execution

The accepted evaluation used evaluator commit `8532275932dabddc498c23a2b6d9a045647542f0`, a fixed schedule of 82 distinct parent-task identities from ALFWorld TRAIN, one P0 and one final checkpoint for each continuation, and corresponding reset seeds across the three conditions. The supervisor recorded a completed evaluation, exit code 0, 246 completed episodes and no unresolved episode record. Its event ledger SHA-256 is `6146bb79faeb572c3674ff9ba907fac4be25eff4c2bd161a3d7cf3156d81c96e`. Read-only inspection of its recorded generation entries found 5,001 completed calls, each with `do_sample=false`, thinking disabled and a 16-token maximum; this is a check of event metadata, not an independent model rerun.

The runtime specification records TextWorld 1.7.0, PyYAML 6.0.2, PyTorch 2.6.0+cu124, transformers 4.56.2 and PEFT 0.17.1; ALFWorld and certain imported modules have blank version strings but bound files. Six before/after recorded import receipts agree on Python 3.10.20 and the recorded versions of the relevant Python packages. Entry-file and receipt matches do not constitute a full lockfile, dependency-tree, system-library, driver or hardware reconstruction. The evaluation was performed on a shared GPU; a device allocation interval does not prove exclusive ownership. Source commits and selected code-file fingerprints identify the reviewed implementations, but full dependency closure and historically loaded base/tokenizer revision are not established merely by naming a model.

A prior independent local byte inventory found all 12 base-snapshot files and complete base tree matched recorded hashes; all 12 base entries were symlinks to accessible targets at that audit. The same review found the three adapter trees, 82 game files and 82 trajectory files matched their bindings, as did six specified isolation inputs, six B/C training evidence files and eight specified package entry files. In a new local standard-library check for this appendix, all 164 game/trajectory bytes, all 12 isolation/training-evidence bindings and all eight package entry files matched again. The full base and adapter trees were **not** independently rehashed in this new check; their stated status comes from the earlier independent inventory. Neither inventory proves that an unseen task, scene, semantic equivalent or earlier exposure was absent. Following or transporting symlinks requires retaining their resolved targets.

## D. Outcome extraction and analysis history

The original frozen analysis specified C−A and C−B paired differences, two-sided exact McNemar tests with Holm correction across the two contrasts, and conservative simultaneous intervals. The first approved offline extractor invocation failed after evaluation while validating tokenizer snapshot symlinks: its genuine recorded return code was 1 and it produced no final analysis. It had already streamed result bytes for hashes, so the failure must not be described as no prior result-file access. An earlier operational audit had examined journal structure and terminal/reward consistency, without aggregating treatment effects. The retained records cannot establish that every other person or process was blind to outcomes.

A separately reviewed post-evaluation technical supplement changed only the tokenizer file-binding interface to accept and verify the expected snapshot symlink targets using the production binding contract. The approved corrected extractor at commit `062a757646c5403f71377ee74ae12291bbcf3e0e` completed offline with recorded return code 0; the frozen analysis plan, outcome inputs, contrasts and thresholds were preserved. Its formal analysis SHA-256 is `4a3ea016d4c06022980482ac9dbc58155a68bbe20fbc723a68ce49c7c345ea9b`. A separate statistical recomputation agrees with the recorded results within its stated tolerance; it is arithmetic verification from the extracted data, not a new evaluation or independent authentication of the original supervisor.

## E. Archive custody and access

The private local SI-U1 evaluation evidence archive is stored as 12 ordered fragments. A fresh local check for this appendix rehashed all fragments, concatenated them in memory to the recorded 46,536,262-byte gzip SHA-256 `71eb69cf4422bdbefd19485cc4fc5b7d4618ce974013a5882f1334784e8779d3`, and streamed the 32 regular members against the saved member-size/SHA inventory. It did not emit or extract task text. This confirms equality to that saved inventory locally; it is not a public release or a forensic guarantee that every historical activity is present. The archive excludes model weights, adapters and input dataset files; the previously verified matching local inputs are a separate availability claim.

An earlier remote observation at a named private provenance commit matched Git blob identifiers for the 12 archive fragments. For 11 large fragments the connector returned no file body, so an independent remote full-content download and SHA-256 check remains unavailable; the remaining small fragment's body was not compared in that particular check. Historical publisher receipts remain supporting evidence, but should not be described as a fresh full remote restore. Separately, the source96 original journal has a local compressed archive whose streamed member SHA-256 matches the original journal; a recent remote check of that archive returned a matching Git blob identifier but no full body. These source96 and evaluation archives are distinct and should not be merged or treated as proof of independent physical backups.

## F. Limitations for interpretation and sharing

The 82-task fixed TRAIN schedule is not certified held out or scene-independent. Historical exposure and semantic duplication are incompletely known; one B and one C training seed cannot establish across-seed stability. The original analysis inputs include sensitive task identities and model interactions. Model, data and archive access/redistribution terms, permissions and institutional policies require review before external distribution. Exact hashes help identify particular retained records; they do not prove lawful redistribution, complete historical isolation, a fully pinned environment, or an end-to-end replication.
