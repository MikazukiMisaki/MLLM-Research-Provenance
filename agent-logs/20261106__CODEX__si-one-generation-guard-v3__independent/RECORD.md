# One-generation guard v3: synthetic candidate

Status `SYNTHETIC_ONLY_REVIEW_PENDING`. This is not a model runner, a scientific experiment, a sandbox, or a release. It does not modify the frozen policy or any scientific worktree. No real tokenizer, model, PEFT adapter, GPU or environment was loaded or invoked by these tests.

The prior v2 accepted and appended to a pre-existing ledger in a synthetic counterexample. V3 exclusively creates a persistent claim and then an exclusively created ledger before validating or calling the model edge; an existing claim or ledger stops the fake call. It restricts accepted generation kwargs, verifies batch/input/output limits and selected decoding fields before the fake model call, and fsyncs append-only event records. Input/config rejection consumes the local attempt. A completed fake output is checked after the call; an oversized or malformed return cannot be prevented retroactively.

Thirteen tests passed in an actual isolated subprocess, return code zero. They cover pre-existing ledger rejection, one-call behavior across new guard objects, concurrent threads, invalid arguments, input/output limits, beam setting, ledger and fake model failures, the real P0 policy with synthetic tokenizer/model/runtime, and synthetic start/return recording failures. A separate test launches two own fake worker processes: after the first enters the fake model edge, the second is refused, then the first is killed; the claim and started-only ledger remain, correctly representing an uncertain consumed attempt. This is one selected crash window, not a comprehensive proof of crash safety or durability under every filesystem failure.

Limitations: the persistent marker prevents another guard from using the **same** directory; a different directory or direct reference to the underlying model can bypass it. The trusted supervisor must bind one global run identity, control the call path and prohibit reruns. There is no security isolation or guarantee against hostile mutation of directories/files. Fsync failure or abrupt death can leave a consumed claim with an empty/torn ledger or a started event without a terminal event; such states must be preserved and charged conservatively as unknown, never interpreted as free work. Real PEFT compatibility, actual effective model generation config, token and model memory behavior, true GPU/device cost, model loading and full process cleanup remain unverified. Independent exact-byte review and a concrete separately reviewed supervised execution design are required before any real call.
