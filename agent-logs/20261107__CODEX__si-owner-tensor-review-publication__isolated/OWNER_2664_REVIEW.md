The correct current behavior is fail-closed. A future complete owner must independently bind the final event bytes, validate outcome and actual direct exit, and establish whatever cleanup proof the protocol requires; simply trusting a child-written label does not suffice.
2. **A measured output overrun is not retained in the owner accounting.** In the real `GenerationGate` shape-check path (`production_episode.py:61–63`), a fake generator returned shape `(1,23)` after 3 input tokens: the observed output is 20 tokens, exceeding the reserved maximum 16. Our independent synthetic test reproduces that owner ledger state. The stop and reserved debit are conservative relative to a missing return, but they understate the measured 20-token event; future code must retain observed overrun as well as UNKNOWN physical tail and stop, rather than report 16 as actual consumption. No real overrun was observed here.
