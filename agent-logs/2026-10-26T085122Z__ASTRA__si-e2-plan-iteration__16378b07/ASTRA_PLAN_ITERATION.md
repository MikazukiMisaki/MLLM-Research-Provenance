# Astra：SI-E2 执行能力与 SI-P3 采集前方案复审

结论：**当前采集投入以 NO_GO 为优先，运行能力仍 BLOCKED。原 v1 不建议直接采集；独立 v2（固定 d=5、source-first 不可构造检查）只保留为待审设计，不是工程一过就默认启动的候选队列。** 早期位置不解决原actor失败数量可能不足C24的问题。任何新96 source本身也须有独立的投入理由；训练和600-task评价继续NO_GO。这些是采集前设计建议，尚未采纳或实现，不是运行授权。

## 2. 执行阻塞：Astra 没有证实更好的宿主入口

OBSERVED：应用项目/任务元数据将 Research Astra 和当前线程连接到 `remote-ssh-discovered:sdxsrv03`。本工具执行器自报 hostname=`acc28b43e0d2`、UID/EUID=2000、PID namespace=`pid:[4026534077]`。这些记录保存在本目录 executor 元数据文件。

NOT PROVEN：应用的远程连接标签不证明当前 shell 位于 NVML 报告的宿主 PID 命名空间；单个 NSpid 字段也不证明这一点。现有执行工具没有已展示的 host/namespace 选择参数。旧记录中的 local PID 837631 与 NVML PID 3082604 仍无可信映射。本轮没有再次 SSH 或查询设备；早先一次 SSH 认证失败不能被重新解释为已取得宿主入口。

缺少的具体能力是以下二者之一：

1. 首选：已经认证、可直接在 NVML 所在 PID 命名空间执行的宿主入口，且保留相同版本、模型与环境绑定。
2. 替代：来自可信宿主视图的 `/proc/<hostpid>/status` NSpid/UID、进程 start-time、boot/namespace 身份，能与同次容器进程、设备 UUID 和时间窗口独立核对。还要处理 PID 重用、进程退出和映射缺失；缺任一项即停止。

同设备 UUID、单进程、相近时间或相近显存不能代替 PID/UID 身份。不能为了继续而放宽现有所有权/外来进程检查。配置可信入口需要真实能力变化，反复批准相同失败命令没有帮助；本讨论不要求传送密钥、不修改认证、权限或命名空间配置。

顺序建议：可信入口/映射就绪 → 新绑定、单独审查的零模型身份探针 → 新的有界8B/P0工程测量与旧已用6步轨迹 replay → 实际采集驱动接入 journal/auditor 的独立验收 → 才考虑唯一一个新96采集版本。原两次探针授权已消耗，原失败和非零CUDA成本保留。不能拿96新任务作工程 smoke test。

可并行准备的是实际采集驱动的接口设计；实现若另行开展，应以假模型/假环境边界证明生产编排、预算、完整原件、异常落盘和独立审计闭合，随后再审实际入口。现有 synthetic PASS 不能直接解除软件门禁。当前讨论没有启动实现任务。

## 3. 为什么重新审查 v1，而不是降低门槛

Sol 本轮的旧 source 结构审计给出：127条已消耗 source，其中非 light 为四家族各30条、合计120；没有 pick-two。按“完成 d 步之后、下一动作前仍非终止且 map 非空”计，d=5/10/15/20 的历史可达数为111/75/41/22。方法正确区分 `L>d` 与 `L=d` 已终止的边界。Astra 阅读了统计、方法和独立结构复算，未自行重新计数全部原始轨迹。

四位置等权的249/480=51.875%只是同一旧队列的 source×cutoff 描述性平均，不能把480看成独立样本，不能外推新96的Q、成功率、失败概率或硬上界。旧家族混合与新五家族不同，pick-two 尤其无历史观测。可达只是Q的必要条件，之后还有 replay、合法teacher动作、终局和2048完整序列等条件。

因此我不同意“工程通过后，原96方案就值得直接运行”的推论。Q≥72/96要求75%完整有效配对；现有历史描述已经提示晚位置不可达可能先于学习问题主导 NO_GO。若目的只在检验原样 v1 能否凑齐配方，继续它在逻辑上可以成立，但当前不优先推荐这笔投入。也不支持为了通过而降低Q/C/neutral门槛、扩大N或追加384。

末轮又收到并读取了协调方按生产source终局语义（末步done为真且reward>0）核对的 `independent_source_outcome_upper_bounds.json`：全部127条为120成功/7失败；非light120条为114成功/6失败。四族中pick-place为0/30失败，clean/cool/heat各2/30失败；这6条在d=5均可达。pick-two仍无旧观测。此为已消耗旧source的描述，不使用teacher结果，也不是新96的失败率预测。

**不依赖概率模型的必要条件是：C24至少要求新96中24条原source失败且位置可达，即原source失败占比至少25%；五家族失败数至少9/6/4/2/3，之后还须teacher成功和完整Q。** 固定d可以改变哪些失败位置可用，不能创造更多原source失败。旧6/120不能直接外推，却明确说明只修anchor没有论证C24可行；最缺证据的是成功纠错供给，而非代码能否运行。因此当前不推荐自动投入96甚至“先跑source看看”。先利用已登记分区/家族元数据、明确情景及真实资源上界给出新的投入理由；不能为获得该理由偷看新结果、换任务、下调C或追加采集。若缺乏值得该成本的理由，就保持NO_GO，并保留研究问题，不把尚未测成写成学习无效。

## 4. 唯一待审 v2：固定早期位置与事前不可构造检查

**候选而非已采纳协议。** 将所有96任务的唯一位置固定为 d=5；保持原96身份、五家族数量、H50、单K1、teacher后同环境原地交回、模型/提示/解码、全部质量和训练配方门槛。早于或恰在5步终止者保留 NO_ELIGIBLE_STATE，不找替代 prefix、不补任务。v1不覆盖，也不作为v2失败后的备用跑法；任何新 source 前只能独立审核并选定一个版本。

理由是减少固定晚位置带来的结构性不可达，而不是按 teacher 收益选位置。旧111/120不构成新队列产率预测。较早位置可能主要增加 neutral，未必增加C；它可能发生在未来错误之前，不能称错误触发恢复。研究对象必须收窄为**固定早期单次干预的成功动作向普通P0输入蒸馏**，不声称跨恢复阶段覆盖。

纸上完整上界如下；详见 `paper-budget-comparison.json`：

| 完整96上界 | v1：均衡5/10/15/20 | v2候选：全5 |
|---|---:|---:|
| source generations |4,800|4,800|
| teacher generations |192|192|
| suffix generations |3,504|4,224|
| generations合计 |8,496|9,216|
| replay动作 |1,200|480|
| 含reset环境操作合计 |9,792|9,792|
| 输出token |138,240|149,760|

v2少720 replay动作、多720 suffix模型调用；不能说它全面降成本。建议仍保留累计16M输入token、4 device-hours及每次8192输入的原投资硬帽，不自动扩大。更长suffix让可完成性更需真实工程依据；这些数字是上界，不是实测成本或预期收益。

同意 Sol 提议的 source-first 不可构造检查，但它是 v2 的明确顺序修订，不是对 v1 的默许例外：

1. 先运行并完整封存全部96条预定source。冻结每task seed/counter、调用顺序、版本及原始证据；尚有技术missing、身份/完整性问题或预算未完成时，分别记对应STOP，不能作结构性NO_GO。
2. 在任何teacher调用前，令E为有可达固定状态的任务集合，F为其中Y0=0者，S为其中Y0=1者。E必须是完整Q的保守上界，不能被写成已通过完整Q。未来collector应保存完成第d动作后的pre-action snapshot、terminal/truncated、完整map和停止原因。不能直接移植旧轨迹的 `L>d` 计数器：旧127只有末步done，但未来可能d+1解析停止且环境仍非terminal，已存在有效anchor却没有step[d]记录。此时单凭L=d排除会造成错误的不可构造结论。证据unknown不能按0处理，必须完整性STOP。
3. 若 `|E|<72` 或任一家族E少于Q配额22/17/10/6/7，完整Q不可能；若 `|F|<24` 或任一家族F少于9/6/4/2/3，C不可能；若 `|S|<24` 或任一家族S少于同配额，neutral不可能。任一必要条件已不可能，才停止。不得用预测teacher成功率或训练收益增加停/走条件。
4. 单列 `COMPLETE_SOURCE96_STRUCTURAL_NO_GO`，全部未测YT=NA，并标记 `TEACHER_NOT_RUN_SOURCE_FUTILITY`。保存完整96 source分母及真实费用，不能称完成96 paired采集、不能把未调用teacher填成失败。
5. 上界通过只允许进入原定后续检查；应对所有预定可达task做一次teacher，不能只采失败任务。随后按既定共同Q、C/B池和固定抽样执行；禁止改位置、补样或重抽。单K1之后同环境handoff仍不变。

这项修订可在数学上已不可能凑齐配方时省下teacher/suffix调用，但不保证省下source成本，也不保证所有NO_GO均被提前识别。必须修改并审核驱动/事件合同/审计状态、source-first reset/replay绑定和独立随机计数隔离。不能用现有逐slot实现或旧验收结果直接声称兼容。

## 5. 最少的语义补充：保留剂量，收窄归因

1. **估计目标与标签合同。** 现代码的teacher Stage2使用Stage1诊断/子目标，而训练输入由 `projection()` 重建普通P0公共提示；监督仅为合法动作ID+EOS。它是teacher→P0动作蒸馏，不监督诊断。必须证明同一动作前公共状态、完整map、ID→command和部署输入可重建，不把结局/隐藏状态放入学生输入；成功后缀不认证动作普遍最优。相同公共输入的不同动作标签应如实报告，不能事后按结果消除。
2. **B包含C且是C分布匹配对照。** B从整个成功池抽，包括C；保留一次family×实际监督长度匹配抽样、至少8neutral和禁止重抽。C−B只估计共同S120与蒸馏配方下failure筛选的差异。B的匹配分布来自所选C，不能称完全独立于C的一般success-only训练。报告B∩C、neutral数量、不同公共投影及实际监督token；重叠小/大都不触发重新采样。
3. **C−A是整个追加训练包的效果。** 它同时包含S120复训、teacher标签迁移与24新例，不能把全部提升独归于纠错经验。若要识别新例相对S-only的独立贡献需第四臂；本轮建议收窄主张，不自动加第四臂。C−B也仅适用于共同S背景、该小剂量与单seed。
4. **24新例×2曝光与18updates尚未验证有效。** 保留S120、配对slot顺序、fresh optimizer、原P0续训、唯一final-update18检查点；不按loss改epoch/seed/checkpoint，不以mask或loss下降充当任务成功率提升。即使B含8neutral，最重叠情形两臂仍可能共享136/144个例子；有集合差异不等于足够学习对比。
5. **构造可行与效能投入分开。** 完整数据后Q72/C24/neutral24及家族、投影、token/曝光等条件全过，也只记RECIPE_CONSTRUCTIBLE。600-task三臂评价上界90,000 generations/91,800含reset操作远超这点监督量，必须另作投入决定。保留双主比较、净提升/伤害标准、单训练seed和TRAIN任务隔离但scene重用的限制，不把R19 oracle当功效假设。

## 6. 同意、异议、停止和下一步

同意：保持小agent成功率自我改进主线；可信身份先于8B运行；实际采集驱动先闭合；B包含C；固定N与一次抽样；C/neutral各24和现有剂量仍作为资源门槛；独立决定训练/评价投资。

明确异议：不支持在新增可达性证据之后直接继续原v1采集；不支持把软件PASS、早期可达、配方能构造或训练loss下降视为学习效果；不支持用降低门槛或扩大数据量来掩盖结构问题。

| 条件 | 处置与允许的结论 |
|---|---|
| 无可信宿主入口/映射，或驱动/账本/审计未闭合 | 不启动96；这是能力/工程阻塞 |
| 科学采集前尚未选定并冻结唯一版本和真实预算 | 设计未可执行；不运行v1/v2试赛 |
| 身份、泄漏、命令、replay或receipt违规 | INTEGRITY_STOP，保留原件，不补任务 |
| 触及硬帽但阶段未完整 | BUDGET_STOP/INCOMPLETE，不填失败、不追加额度 |
| v2完整96source后必要数量已不可能 | COMPLETE_SOURCE96_STRUCTURAL_NO_GO；YT未测 |
| 完整采集后任一固定质量/配额/匹配条件未过 | COMPLETE96_RECIPE_NO_GO；不加384、不重抽 |
| 配方可构造但完整学习/评价投入不值得 | 停留在可行性结论，不因前期投入继续 |
| 将来正式评价未同时达到C>A、C>B与预定收益/伤害条件 | 不支持此小剂量配方的预定效能主张；不继续调至positive |

下一步限于协调方整合设计、明确可信执行能力的取得方式，并重新论证是否值得获取新96的source结构。source-only本身最多需4,800次source generation，不是免费预检，不能由完整采集预算自动放行。若未来有充分投入理由，再选定唯一待审版本；实现、身份探针、实际工程与科学采集各自仍需具体范围。本文件不放行任何运行。
