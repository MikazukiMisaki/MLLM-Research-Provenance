## 1. 问题和范围

在相同已记录前缀与剩余步数下，固定的单次两阶段诊断/动作是否相对于普通续跑、以及调用次数和输出上限匹配的诊断信息消融对照，产生可观察的不同结局？另行记录动作一致性、有效动作、代价及人工可复核的原因。此处不引入 selector、按观察到的前缀自动挑选干预、额外反思轮次、DPO、其他环境或 joint operator 修订。继续使用冻结 H4/P0 与同一 Qwen3-8B；须先绑定其真实代码、权重、适配器、解码和 PDDL 环境版本。不改源实验结果。

这是一项**四组最多、非推断性**开发试验，主目标是验证三臂生产路径和观察潜在差异，任何零差异或正差异都不能证明一般有效或无效。C1/C4 SFT、训练种子和其 20 单位方案完全不在本次三臂中；今后若研究它们，应单独设计其目标、隔离、预算与审查。

## 2. 固定任务分配和分支时点

1. 在看任何试验结果之前，独立审查允许来源、自造生成器的固定版本、具体谱系/近重复及目标语义，确认至少四个不同**具体谱系组**并固定顺序/标识与对应物件的不可变承诺。公共 domain 或抽象 family 本身不自动等同具体谱系，也不证明不同实例独立。派生关系、分组及去重规则预先固定；不因实验结果重分组。若无法证明允许来源或四个合格组，不运行。本研究不宣称任务对未知历史任务、预训练语料或正式评估集独立；不能建立独立保管时不得称为 held-out。
2. 分配前四个预先固定开发组各一次来源 episode，统一在**首个环境 action 完成后的下一次预动作时刻**分支：`r=1`。不依据模型置信度、动作结果或后续成功挑选时刻，不挑成功轨迹。前缀第一步若终止、不能安全到达下一决策或在冻结接口下无合法动作，该单元按预先定义记录为 `INELIGIBLE_AT_FIXED_PREFIX`；不换一个任务、随机种子或时刻。若发生技术故障或重放/状态证据不足，则 UNKNOWN 并按第 5 节停止，而不是视为该任务自然不可干预。
3. 来源 episode 执行并保留自然续跑作为 CONTINUE。仅在已经冻结的四个来源上建立其对应的其他两臂；来源按冻结组序执行；每个合格组的 RECOVERY 与 MATCHED-EXTRA 顺序预先交替：第 1、3 组 R→M，第 2、4 组 M→R。来源 CONTINUE 始终先执行，不能消除时间/运行顺序效应，结果须据实限定。任务/运行身份和固定环境初始化参数须在执行前绑定。采集/评判分离，禁止基于已观察到的 CONTINUE 结果挑选是否分支。即便 CONTINUE 最终成功或失败，也要按此规则执行合格单元两臂；遇技术 STOP 则留存部分研究，不补案。
4. 每条分支各自 reset 并实际重放同一前缀的 1 次 action；若原前缀的确定性、环境版本、动作映射、状态信息或模型输入无法按可观测字段核实，即 UNKNOWN，停止。不同实例/episode/实验随机性的范围和来源要预先绑定并可复查；重放一致是证据条件而非假定。任何观测不到的内部状态明确为 UNKNOWN，不伪称完整快照相等。

## 3. 三臂、契约和共同期限

* **CONTINUE：** 复用绑定的来源 episode 第 1 步之后，冻结 P0 正常生成下一个动作并继续。已完成的来源操作只计一次，不为本臂额外运行；须能从原始 ledger 审计动作与环境状态。若实现无法可信复用，本草案不得悄悄另跑，须先修订成本/调度并重审。
* **RECOVERY：** 重放至相同决策点，依次一次冻结 diagnosis/subgoal 生成（历史接口最多 40 输出 token），一次使用其诊断和相同动作映射的固定 action-ID 生成（历史接口最多 16），有效时落地一个合法动作后正常续跑。诊断和动作的实际接口、prompt、解析、格式错误以及失败语义以 exact-SHA 生产审查与冻结实现为准；不在现场补问、修正 prompt 或多次生成。
* **MATCHED-EXTRA（候选诊断信息消融，未实现）：** 使用与 RECOVERY 完全相同的未适配 recovery 后端、stage-1 请求、贪心解码和 40 token 上限实际生成并记账；控制组不将其输出文本、诊断或子目标传入 stage 2、动作历史或环境。stage 1 合法时，用事先固定的无信息占位诊断和子目标，经同一 v2 stage-2 构造器调用同一 recovery 后端，stage-2 输出上限 16，使用相同解析器/唯一映射；之后同一 SFT-P0 续跑。占位文本可能改变行为和 prompt 长度，此比较针对生成诊断/子目标输入与占位文本的联合差异，不是 P0-only 对照，也不保证 FLOPs、tokens 或时间相等。stage 1 无效时，两臂仍各启动 stage 2 并使用一致的冻结无效标记，两个请求均记账；不能省略第 2 次调用。两个 stage/grounding 任一无效时，本草案候选 OSR 手回 P0 规则：不执行干预动作，从相同状态按 P0 续跑；处理规则仍须独立审查并在试验前选定，不能事后选择旧 R4 的异常停止规则。技术异常、操作状态未知和接口不一致始终 STOP/UNKNOWN。

上述对照 prompt、调用接口、stage-1 输出屏蔽方式、RNG/缓存、基线与 recovery 生成、解析器、状态前缀与 action-ID 映射尚未通过独立生产接口审查；都必须明确 source SHA、输入字节/哈希和控制流后才能定稿。不能据此宣称已有产品实现支持该对照。

每条重放分支从初始状态起累计 `r + a + c <= 50`，其中 `r=1`，`a∈{0,1}` 为实际执行的干预动作数，`0<=c<=49-a`；动作有效时即 `r+1+c<=50`、`c<=48`，无效而手回时不执行干预动作、`c<=49`；终止条件更早时及时停止。CONTINUE 的整个来源 episode 亦最多 50 步。三臂动作索引对应同一决策时刻，评估中不追加 recovery；重放不能扩充环境 horizon。运行身份分离并记录 r、c、每个动作前后的原始响应、动作 ID/map、prompt、解析结果、token、实际发生状态和停止原因。

## 4. 结果与判定

每个到达固定前缀且三臂均有可判定结局的开发组，逐一报告 CONTINUE、RECOVERY、MATCHED-EXTRA 的成功/失败、终止原因、行动/调用与 tokens；展示 recovery−continue 和 recovery−matched 两个任务级配对差、胜/负/同值及观察到的 invalid action。对 `INELIGIBLE_AT_FIXED_PREFIX`、技术 UNKNOWN 和缺失臂另列全分母与原始原因，不把它们编作 0、不以完成子集无偏地代表全部对象。

本试验通过**执行可行性门槛**仅意味着预先指定的完整三臂记录、状态对齐和账本核对能够完成；具体必须达到几个完整单元由冻结版预先定明，不得事后据结果调整。建议要求全部四个预定开发组均符合身份/前缀/三臂证据，若自然提前终止导致不足，则记为非技术性可行性不足而非补案。即使达到上述门槛，也不是 Phase 2 有效性或因果作用已通过；四组不足以确定收益是否可复现或估计总体成功率。任何下一阶段判定先单独冻结有意义效应、额外样本、抽样、训练及预算。

## 5. 失败、未知和停止

记录每个实际开始的外部操作与返回：模型/环境构造、生成、reset、step、翻译/编译和清理、退出码和可用的资源证据。成功、环境自然失败/50 步未成功、invalid action、提前终止按冻结评估器的真实语义分别记录；不能把解析失败或技术异常任意折算成任务失败。任务中断、调用部分返回、不可证明状态映射、未回收子进程或收据缺失为 UNKNOWN；记录真实的已开始/已返回/可能仍在进行状态，成本不记为零。

**首次技术错误、前缀不匹配、预算将超限、资源测量不可用或实际契约偏离即停后续科学调用，无自动 retry、重复分支或补案。** 安全清理/回收不因停止而跳过，独立账本记录其启动与异常。预设最大次数是硬闸要求；wall、GPU、RAM 与后代内核/翻译过程如何限制尚需工程验证。实时采样存在空窗，不能据此保证树级总占用从未超过阈值。异常后的未确认操作保持 UNKNOWN。

## 6. 三臂物理上界（执行版需证实）

这些上界是候选规则，不是已执行成本，不包含先前消耗；计数包含技术失败时已经开始的操作。固定四个来源、每个最多 50 步、两条独立分支的重放 `r=1`，每个分支最多 `1 replay + a intervention + (49-a) continuation = 50` 步，`a` 为 0 或 1。每分支两次 recovery 后端生成，随后最多 49 次 P0 动作生成（在无效手回时可取 49）；重放使用已持久化动作、不调用模型。

| --- | ---: | ---: | ---: |
| 4 个来源 episode；其中记录 4 个 CONTINUE | 4 | 200 | 200 |
| 4 个 RECOVERY 分支 | 4 | 200 | 204 |
| 4 个 MATCHED-EXTRA 分支 | 4 | 200 | 204 |
| 总计 | **12** | **600** | **608** |

reset + step 最多 **612 次开始**。608 生成包括最多 **592 个 P0 actor**（来源 200 + 8×49）、**8 个 stage-1** 及 **8 个 stage-2**；这些独立上界假设无效手回仍可继续至 horizon。若事前可验证每次输入不超过候选 4096 token、P0 actor 输出不超过 32、stage-1 与 stage-2 分别遵循历史 40/16，最大输入 `608×4096 = 2,490,368` tokens，最大输出 `592×32+8×40+8×16 = 19,392` tokens。4096 是本草案候选上限，非对历史生产输入的已核实陈述。实际输入编码、预检 tokenizer 调用/成本和模型实现是否维持冻结 H4 仍未验证。若无法在生成前核验超限便不得开始该调用；不能截断 prompt 后声称基线不变。

候选模型权重加载上限 **2 次开始**：一次未适配的 recovery 后端、一次带适配器的 SFT-P0 后端，假设两者全程可复用且实际可容纳；生产接口、显存和可复用性均未知。如果实现需要更多加载/进程或不支持共享，须先修订审查，不得假设上限成立。候选环境构造最多 **12 次开始**（各 episode 一次），最多 12 个已成功构造实例各一次常规 close；失败后的必要清理另行登记，不能以次数上限阻碍回收。不得假定 construct、reset 与 close 一一成功。实际编译、翻译、子进程、CPU tokenizer、生成加载、磁盘写入及其内部循环与异常清理须由独立审计的生产实现、资源监控和真实 started/returned ledger 另列；目前次数、CPU、内存、GPU 显存/占用、实际 GPU-hours、wall-time 与磁盘均 **UNKNOWN**。在可检验阈值、可测能力与缺失数据停止规则确定前，本表不构成完整物理预算。启动后即时观测和有限监控不等于整个进程树硬上限。

原设计的 12 个来源 episode 和七个评估产品属于不同的 SFT 候选；本草案仅有四个来源与三臂，不包含那 140 个产品评估、训练、checkpoint 或 optimizer 操作。任何重跑、前缀额外生成、模型重新加载或新对照均不在此上限内。执行前需重新对账当前项目累计物理成本及此前 UNKNOWN 项，明确本研究增量与全项目累计，不能把旧成本清零或把旧值假定为当前值。

## 7. 定稿与执行前最小依赖

- 对三臂精确生产 source、模型和 tokenizer/adapter、环境、解析器、固定 prompt、action map 和随机性做独立 exact-SHA 接口审查；在 synthetic fixtures 下测试匹配前缀、诊断输出不进入消融组 stage-2 prompt、horizon、异常账本与 no-retry。验证来源 episode 的自然续跑确可复用且无事后选择。
- 静态确认允许的四个开发谱系组、不可变绑定、可验证任务目标及安全物理环境；不能把哈希或生成规则当独立 custody 证明。留存为 DEVELOPMENT_ONLY；不足则停，不读取任何受保护数据补足。
- 分别实测/约束合理的 wall、CPU、RAM、GPU、磁盘与编译/子进程预算，并规定无法测量时如何停；补入任务启动前、运行中与失败清理的原始账本、单次身份、保留证据与安全边界。
- 执行团队提交唯一完整命令、资源计划、先验账本、输出位置和冻结稿；独立审查代码、环境和数据漂移后才能进行具体工程 release。本文件本身不授权启动、不暗示现有正式评估隔离或统计效力已经解决。
