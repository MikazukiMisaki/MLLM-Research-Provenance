# 下一步最小实验路线：开发可行性，而非已验证的自我提升

状态：**设计候选，未执行；只使用已授权的项目文档与开发汇总。** 不访问未知/受保护任务，不运行模型、训练或环境，不改变科学代码。立即可做的唯一动作是：**冻结一份事先登记的生成规则、谱系划分、配对估计量与预算表**，并由独立方只审规则和哈希，暂不生成或打开任何待评估实例。下文提供可审初稿；尚未自动批准任何科学执行。

## 已有事实与研究范围

公开项目文档把当前里程碑限定为同一 Qwen3-8B 的两阶段 bounded recovery；H4 基线及 joint operator 冻结，不增加 selector、多轮反思、DPO、记忆、PPO/GRPO 或其他环境。先前直接 PddlEnv 的自造任务成功只支持各自单个工程实例。近期 clean-1 六步实验的 owner 日志记录七条返回快照和直接 worker 返回码 0；这是单一自造实例的初步原始记录，须以另行独立审计为准，不是模型成功率或训练证据。Parser-only 返回不证明编译、生产 adapter 或任务可解。所有这些运行都不能作为新的 held-out 模型评估。种子 1005、1009、1010、1022、1027 明确仅供开发，不得作为 held-out 证据。

现有 C1/C4 加权 SFT 是另行提出的候选比较，研究问题不同于“单次两阶段 recovery 是否有效”。如果后续把它纳入本项目，先明确其相对当前里程碑的范围与科学协议；不能把一次 loss fixture、工程 witness 或加权训练，写成已证明两阶段 recovery/selector 有效。两种路线共用同一个冻结基线和实际允许数据，不修改 H4、joint operator 或原始记录。

## 独立性、生成与数据边界

1. 用已知公开 domain 和自造 generator 的固定代码与版本，先冻结角色规范化、结构指纹、家族、目标谓词/个数、初态、可达性、文本生成与去重规则。划分的基本单位是**完整谱系/连通组件**：共享具体父体、重命名、近邻编辑、模板派生或可复原的同源变体归为同侧；不能按文件/随机种子把同一组件拆到训练与评估。连通关系必须在观察效果之前定义，不能为获得更好结果事后合并或拆分。
2. 在训练侧使用前，独立保管方根据预先承诺的生成规则和保密种子固定开发评估分配，记录不可变承诺与版本；收集、筛选、训练及调参不得读取评估任务、轨迹、错误或结果。只有冻结产品和分析后按固定顺序开放。没有条件建立这类隔离，就只做公开开发调试并明确不能称新任务评估；不通过搜索保护数据来弥补证据不足。
3. 自造、未用作训练、与已知公开开发谱系隔离是可检查的局部事实；**不等于**与未知历史数据、模型预训练语料、已有任务分布完全独立。相同公共 domain 和 generator 也会限制泛化。明确 estimand 是冻结的构造任务集合或其预先描述的生成分布，不能宣称一般 ALFWorld/自然任务泛化。
4. 现有结构分析提示合理的保守编辑连边可能只留下两个粗组件；同组件的多个变体不是多个独立组件。若事先独立审查不能确认足够的组件，保留分组件描述和有限集结论，不以增加相似变体冒充独立重复。

## 最小顺序与可比性

**先固定问题。** 对两阶段 recovery，先在允许的训练侧前缀做一个固定的 diagnosis/subgoal 调用，再固定一个 Action-ID 调用；严格同前缀、剩余 horizon、动作映射和解码，比较正常续跑与单次 recovery 的配对结果，另计新增生成与重放开销。只有在明确的开发门槛下有可复现的收益/无效/损害差异，才讨论后续学习；不得先做 selector。

**若另行决定进行 C1/C4 SFT 可行性研究，**采用同一合格训练记录、顺序、完整窗口、P0、tokenizer、上下文、优化器、学习率/裁剪和训练量；不同之处只为预先定义的 C1/C4 权重。标签的定义和已验证成功纠正必须在训练侧独立固定，失败动作不能伪装成成功目标；记录所有失败、无法验证和丢弃的尝试。以 distinct loss example 计 M/K，必须 `0<K<M`，建议每类不少于四个去重例子且来自多个源任务；不达门槛停止。该门槛只判断软件/数据可行性，不证明统计功效。C4 采用 `alpha=M/(M+3K)`，目标权重 `4 alpha`、其余 `alpha`，按完整更新窗口内未加权有效 token 数作分母；该对比包括梯度尺度、裁剪与优化器动态差异，不等价于“只改变样本重要性”。

冻结一个产品选择规则，不看评估选最佳 checkpoint。每一训练种子从同一可验证 P0 及相同初始优化器重启，C1/C4 配对相同实现的 RNG/顺序/窗口，记录完整参数及产品 hash；三对不同训练种子是最低的稳定性探查，不是精确的训练算法总体估计。评估时 P0、三份 C1、三份 C4 在相同任务实例与运行种子上按相同 H4 prompt、动作接口、greedy/32-token 解码及 50 步 horizon 执行；比较只因被测产品不同。所有任务/种子、启动次数、失败或未返回结果以及计划外成本均需记录，不能只保留成功 episode。

## 估计量与精度

预指定主要效应：在固定评价单位集合上，每一训练种子的 `success(C4)-success(C1)` 配对差；同时报告 `C1-P0`，并列出每种子的任务级胜/负/同值、无效/UNKNOWN、分组件计数与完整分母。训练变异、任务变异和模型/环境随机性分开；不能将三份模型在同一任务上的结果当成三个相互独立任务，或把一个训练种子当作训练算法重复。P0/H4、C1 与 C4 保持等价评估协议，不将辅助恢复调用混入一个 arm 而声称可比。

小型 20 单位试验只描述该冻结集合的条件差异。若无预定义的概率抽样/随机化与合适的组件数量，不给总体显著性或泛化置信区间；若只有两个独立组件，20 个相似变体并非 20 个独立抽样单位。作为量级说明：对真正独立、同分布且取值 [-1,1] 的配对差，双侧 95% 分布无关 Hoeffding 误差界要达到 ±0.10，需至少 `ceil(2 ln(40)/0.1²)=738` 个独立单位；在 20 个独立单位也约 ±0.607。另一正态近似在事先假设不一致率 0.20 且差值近零时约需 77 个独立单位，但该假设未经证实，不是功效保证。应预先确定最小重要差异与允许精度；资源不足就明确报告探索性结果，而不是声称高精度。

## 预先可核验的操作计数示例（上界草案，不是已授权或完整物理预算）

为把成本具体化，以下给一个保守可复算的 **上限示例**：最多 12 个训练侧 P0 episode，每个最多 50 steps；最多 4 个训练侧单次 recovery 分支，每个新 reset，重放至多 49 步、替换 1 步、续跑至多 49 步；每个 recovery 仅 2 次生成，续跑每步至多 1 次。最多 20 个冻结评价单位，对 P0 和三对 C1/C4 产品各跑一次、每个至多 50 步、每步至多 1 次动作生成；不在评估中添加 recovery。每个物理开始的操作计一次，即使失败或返回 UNKNOWN；首错停、不自动重试、不背填。

| 阶段 | 上限及计算 |
|---|---|
| 训练侧采集 | 12 reset，600 step，600 次动作生成 |
| 四个配对分支 | 4 reset，4×(49+1+49)=396 step，4×(2+49)=204 次生成 |
| 20 单位 × 7 产品评估 | 140 reset，7,000 step，7,000 次动作生成 |
| 总物理交互/生成 | **156 reset + 7,996 step = 8,152 starts；7,804 次生成** |

若每次生成输入超 4,096 token 立即停止而不悄悄改写 H4 prompt，则输入总上限为 `7,804×4,096=31,965,184` token；动作输出遵循 H4 的 32 token，上述 7,800 次动作生成加四次最多 64 token 的 diagnosis，输出上限 `7,800×32+4×64=249,856` token。这里的 64 是两阶段诊断阶段尚须另行审查的候选，不是已实现配置。超限、实际编码不符或不能维持冻结协议即停，而非截断后继续。

训练量示例：固定最多 32 个合格 distinct 例子，单例完整编码最多 1,024 token，一次 epoch、每完整/末尾窗口最多 4 例，三对 C1/C4：最多 `32×6=192` 单例 forward/backward，`ceil(32/4)×6=48` 次 optimizer step，训练输入最多 `192×1,024=196,608` token。实际 M/K、mask、部分窗口与模型 dispatch 必须在执行前验证；不足门槛不以其他或保护数据补足。固定模型加载预算示例最多 14 次（采集 P0 1、六次独立训练起始加载 6、七个评估产品 7），若实现在任一阶段需要额外加载或生成则停止并重审。

若每次 reset 都新建一次环境，此示例另最多 156 construct/load/close starts；源码提示正常 load+reset 各两次、共 4 次 `pddl2sas` 函数调用，但真正调用数、内部 native 调用和 OS 进程数 UNKNOWN，不能把 624 推算当硬限。还须独立计入前期工程与已消耗失败尝试，不能把历史 UNKNOWN 时间/资源写为 0。上表是严格条件成立时对**显式调用数量**的上限，并非完整训练/实验的总物理成本。

## 真实执行阻断

* 没有独立保管且预冻结的评估分配、组件证据和可验证的允许数据来源；实际合格 M/K、有效 token 与可靠纠正样本数均未知。
* 尚无完成审查的生产训练 dispatch、同源 P0/optimizer 复位、三对产品的精确可复现实现和训练资源监控；CPU/单设备合成 loss 一致不证明真实模型路径通过。
* 未绑定模型加载与恢复预算、活动 token 的真实账本、模型/GPU 前后处理、内存/时长/磁盘、启动/编译/清理/失败尾部和未知后代。当前不能证明有限的全进程树物理总上限；若必须要这种总上限，在可验证资源委托和外部账本到位前阻断。若接受较弱策略，也须明确总量未观测、风险责任、允许的 UNKNOWN 和停止条件，不能把它称完整可验证总预算。
* 三个训练种子与 20 个相似自造变体不会制造跨组件精度；不能用未经预注册的扩充、挑选或 post-hoc 调参替代任务独立性与统计设计。

下一步只冻结本协议的候选文字、哈希、责任和差异供独立审查；不生成评估实例、不查看保护任务、不启动模型/环境。审查若发现里程碑范围或预算不符，修改协议并重新固定后再考虑任何实验。
