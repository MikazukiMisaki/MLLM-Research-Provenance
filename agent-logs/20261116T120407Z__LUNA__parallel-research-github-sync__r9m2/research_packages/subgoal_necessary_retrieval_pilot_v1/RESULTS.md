# 必要取回反例：开发试验结果 V1

## 本轮观察

按照[预先记录的方案](PROTOCOL.md)，使用 Qwen3-8B、固定的裸编号执行提示与贪心解码，对 8 个虚构题面各运行两个子目标条件。16 次生成均记录了结果，过程退出码 0；没有运行 ALFWorld 或执行动作。

| 人工情境类型 | 给定相容子目标：选目标相容动作 | 给定冲突子目标：选冲突动作 | 配对中选择改变 |
|---|---:|---:|---:|
| 第一件已放好、第二件可见 | 4/4 | 4/4 | 4/4 |
| 第一件已放好但脏、需要取回清洗 | 4/4 | 4/4 | 4/4 |

特别是，在四个必要取回题面的相容条件中，模型都选择了**取回第一件**。这一观察排除了用“对这些输入始终拒绝取回第一件”描述本轮全部输出；它并不能证明模型会自行发现何时应该取回，因为提示已明确要求执行给定子目标。把同一题面中的子目标改为取回已经清洁的第二件后，四次都转向该动作。

本研究中的“冲突”是人工根据即时任务进度对动作的归类，不表示动作不可逆，也不证明任务最终失败。八个题面只有两套结构，每类四个词汇变体，不能把它们当作八个独立任务或独立确认集。本结果不证明其对真实环境、自然错误率、其他提示或模型的泛化；没有观察实际清洗、局部状态转移或终局。

## 记录及复算

16 次调用合计 3,921 个输入 token、80 个输出 token（包含 EOS）。程序从启动到完成事件约 14.997 秒；用户／系统 CPU 时间约 11.182／6.425 秒，单调用最长约 1.117 秒。离散显存样本最高 16,200 MiB，不是硬峰值或独占证明；其他进程的工作量及物理 GPU 时间未知。

原始本地事件日志 SHA-256：`d97cf08322d295a96d58973301379d3a99f4a11615f42475f2e7a3ad8a176913`。其中设备身份仅留在本地、不会上传；[脱敏导出](sanitized_events.jsonl) SHA-256 为 `ae7f79d78bd800a046b07d556194f496330a3a904531eab123e8ab12c4502fcf`。导出保留实际渲染提示、输入 token IDs、逐输入摘要、每次调用的输出 token、解析选择和完成事件，移除了 GPU 样本及设备身份。候选题面 SHA-256 为 `0b4fe41d9378def250ade4e1e71049878e9e34643108108034c28d2728ccdc6f`；运行脚本执行时 SHA-256 为 `47e80752c9961d5ea84085ce9138550f5ec7a2dd29d97942de37bb2e2e1d5414`。

同机核对了 16 条记录的题面、编号映射、输入 token 摘要及输出动作映射；[分析脚本](analyze.py)从脱敏导出重算的 [JSON 汇总](results.json)与本地原始记录的汇总逐字节一致。这些是记录内一致性检查；设备、模型权重、实际物理调用仍依赖执行环境，未独立认证权重或全量 logits。
