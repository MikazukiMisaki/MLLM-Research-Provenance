## Historical-only static version comparison

`historical_g1_archive_structure.py` compares only 60 already-executed G1 common-path historical identities, not the 1,207 potential paths. G1 schedule and raw trajectory fields match the hash-bound manifest by index, ID, split and recorded game hash. For all 60, the 0.4.0 game bytes match those recorded hashes while 0.2.2 bytes differ. Both versions parse as JSON; across these matched historical members, `grammar` and `pddl_domain` root values differ in 60/60, `pddl_problem` and `solvable` values match in 60/60, and `walkthrough` is absent in old/present in 0.4.0 for all 60. Only field-level equality/presence aggregates are exported, not game bodies, historical identifiers or outcomes. This pinpoints a static migration/observation-interface concern; it does **not** prove actual behavior differs, runtime incompatibility, faithful conversion, or any property of the 1,207 old-only games. The currently installed 0.4.2 Python version is not sufficient to identify historical asset version. Prior byte audit shows 0.4.2 asset supplies no new paths and changes 334 shared bytes, so it does not enlarge the old/current candidate identity union.
