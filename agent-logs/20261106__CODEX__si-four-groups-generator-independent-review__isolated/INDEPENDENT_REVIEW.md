## Implementation-blocking ambiguities to resolve before concrete generation

1. **Grammar task marker.** The design says replace the complete public text `Your task is to: UNKNOWN GOAL.` with “the validated fixed goal sentence” and also requires one task marker. It does not explicitly say that the replacement includes the leading `Your task is to: ` prefix. If the sentence is merely `clean ... .`, the marker is removed; the reviewed P0 worker's task extraction also requires that prefix. Freeze exact byte construction, e.g. `Your task is to: ` + prevalidated goal + `.`, require exactly one prefix and one task sentence, preserve all other public grammar bytes and test multiple safe identifiers. Static source `alfred.twl2:17` contains the quoted marker; runtime grammar parsing remains a separate test.
2. **Deterministic output versus recorded interpreter.** The design calls output a pure function only of public input bytes, versioned source and spec, while each deterministic manifest also records the actual interpreter/runtime version. The same input/source/spec under two runtimes can therefore generate different manifest bytes. Pin the exact interpreter/runtime as an explicit input of the determinism contract, reject a mismatch before output, and state that repeated equal bytes require equality of all pinned inputs. Alternatively keep runtime-specific data solely in a separate noncanonical run receipt. Test mismatch and compare repeated outputs under the same reviewed runtime.
3. **Author/date provenance versus deterministic bytes.** Protocol v3 requests author and creation date; v2's strict lineage fields contain only node ID, links and overlap, and its manifest records authorship category but no actual date/author. Define an immutable creation/provenance receipt separate from deterministic case bytes, recording the permitted identity/category and actual UTC time and binding batch and generator hashes. A nonauthenticated receipt does not prove independent custody or pre-execution commitment. Resolve privacy requirements without storing personal details or machine paths in distributable case manifests.
4. **Read-before-hash does not enforce asset isolation.** The design accepts caller-supplied public paths then reads to verify their hashes; absent prior path restriction, a protected or unrelated file could be opened before hash rejection. The case-spec input also needs a controlled source. Restrict both public inputs to independently reviewed allowed path identities and case specs to a fresh controlled workspace *before* opening; use bounded reads, no-follow/anchored file-descriptor rules and provenance checks to prevent path/symlink escapes or treat inability to establish this as UNKNOWN. Tests should use synthetic fixtures and must not access a protected file. A hash is an integrity check, not an access-control mechanism. Output writes must similarly remain inside the chosen isolated root, use exclusive no-follow creation and never replace another agent's evidence.
5. **Finite resource bounds are not yet numbers.** “Bounded” lineage and “excessive input” are not a deterministic validation threshold. Fix pre-read byte limits for public inputs and spec, JSON nesting/edge counts, role-name limits and maximum output bytes, plus a real CPU/time/memory plan for generator and full batch where warranted. Reject overflow before materializing huge data; record failure and leave no complete batch index. Avoid claiming whole-system hard containment or zero cleanup cost. The separate later CPU feasibility bound of 31 step starts + 4 resets remains conditional and does not include case-generation validation or unobserved native/descendant work.

The lineage schema is substantially safer than free-form descriptions, but validated role and node IDs and digests can still encode arbitrary user-provided strings. A safe naming/secret policy and reviewed input provenance are required; identifier syntax alone is not a secret scanner or proof of original authorship. Do not copy credentials, private paths, protected content or hidden solutions to distributable artifacts. Witness traces stay outside future model-facing inputs.

The documented fixed labels and union-find over known links are a reasonable grouping procedure; it only detects relations represented by the source/known graph and does not prove exhaustive equivalence or global non-overlap. The design leaves domain-specific “causal signatures not distinguishable” and expected source-level transitions as descriptions rather than executable definitions; freeze the actual algorithm and expected fields before case production, test alpha-renaming, swapped items, transitive closure and ambiguous outcomes. A source-hash assertion cannot validate the truth of a supplied external parent link. Missing/external overlap stays UNKNOWN. Compare only allowed newly authored assets; no private benchmark search.
