# v7 → SFT fixture-only token adapter, HOLD

`fixture_adapter.py` accepts only the SHA256-pinned bytes of the built-in, fictional two-row `fixture.json`; all other bytes are rejected, even a caller-authored `AUTHENTICATED` flag. The built-in fixture contains no real data, and its returned status explicitly says `UNAUTHENTICATED_FAKE`, `trainer_compatible=false`, `scientific_use=HOLD`. Its internal projection checks source-ref uniqueness, exact selection/artifact agreement, prompt+completion+mask, EOS, 4096 software ceiling and no truncation, then presents the exact token arrays and reconstructed labels for inspection. The fake path is a software example, not evidence about actual source authenticity. A dedicated `convert_for_training` unconditionally raises; there is no production conversion or training entry.

`python -B -m unittest -v test_fixture_adapter` exited 0 (`test-output.log`, `test-output.exit`), three CPU-only tests: exact fake token/mask preservation; rejection of changed or self-declared authenticated bytes; and internal fake alias/mask/overlength rejection. `make_fixture.py` constructs only the hardcoded fake example. No actual task, sample, model, environment or GPU was accessed, and no worker was started.

The real trainer input, 2048-vs-4096 software limits, LoRA/optimizer/loss details and the concrete v7 incompatibility are documented in `TRAINER_CONTRACT.md`. Neither an input JSONL nor a native Row source selection is produced for use by a trainer. Exact reviewed code hashes are in `source-hashes.json`; no claim is made that those sources were loaded or executed in a live run.
