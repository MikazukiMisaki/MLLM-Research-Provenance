# Unified stateful PyTorch CPU fixture kernel, HOLD

`torch_fixture_kernel.run_fictional_torch_cpu` itself executes one randomly initialized 4×4 linear model and one AdamW optimizer on CPU for 16 fixed fictional rows × 4 epochs: 64 single-row microbatches, accumulated four at a time into 16 optimizer steps. Seed is fixed, order does not shuffle, all inputs, masks, gradients, optimizer state and model are on CPU. It keeps the same model, parameter and optimizer objects, rejects malformed/nonfinite inputs, losses, gradients or state, and returns one fake final checkpoint description after step 16 with `FINAL_ONLY_NO_BEST`. This is not a real adapter checkpoint.

For each four-row group the candidate uses completion-only labels (prompt = -100), the existing native candidate's causal shift (`logits[:-1]`, `labels[1:]`), sum reduction and division by all active completion tokens in that group. It rejects nonbinary or altered masks, prompts/outputs outside bounds and any sequence exceeding the 4096 candidate software limit without truncation. EOS=3 is fictional. The fixed fictional fixture bytes are SHA-bound; the generic Python module and its HOLD functions are **not a security sandbox** and code modification/monkeypatching would defeat these checks. The real-training function unconditionally raises. A fake identity is explicitly unauthenticated and does not approve real execution.

The positive test actually invokes this candidate function, then independently constructs a concatenated reference loss and gradient for each of its 16 recorded batches. All gradients match at rtol/atol 1e-12; the test also reconstructs both AdamW moment recurrences across all steps, checks row/token/mask order and final fake checkpoint. A malformed-mask and real-entry rejection test also passes. Pinned CPU PyTorch 2.6.0+cu124, `CUDA_VISIBLE_DEVICES=''`: two tests, actual exit 0 (`test-output.log`, `test-output.exit`). A separate execution of the same candidate saved 64-microbatch/16-step details in `synthetic-trace.json`, exit 0 (`trace-run.log`, `trace-run.exit`). No real model weights, LoRA, training data, task, GPU or environment were loaded; no scientific model was trained.

The original `native_update.run_one_update` is not called or modified. Its four-row per-call AdamW initialization means 16 calls would reset optimizer state. The tested one-model/one-optimizer architecture matches its causal token-weighted loss mathematically for this tiny synthetic model, but does not demonstrate Qwen/PEFT, physical budgets, true training-time identity, production checkpoint compatibility, full precision behavior or actual model context capacity. No production trainer, provenance resolver, process owner or real authorization is integrated. Exact source hashes and new-file diff are retained in `reference-hashes.json` and `source-addition.diff`.
