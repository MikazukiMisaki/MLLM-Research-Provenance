# 两阶段恢复主线：人工子目标与动作选择观察结果 V1

## 结果

按照[事前协议](SEMANTIC_HANDOFF_PILOT_PROTOCOL_V1.md)，使用项目本地模型缓存完成一批 8 个虚构情境 × 2 个预先给定子目标 × 2 种动作列表顺序，共 **32 次选择**；工具返回退出码 0，日志记录 32 个准备、32 个调用开始、32 个原始返回、32 个分类结果和 `complete`。未自动重试。模型加载、输出及计数均依赖本机、执行者和所存日志可信的条件；这不是外部见证或硬件鉴证。

| --- | --- | ---: | ---: | ---: |
| 第一个动作对应的子目标 | 正序 C1 | 8/8 | 0/8 | 0/8 |
| 第一个动作对应的子目标 | 反序 C2 | 8/8 | 0/8 | 0/8 |
| 第二个动作对应的子目标 | 正序 C1 | 8/8 | 0/8 | 0/8 |
| 第二个动作对应的子目标 | 反序 C2 | 8/8 | 0/8 | 0/8 |

对每个子目标分别比较同一情境下的 C1 与 C2：第一个子目标 **8 对均有效、0 对语义动作变化**；第二个子目标 **8 对均有效、0 对语义动作变化**。四组和两组配对共享相同的 8 个情境，不能称为 32 个独立任务。此处没有缺失、异常或未尝试请求。正序和反序同时改变了编号与位置，因此不能分别估计编号和位置的效应。

在这 8 个简单的人工题面中，给定明确子目标后，动作选择均指向与其语义对应的命令，列表反转也没有改变所选语义动作。这为「简单、明确的子目标能够传递到动作选择」提供了一个限定的正向观察，**不证明**真实 ALFWorld 状态下诊断正确、动作可执行、局部进展或最终成功，也不证明复杂或含歧义的子目标同样可靠；更不能由这批结果断言原有第一件／第二件瓶颈的原因。诊断文字由研究者编写，而非模型第一阶段输出。没有测量动作概率、成功置信度或统计显著性。

## 实际执行与成本

- 实际运行时自报 PyTorch `2.6.0+cu124`、Transformers `4.56.2`，tokenizer 类 `Qwen2TokenizerFast`，EOS ID 为 `151645` 和 `151643`。本次使用 `enable_thinking=False` 模板参数及本地加载；这不证明模型内部过程或历史模型身份。
- 32 个提示合计 **5,436 个输入 tokens**；新增 **160 个输出 tokens**，每次 5 个，包含终止 EOS。最长单次请求记录约 **0.579 秒**。
- 运行日志从程序开始到 `complete` 记录约 **16.084 秒**；进程自报用户 CPU 约 **12.448 秒**、系统 CPU 约 **5.120 秒**、最大 RSS **4,660,076 KiB**。它们是进程自报或日志时钟，不覆盖全部系统和人工成本。
- 启动前、加载后和每次请求前后的离散设备查询中，最高整卡显存样本为 **16,182 MiB**。它包括该卡其他进程的用量，不能证明 GPU 峰值、独占或其他时间点的资源使用。
- 事件日志 SHA-256 为 `0ff8b9ed99a0b98d2453cef1c1b243fb3b5c342d7b3369164b11f4e42bf8df82`，保存在 Git 忽略目录 `artifacts/runtime/parallel-research/semantic-handoff-pilot-v1/`；执行程序 SHA-256 为 `b7d784c4dce04723b2a965ce7770a4ea77208fc255154bd4ac1d23be21c89d0c`。摘要用于字节核对，不证明模型来源、物理调用或日志没有被替换。原始日志包含虚构提示、token 和设备信息，不能默认外发。

## 对主线的下一步含义

下一步应保持第二阶段的选择规则不变，转向更贴近两阶段恢复的比较：在允许访问且来源明确的状态上，区分模型实际生成的子目标是否有事实支持、动作是否落实该子目标，以及后续事件和终局；若暂不能获得这类状态，则只能把本结果作为简单合成题面的基线。任何新批次需事前固定样本、对照、资源与停止条件，不能把本批 32 次观察当成独立留出验证。
