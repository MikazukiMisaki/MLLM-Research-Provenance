# 候选行样式与输出要求：虚构单步开发结果

## 结果

按[事前固定的方案](PROTOCOL.md)，一次运行完成 8 个人工情境 × 4 个条件，共 **32 次生成**；退出码为 0，所有请求均有准备、启动、返回与分类记录。题面属于 4 种结构、每种两个词汇变体；没有运行环境或执行动作。

每个条件按照它被明确要求的格式进行严格判断；同时另报**本研究自定义的裸编号参考**，它不是冻结 H4 基线解析器的完整模拟，见[接口澄清](INTERFACE_SCOPE.md)。有效编号必须符合该条件格式且存在当前映射。下表“有效且对应指定子目标”以每条件计划的 8 次调用为分母，是联合计数；如果只看有效输出，对应子目标的一致性为总体 30/30，而按全部计划调用计联合数为 30/32。这两种分母不能混同。

所有 32 条均正常结束，无未列编号、截断、未知或未运行。唯一的两个格式不符发生在“方括号候选行／要求裸编号”条件，输出分别为 `[A002]` 和 `[A003]`；按照预先方案，它们不被解析为有效动作。两个情境是相同“第二件位置未知”结构的词汇变体，而不是两个独立任务。其内层编号是否对应子目标不改变格式判定。

## 同状态配对与含义

输出要求固定为裸编号时，同一情境的行样式配对中 **6 对双方有效、2 对仅裸候选行有效**；这 6 对有效编号所对应的动作文本均相同，另 2 对的语义动作不可比较。输出要求固定为方括号编号时，**8 对双方有效且对应的动作文本均相同**。本实验的 30 个有效输出均对应研究者指定的即时子目标；研究者已明确要求执行该子目标，这不是自然规划、动作可执行性或任务成功率。

在所测提示及固定动作映射下，候选行样式改变了两个相关情境中的裸编号格式是否合规；其他情境的同类比较没有观察到该格式差异。同情境的配对固定了任务内容与编号，因而支持对这些具体状态的行样式比较；但这两例共享结构且对应 A002/A003，本面板不能识别为什么差异集中在该结构、内容或编号组合。不能据此推断总体错误率、独立任务上的稳定效应、统计显著性，或把有效配对子集的语义一致当成所有情境都不受影响。

两种输出要求下各自的合规是不同文本契约的结果：要求方括号时输出方括号虽符合该研究条件，但不符合裸编号参考。**这不是在证明对现有生产 parser 的性能提升，也不是建议更改冻结 parser。** 输出要求与候选行同时不同的跨条件差异不能归因给其中任何单一因素。这个新研究由上一批全部带括号的 16 条无效输出启发，但输入、任务和格式指令不同，不能证明旧批失败的原因，更不能补出旧批的进度规则动作结果。

Astra 对结果说明作了独立只读审阅，并提出上述分母与配对措辞澄清；它没有独立认证原始日志计数、模型或运行身份。

## 成本与记录

32 次调用记录 **4,436 输入 tokens、178 输出 tokens**（含 EOS）；单次最长约 **0.560 秒**。程序内部开始至完成事件约 **17.359 秒**；进程自报用户 CPU **13.029 秒**、系统 CPU **5.445 秒**。离散整卡显存样本最高 **16,160 MiB**，不是硬峰值或独占证明；系统 I/O、其他进程及人工成本未完整计量。环境为 Python 3.10.20、PyTorch 2.6.0+cu124、Transformers 4.56.2；权重身份与实际物理调用仍依赖本地配置、主机和记录可信性，未独立认证。

32 条保存提示均由同一本机 tokenizer 重新编码并与当次输入 token IDs 一致；32 条输出 token 去除 EOS 后由同一 tokenizer 解码，与记录的输出字符串一致。这是同机核查，不是独立模型复现。标准库分析器从[脱敏事件](sanitized_events.jsonl)重算的[结果](results.json)与原始日志汇总逐字节一致。Astra 还使用[独立标准库实现](independent_recompute/REVIEW.md)，仅依据固定题面和脱敏日志中保存的解码字符串，独立复算事件连接、四条件和配对，未发现差异；它未独立解码 token、检查模型权重或认证物理执行。事件移除了设备标识，保留虚构题面、实际渲染输入、token、编号映射及输出；摘要不能独立证明模型来源或物理执行。

结果后追加的同机未去空白核查显示，32 条原始解码文本均无首尾空白变化；这不能推及其他输出。[接口说明](INTERFACE_SCOPE.md)记录了本研究去空白规则与 H4 基线要求 `Action-ID:` 前缀、当前两阶段裸编号解析器不去空白之间的区别；相应[可选核查脚本](audit_unstripped_tokens.py)仅加载本地 tokenizer，不调用模型或 GPU。
