## Blocking gaps and specific triggers

1. **No real execution entrypoint or continuous monitor.** `direct_worker.py:191–195` explicitly raises for real execution even if flags change; `owned_supervisor.py:136` also unconditionally raises. `direct_worker.py:90–92,162–180` has a `MissingExternalMonitor` and only callback checks at selected boundaries. A fake callback is not independent continuous monitoring during model loading/generation/step; watchdog death, lost telemetry, host RAM/device pressure and shared-GPU interaction remain unresolved. The previously reviewed watchdog has separate blocking findings and cannot be silently coupled as a finished monitor.
2. **Physical device and placement are not bound before loading.** `direct_worker.py:97–100` accepts logical `cuda:0` but does not establish the expected physical UUID or host/container mapping. `pipeline.py:202–206` starts and completes the base-plus-adapter load before `direct_worker.py:175` observes parameter/buffer device names. An incorrect device, CPU-staged model or unexpected temporary resource use can therefore occur before placement is checked. `:126–141` explicitly does not verify all native/CUDA allocations or offload hooks; an absent `hf_device_map` is not proof of a complete placement map. Production `models/qwen.py:228–233` shows `cuda:0` performs `.to(device)` after loading, whereas `auto` takes a different device-map route. This is a material execution difference and 24-GiB free is not a proven capacity guarantee.
3. **Input binding is incomplete and conflicts with the current read boundary.** If `REAL_ENABLED` were flipped, `direct_worker.py:69–86` would reread all five full model shards, contrary to the present no-repeat-shard-read boundary. It checks a selected auxiliary set and two named adapter files, not all potentially consumed runtime inputs or an independently verified package/import closure; production PEFT is called without an explicit local-only argument in `sft/policy.py:45`, so its actual loading behavior also requires review. `manual_goal` enters `orchestrate_once` as an argument (`direct_worker.py:153,179`) and is not derived/verified there against the hash-bound manual file. The feedback-to-manual comparison is valuable only after an exact input/manual binding is proven. Existing cache-reference checks and a hash do not independently prove upstream provenance or unchanged model content.
4. **Acceptance is same-process, not independent semantic verification.** Tokenizer/rendering/decoded IDs are recorded by `capture.py:2–25`, then core records policy-returned prompt, parser and action metadata. `owned_supervisor.py:94–118` validates basic event/result/guard digest relationships and expected statuses, but does not independently retokenize/redecode or recalculate parser selection, final mapping and actual step from independently anchored bytes.
