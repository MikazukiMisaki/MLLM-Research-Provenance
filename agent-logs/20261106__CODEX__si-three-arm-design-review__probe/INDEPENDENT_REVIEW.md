# Independent review of the four-case, three-arm development draft

**Decision: NOT YET FREEZE / NOT EXECUTION-READY.** The draft's four-case accounting is internally consistent under its stated assumptions, and its fixed-prefix/no-replacement and UNKNOWN rules are constructive. The precise baseline contract, information-ablation estimand, action/error handling and implementable full physical budget still need prespecified resolution. This is a research design review only; no model, engine, protected task/trajectory/schedule or experiment was run.

## Findings and concrete corrections

1. **MAJOR — define H4 vs SFT-P0 explicitly.** Section 1 calls them frozen “H4/P0” interchangeably while section 3 defines source CONTINUE and handback as P0 and the other arms as unadapted Qwen recovery. Historical `TwoStageRecoveryOperator.__init__` checks a `QwenPolicy._config` with H4 max_new_tokens 32; `SFTP0QwenPolicy` wraps a backend and frozen historical P0 uses a distinct LoRA policy/prompt and 16 generated-token cap (`scripts/run_sft_recovery_runtime_compatibility.py:489-537`, `src/sft/policy.py:15-72`). These are not the same action policy. Freeze a single concrete per-arm model/adapter/prompt/parser/cap matrix: source and subsequent continuation = specified SFT-P0/adapter/16 if that is intended; recovery stage 1/2 = specified unadapted Qwen v2/40/16. Specify actual loading strategy, memory checks and adapter placement. Do not silently run H4 while calling it P0 or vice versa. The draft's 32 P0-output ceiling is conservative arithmetic, not proof that the frozen P0 setting is 32.
2. **MAJOR — P0 and recovery parsers are different.** `src/sft/policy.py:51-72` applies `parse_p2_selection` to decoded text; `src/models/protocol_stability.py:44-77` examines the final nonempty line and can accept preceding text. The V2 recovery stage-2 parser instead requires an entire bare ID and explicitly checks `output_complete`. P0's shown path has no analogous EOS/completion guard before parsing. Freeze exact input, output, EOS/token-cap and invalid-action semantics for each arm rather than calling all outputs one strict bare-ID contract or adding a new reject/truncation rule silently. For any prospective safety guard, label the behavior change and add equivalence/failure tests. Define a malformed first source decision as a scientific invalid/withheld outcome or technical UNKNOWN according to a frozen rule; do not silently categorize every absence of a first action as INELIGIBLE, nor count a parser failure as a task failure without specifying it.
3. **MAJOR — information is not fully erased by MATCHED-EXTRA.** The valid path removes diagnosis/subgoal text from the matched arm, but the frozen invalid marker and action-withholding rule expose the Stage-1 validity status to stage 2 and the policy. This is a comparison of actual generated text versus a chosen placeholder **conditional on shared protocol and its validity mechanism**, not an intervention that removes all information from stage 1. The placeholder itself is a semantic intervention and has different token length; report actual prompt/tokens and avoid statements that it isolates “reasoning”, extra compute, or pure diagnosis alone. Two independent greedy calls with identical input are not guaranteed bitwise identical on all runtimes; preregister how to report stage-1 output/status mismatch without conditioning case inclusion on observed treatment outputs. If status equivalence is a prerequisite, specify the precommitted stop/UNKNOWN rule and consequences, while preserving all started costs; do not silently discard cases. Otherwise interpret unequal statuses as part of implementation/measurement variation.
4. **MAJOR — freeze semantic diagnostic handling without revising historical status.** The independently inspected parser can report a whitespace-only diagnosis valid. The fake v2 supplementary `semantic_nonempty` is a Boolean over parsed values, not a correctness or completeness indicator: missing can map to False, truncated extracted text can map to True, and logging failure itself causes STOP. If used, record the original stage-1 raw output, completeness and frozen historical status plus a separately defined three-valued nonempty/UNKNOWN assessment; define UNKNOWN when completeness/field availability cannot support a judgment. Do not silently exclude, repair, reclassify historical valid, or gate an arm differently. If new strict nonempty rules withhold actions, call that a new prospective treatment and fix when they apply relative to the second physical generation.
5. **MAJOR — make fixed-prefix operational states reproducible and decision-independent.** `r=1` is clearly fixed before outcomes, source CONTINUE precedes both branches and no replacement is allowed. Freeze the task ancestry and own-case bytes, exact reset/config/seed *bindings* without reading protected pools, intended wrapper/direct environment and its limits, executed command and ordered raw/public action maps, prompt/task/observation/history and available local-state hashes. Before R and M verify each replay's recorded public state and action map with the source at decision time; hidden state remains UNKNOWN. Do not make branch eligibility depend on CONTINUE eventual success. Source-terminal, actor-invalid, no-action, technical exception and incomplete replay need disjoint operational categories. Four legitimate self-authored units are not established by a schema or shared domain; do not label them independent held-out tasks.
6. **MAJOR — budget is a conditional ceiling, not yet complete launch budget.** Under draft assumptions: source 4×50=200 P0 generations; each of 8 R/M branches ≤49 P0 calls plus 2 recovery calls = 8×51=408; total 608 starts = 592 P0 + 8 stage 1 + 8 stage 2. Reset starts 12 and step starts ≤600, hence reset+step ≤612. The valid case has `r=1, a=1, c≤48`; invalid-handback has `a=0, c≤49`; both satisfy `r+a+c≤50`. These are maxima and differ by outcome. With 4096 **actual consumed input tensor** tokens/call, 608×4096=2,490,368 input-token ceiling. Assuming the draft's loose 32 P0 output ceiling gives 592×32+8×40+8×16=19,392 output tokens; if the actual frozen P0 uses 16, the stricter bound is 9,920. Neither establishes runtime input length or tensor-guard implementation. Per-call input caps must be checked on the exact token IDs presented to generate without truncating the frozen prompt; CPU-only pretokenization is not by itself proof of actual tensor identity. Separately budget recovery model load, P0 base load, adapter load/attach, tokenization, 12 construct/load/reset/close limits, replay, translation/compile and descendant processes, disk, CPU, device time, monitor/supervisor/cleanup and previous or incomplete work. The candidate 2 model loads is conditional on actual reuse and fit; do not conflate adapter attach with zero-cost load. Unavailable limits and cumulative budgets must be explicit before execution.
7. **MAJOR — outcome and stopping semantics need an executable contract.** Freeze handling of source terminal after first action, no legal actions, P0 parser failure, Stage-1/2 malformed/invalid/truncated, duplicate or stale mapping, deliberate OSR no-action/handback, natural environment terminal, timeout and missing receipt. Keep technical UNKNOWN out of success/failure denominators; record all 4 allocated groups and outcomes, preserve starts/returns/unknown. Choose R10-style handback vs R4 interruption once, and apply it identically in R and M. Predefine how the all-four feasibility gate treats source-terminal/ineligible and any UNKNOWN. A later result-selected change to eligibility or metrics would invalidate the prospective design.

## Statistical and causal limits

At most four development groups permit interface verification and descriptive paired differences, not a meaningful estimate of population success improvement, absence of harm, or reproducible generalization. Specify both per-group paired wins/losses/ties and initial/all-group denominators; no post hoc replacement or subset claims. A true P0-only arm estimates a total operational contrast with differing intervention calls/model identity, while R–M estimates a narrower text-versus-placeholder contrast under same call count; neither is a clean per-token compute causal effect. Source-first scheduling is unblinded and time-ordered; alternating R/M mitigates only their order imbalance. Four-case appropriateness as an engineering screen depends on actual independent lineage/custody and not equivalence to real production ALFWorld wrapper.

## Relationship to SI-U1 self-improvement

The central research objective is whether training on an agent's own experience improves success relative to the frozen P0 and suitable supervision controls. This three-arm recovery proposal neither trains an agent nor evaluates an updated policy; any recovery success is therefore not self-improvement or evidence of success-rate uplift. At most, with an explicitly designed data pipeline it can test whether a recovery produces **candidate corrective experience**: a public pre-decision state/history, an exact environment-grounded selected action and observed successor, with documented origin/model/treatment and validity. An outcome of one step alone does not establish that the action is beneficial or a suitable supervision label; success of the later suffix is confounded by P0 actions, and a difference versus matched or continue branches is not itself an action-level counterfactual ground truth. Invalid/withheld/UNKNOWN and failed trajectories must never be silently turned into positive targets.

Before interpreting recovered actions as learnable targets, independently define target eligibility, prefix/action/outcome attribution, label uncertainty, outcome-independent or preregistered filtering, duplicate/task lineage, data permissions, and common-quality/exposure controls. Freeze the comparison between source experiences and matched neutral/expert/P0 examples; then use a separately budgeted training procedure and task-isolated post-training evaluation with specified statistical precision. Four hand-authored development cases cannot establish sufficient training coverage, data-source independence, generalization, or expected SI-U1 gains. If an adequate set of credible, non-leaking targets cannot be obtained, stop the training plan rather than relabeling successful scripted paths as self-generated improvement.
