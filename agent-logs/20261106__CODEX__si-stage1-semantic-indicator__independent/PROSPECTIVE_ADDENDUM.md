## Finding independently confirmed

The compiled stage-1 regex requires a literal space after `Diagnosis:` and then one or more non-newline characters. An all-whitespace capture can match. `parse_stage_one_output()` strips each captured field, rejects counts above 12, but never rejects count 0; a complete two-line raw output with an empty-after-strip diagnosis and a nonempty subgoal can therefore yield historical status `valid` and zero diagnosis words. The v2 operator generates stage 2 before testing stage-1 validity, and historical `valid` passes the empty diagnosis into the stage-2 prompt. When stage 2 and grounding also pass, a selected action is possible; this is a static possible path, not evidence it actually occurred. Literal historical parser behavior and prior results remain untouched, and no retrospective rate is inferred.

## Proposed symmetric prospective rule

**Recommendation: keep the historical parser and action behavior exactly as frozen for this exploratory comparison; add an observational field, not a new treatment gate.** Each RECOVERY and MATCHED-EXTRA branch independently emits its own stage-1 generation and gets its own historical `StageOneDecision`. Keep raw output/bytes, `output_complete`, exact historical parser `status`, extracted diagnosis and subgoal, their word counts, stage-2 prompt/decision and final disposition under the normal journal. In the matched control, do not put the generated text into stage-2 or actor/environment state; retain it only in audit storage. Execution must not consult this supplemental indicator, its value, or aggregate rates.

Use the same version-pinned Python string rule for both arms, with three-valued fields and no model judgment:

- `diagnosis_nonempty`: if the original returned stage-1 generation is complete, historical parsing returned normally, and extracted diagnosis is a Python string, TRUE iff `len(diagnosis.strip()) > 0`; FALSE otherwise. If incomplete, no return, parser exception, missing field or a non-string value, UNKNOWN. `subgoal_nonempty` is computed identically on the extracted subgoal. FALSE means a present string is blank after Python `str.strip()`, not a missing/unknown field.
- `semantic_nonempty`: FALSE if either field is FALSE; TRUE if both are TRUE; UNKNOWN for all other combinations (e.g. TRUE+UNKNOWN). This name is retained for compatibility but it is only a string-presence check; it is not evidence of meaningful diagnosis, correctness, action alignment, faithfulness, or safety. Pin Python version/Unicode semantics: `str.strip()` is a whitespace operation and can leave invisible non-whitespace code points intact. No ad hoc normalization, content-dependent text repair, model-based judging or alternate mapping is allowed.
- `historical_parser_valid` remains the exact status comparison `status == 'valid'`, independent of this flag. If stage-1 status is malformed/truncated/too-long, preserve that status and the extracted field observations; where no complete, normal parsed string exists the indicator is UNKNOWN. An indicator TRUE must not promote an invalid parser result. A historical valid+FALSE is recorded as the discrepant condition; do not retroactively rename it parser-invalid.

This field is calculated by an offline audit over immutable, complete record bytes or by a side-channel logger proven not to alter calls or decisions. A missing audit field or logger failure must never silently become FALSE; follow the trial's technical UNKNOWN/stop rules if reliable evidence cannot be persisted. Freeze the function, schema and runtime before execution. Log individual field values, tri-state flags, original parser status, whether two generation calls started/returned, action ID/grounding and disposition. Respect ordinary evidence sensitivity and data access restrictions.

## Two-arm symmetry and analysis

Both arms follow the **same** historical status criterion, actual stage-call count (stage 2 still requested for historical invalid), action grounding and proposed frozen OSR handback policy. If a branch's parser says `valid`, RECOVERY feeds its original parsed fields to its stage 2 exactly as before, even when supplemental `semantic_nonempty=FALSE`; MATCHED-EXTRA uses predeclared placeholders exactly as for every historically valid output. For historical invalid status, use the same frozen invalid marker in both and apply the same preselected invalid/handback rule. No stage-one output, its blankness, count, this supplemental field, or arm-level audit status is fed to the control stage-2 prompt, except the historical valid/invalid status already stipulated by the common interface; this status is itself information, so the control withholds diagnosis/subgoal content, not all information about stage 1.

Identical rules do not promise identical outputs or statuses: calls in the two physical runs may differ. Report each branch's original status and tri-state indicator, the pair's joint categories and both outcomes for **all** preselected eligible groups; retain valid+FALSE, historically invalid, UNKNOWN and partial/technical records. Neither primary comparison nor branch eligibility may remove a pair because either branch has FALSE or UNKNOWN; technical UNKNOWN remains subject to the preregistered first-error stop and incomplete-study reporting. Counts restricted to both indicators TRUE may be reported solely as explicitly post-generation, descriptive sensitivity summaries, with the excluded pair counts and no causal/generalizable interpretation. Four development groups cannot identify rates reliably. The combined diagnosis-and-subgoal versus placeholder contrast remains affected by placeholder semantics, prompt length, call order and runtime randomness, not exact compute-matched or a pure diagnosis-only experiment.

A stricter alternative (versioned nonempty action withholding) would alter prospective scientific execution semantics and potentially change treatment effects even if call count remains two. It is **not** this recommendation. If separately proposed, both arms must apply the same gate at the same point after both calls, prospectively define UNKNOWN/handback and costs, and undergo separate scientific/exact-code review. Never describe that strict version as historical-equivalent or silently modify old evidence.

## Before any release: fake-only edge checks and open boundaries

Use synthetic text/objects only to check: spaces and tabs in a diagnosis with a valid subgoal produce historical valid but audit FALSE; ordinary one-word fields produce TRUE; final blank subgoal, malformed layout, ID leakage, overlength and truncation retain real historical statuses; no-return/exception/missing/non-string produce UNKNOWN; Unicode invisible-but-not-whitespace is not misrepresented as semantically meaningful. Confirm same original raw bytes and exactly two generation starts (when the two-return path is reached), stage-2 call on historical-invalid stage 1, no extra call/action/retry, original valid+FALSE dispatch in treatment, placeholder dispatch in control, and unchanged OSR handback. Fakes cannot prove production state isolation or an actual model result.

Other boundaries of the four-group draft remain: matched information ablation is unimplemented; fixed source prefixes may have no actual recovery opportunity; public replay equivalence does not prove hidden state equality; two backends need separately checked fit; historic 40/16 caps, P0 prompt/config, 4096 input candidate, action parsers and sources need exact binding; component custody, independent held-out tasks and complete CPU/GPU/translator budget remain unproven. Equal call caps do not equal equal tokens/FLOPs. No new selector or DPO, no scientific run, and no historical result alteration.
