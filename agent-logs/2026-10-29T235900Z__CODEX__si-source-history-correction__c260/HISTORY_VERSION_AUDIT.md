# Correction: SFT protocol bindings and historical game hashes

This note corrects this audit's earlier statement that the old SFT protocol's split/exclusion bindings contradict the present files. That statement was wrong: the protocol stores SHA-256 over canonical JSON values, not SHA-256 over pretty-printed file bytes. The two hash domains differ as expected. The earlier Luna correction `SI_P0_PROTOCOL_HASH_CORRECTION_ADDENDUM.md` had already established this distinction. Preserve the old statement for traceability but do not rely on it.

An independent standard-library recomputation, `SFT_PROTOCOL_VERSION_INDEPENDENT_AUDIT.json`, shows both current split and exclusion canonical hashes exactly match their protocol fields. The current protocol, split, exclusion and collector raw bytes are also identical to their respective tracked bytes at freeze commit `f44ec40b2e12d34cb709b32eca591bae7b39d45d`. These establish consistency of saved versioned artifacts, not a record of what a historical process actually loaded.

The original accepted initial and extension datasets contain 1,273 distinct source IDs. Their recorded source-game hashes all match both the corresponding currently installed local game and the official 0.4.0 archive member; their recorded trajectory hashes all match corresponding local trajectories. This supports that accepted historical records describe games with 0.4.0 asset bytes, assuming those source fields were faithfully recorded. It does not establish the archive installation procedure, the historic environment package version, or the game version/actual execution of the five unaccepted SFT-manifest candidates. It is not evidence of model pretraining or non-exposure to other sources.

Historical production launcher/environment and per-rejected-candidate execution receipts remain unlocated in the searched sources. The five initial-manifest hits stay conservative possible collection exposure; do not label them individually confirmed executions, SFT-training exposures or held-out. No candidate task payload, outcome, model, CUDA or ALFWorld was accessed.
