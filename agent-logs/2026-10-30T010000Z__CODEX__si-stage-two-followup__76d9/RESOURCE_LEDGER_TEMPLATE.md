# Project-level resource ledger template and evidence rules

Status: STATIC_TEMPLATE_ONLY. Not a runner, operational budget, hardware reservation, execution protocol or permission. Use a new immutable ledger version for each future scope; never edit the underlying historical journals or merge unknown into zero.

## Identity and provenance (one leaf invocation per row)

- Stable unique run ID; linked task/phase; classification `science`, `engineering`, `preflight`, `offline_analysis`, or `unknown`; start/end and timezone; scientific commit and model/adapter/tokenizer/data/protocol identities; authorization or approval document where the historical protocol required it; source and raw-event paths plus hashes; reviewer, audit status and retrieval status.
- Parent run, predecessor/successor, attempt number, planned/actual retry, underlying logical unit IDs and physical event IDs, plus a duplicate/overlap group. A run summary that already covers children is an aggregate, never another additive leaf. Mark whether input is a raw physical event ledger, independently verified artifact, reported aggregate, inference or absent.
- Stage may be acquisition (including failure collection), data preparation, training, preflight, evaluation, diagnostic/remediation or storage. For training record fixed seed/arm, fresh vs reused seed, data lineage, planned and actual microbatches, updates and training tokens. Do not treat repeated seeds or common tasks as independent scientific units.
- Per field record `{value, unit, state, evidence}`: states `observed`, `derived`, `unknown`, `not_applicable`; append `failed`, `open` or `reserved` where needed. An omitted or unknown field is **not** zero. Distinguish actual measured from projected, reserved or hard cap; no numeric limits are specified by this template.

## Physical effects and accounting

For each API/model generation, environment construction/reset/step/close, model load/close, training work and GPU context: record separately **started**, **physically returned/completed**, **failed**, **open/incomplete** and **reserved/spent** using stable event IDs. Record a call that physically returns but fails lossless recording even if its logical unit never completes. Distinguish physical action steps from all other non-reset environment operations. Include generation input/output tokens, failed/unknown return token counts, supervised training tokens, replayed/cached operations, CPU tokenization, and any external service charges. A count is chargeable only once per real operation; wrappers, journals, validator echoes and source aggregate rows are references, not new operations.

For each attempt record nested process/wall/worker/supervisor/device allocation intervals and their nesting. Billable or allocated device time must have an explicit clock source; do not sum nested wall times or infer worker allocation from device-wide sampling. Include shared GPU identity/namespace and contemporaneous device-visible memory/free/utilization observations, worker-reported allocator peak/reserved, measurement method and ownership certainty. An empty visible compute-app list and device-wide free memory do not prove exclusive GPU or process-to-device ownership. Record failed startup, partial allocation, interrupted operations and uncertain owner as real or unknown; no retrospectively erased consumption.

## Logical research and effects

Record task identity and parent/family/scene proxy in protected private artifacts, split and sampling provenance, frozen order and seed, unit opened/closed/failed/NA, generated examples accepted/rejected and results excluded under the frozen protocol. Logical replay, comparison arms, aliases and re-used trajectories may have treatment-specific costs even when the physical operation occurred once: record the alias link and the scientific treatment rule separately; never fabricate a new physical call or count a shared operation twice. Attempts and partial units remain discoverable after failure. Prior NO_GO, missing outcomes and stopped runs remain visible.

## Storage and dissemination

Per run, bind original file identities, size and SHA256, artifact class/sensitivity, local/remote retention location, access control, content policy, source-to-archive byte verification, and actual uploaded/downloaded bytes if known. Account separately for input datasets, mutable checkpoints, raw trajectories, logs, temporary copies, compressed archives, snapshots, final outputs and remote copies. Distinguish logical unique content from separately occupied filesystem bytes; sum device peaks only when paths and timestamps are measured. Record free space and evidence integrity at named times, but a snapshot is not a storage reservation. Keep model weights, credentials, machine-specific data and private task text out of public provenance under the existing policies.

## Completeness, monitoring and release boundary

1. Reconstruct every relevant old leaf invocation and verify parent/successor links, event hashes, independent summaries and archive material before any project-wide total. Track unresolved lineage, missing historical G1/SFT/training/diagnostic/failure records and uncertain prior exposure as explicit unknowns.
2. A future study can build expected resource requirements only after its prospective estimand, independently eligible tasks, statistical precision/power, software interfaces and number of arms/seeds are fixed and reviewed. Reserve explicit headroom for inputs, failed acquisition, fresh/reused seeds, preflight, actual evaluation, engineering repair, allowed attempts, storage and incomplete operations. This template does not choose any numbers.
3. Record resource ceilings and measured stop triggers only in that separately reviewed study. Distinguish per-unit, per-run and project cumulative quantities, and science/engineering/preflight. Carry prior costs, freeze the treatment and task selection independently of results, record fail-stop and any explicit retry policy, and preserve distinct identities for every attempt.
4. The monitor must capture physical and logical started/completed/open events, time, memory and disk with timestamps and source receipts. Fail closed on missing or contradictory evidence, drift, partial units, resource overrun, unknown ownership where required, GPU contention or exhausted capacity. Preserve the raw state and seek independent analysis rather than silently retrying.
