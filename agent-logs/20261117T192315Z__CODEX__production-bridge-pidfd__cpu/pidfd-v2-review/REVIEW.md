## Implementation boundary

`owner.py:42–65` retains the owner object and temporarily defers default SIGINT until assignment of the returned Popen; the tested real SIGINT is then propagated and UNKNOWN recorded. After assignment, `terminate` catches `BaseException`, records UNKNOWN when possible, re-raises KeyboardInterrupt/SystemExit, and closes acquired pidfd in `finally` (`:66–91`). When journal recording fails `_unknown` marks in-memory `durable=False`; it cannot guarantee a durable event. The regular `_record` fsyncs the journal. For power-loss durability, `__init__` creates the owner directory and fsyncs the new directory but does not fsync its parent directory; persistence of the newly created directory name after a system crash has not been established. The tests demonstrate ordinary observable filesystem writes, not power-loss recovery.

`terminate` validates `/proc/self/fdinfo/<fd>` PID against the owned Popen PID, checks `waitid(P_PIDFD,...WNOWAIT)` for direct-child waitability, then signals only by pidfd. The no-reaper and no-PID-reuse assumptions between spawn and pidfd bind remain essential; initial single-thread/default-SIGCHLD check does not prove an external waiter or kernel-level policy cannot intervene. The capability/header fallback is restricted to the examined fixed Python and Linux environment; compatibility elsewhere is not established. No foreign PID or process group was signaled in these tests.

Popen raising internally after creating a child but before returning a handle, SIGKILL/owner death, arbitrary asynchronous exceptions during individual assignment bytecodes, hidden reapers, descriptor or filesystem failure, unrelated signal policy and repeated SIGINT are not covered by the passing tests. UNKNOWN may mean the child is still running; failed durable recording must halt the larger workflow without claiming complete evidence. The owner cannot establish host namespace visibility, descendant cleanup, GPU ownership, GPU work completion, or permission to start another arm. A process-tree supervisor, runtime source/product identity, physical resource budgets, and a controlled parent-worker integration require separate implementation and independent validation. No scientific task/model/GPU/environment was run.
