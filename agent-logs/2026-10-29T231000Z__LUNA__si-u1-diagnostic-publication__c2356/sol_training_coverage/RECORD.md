# SI-U1 training data coverage: read-only independent audit

Scope: audited B/C frozen training metadata and the actual selected training records, data reviews and completed training receipts. Aggregate output only; no task identities or text are included. No model, environment or evaluation result was read or run. This audit does not evaluate effectiveness.

Each arm had 78 distinct task parent groups, four selected action examples per parent, 312 unique training examples, four epochs and 1,248 presentations. Each actual completed training receipt records 78 optimizer updates and **6,240 supervised tokens**, including EOS; not 67,240. Each arm has 34 simple, 24 clean, 10 cool, 8 heat and 2 pick-two parent groups, corresponding to 136, 96, 40, 32 and 8 examples respectively. Thus pick-two represents 2/78 independent parent groups and 8/312 unique examples per arm; 32 presentations are repeated examples, not 32 independent examples. No look-at parent is included.

Programmatically verified actual dataset hashes, manifest hashes, data-review hashes and result hashes against accepted values and checked manifest/receipt cross-bindings. Both actual receipts report completed, 1,248 microbatches and 6,240 supervised tokens. Recorded full inputs including completion are B=661,620 and C=695,872 (C +34,252, +5.18%); identical supervised dose is not identical input context or training examples. Both share the 700,000 input-token cap and max sequence length 2,048. Both arms have 312 distinct raw prompt SHA256 values, zero repeated exact prompt bytes within the arm, no conflicting targets for the same exact prompt hash, zero action IDs failing A+three-digit syntax, and no exact parent group or prompt SHA overlap between arms. Each example is present once per epoch; the four epochs repeat examples by design.

The prior CPU tokenizer feasibility report for the same selected construction recorded 1,560 supervised tokens for each one-pass 312-example set, no length failures, max length B=1,138 and C=1,102 (both <2,048). That source was labelled feasibility-only; it supports a bounded structural check and is not by itself a training approval or an independent re-tokenization in this audit. Independent B/C data reviews authenticated selected data and full ordered exposures. A syntax-valid ID, successful-trajectory inclusion or exact-prompt uniqueness does not establish that any selected action is optimal or generalizes. Data verification here is consistency against recorded hashes, not an independent reconstruction of every original source event or GPU arithmetic.

C consists of four selected action decisions from retrospectively successful P0 trajectories per chosen parent; B contains selected expert demonstrations matched by family and dose, on different parent tasks. This design provides an informative policy-level comparison of these specific data construction pipelines; a difference cannot identify data provenance as the sole cause because task contexts, state distributions and demonstrations differ between arms. There is no clean recovery-specific treatment. Limited pick-two exposure is a plausible diagnostic hypothesis, not evidence that it caused any failure; parent group count, repeated dose and action-position coverage must not be conflated. Exact parent/hash disjointness does not prove semantic, scene, or layout independence. One initialization and one realized training run per arm cannot establish seed stability.
