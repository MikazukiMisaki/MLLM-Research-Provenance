# Frozen one-pass expert training feasibility upper bound

Purpose: report a conservative upper bound, not qualifying pairs or an experiment on policy behavior. The only input is the existing expert SFT JSONL, expected SHA256 c547e8f0c5988b29288f2a097169c7859741b7d4f53f222af31f5e2889d516cf, expected exact size 116622803 bytes. It contains expert demonstrations, not self-generated experience. Population and order are physical file row order, exactly one sequential pass. Use only rows with dataset_split exactly `train`; other valid splits are skipped based solely on split (whole JSON records necessarily pass through the decoder). No evaluation results, trajectories, model, tokenizer, GPU or environment are used.

Within stored task_id, group records with exactly equal prompt string (no normalization) and equal dictionary indexed_action_map (string keys and values; ordering irrelevant). A potentially qualifying group requires two distinct rows with distinct nonempty target_action_id strings that map to nonempty command strings. This deliberately treats two file rows as potentially distinct source decisions even if not proven; it does not require same underlying episode, completion, exact encoded tokens, target mask, equal target lengths, state, canonical parent identity, or label semantic correctness. Hence it is only a necessary-condition upper bound for the narrower exact prompt/map stored-task construction, not a bound for all possible renderer/tokenization or policy designs. Count distinct stored task IDs represented, groups, eligible train row count, and missing/invalid fields; output no prompts, actions, token IDs or names.

All train rows with missing/untrusted fields mark their known task ID UNKNOWN; if task identity or split cannot be read, mark the global bound UNKNOWN. The conservative upper bound is union of known-match IDs and field-unknown IDs; source-decision authenticity, true parent identity, tokenizer/rendering equivalence, equal loss masks and source/evaluation separation always remain UNKNOWN, so even >=16 cannot be marked eligible or GO. A parse failure, changed input, SHA mismatch, bytes/rows/time/memory limit, or interruption invalidates all counts: report UNKNOWN, preserve receipt, no retry. Split values other than train or validation are UNKNOWN, not silently excluded. At most 134217728 source bytes, 30000 rows, 2097152 bytes per row, one CPU-only process, 60 CPU seconds, 90 wall seconds, 1.5 GiB address space, 65536 bytes output file. No extra data files or evaluation outputs read. Freeze code and this plan and their hashes before launch. Counts are aggregate-only. This is one new analysis, independent of consumed self-success C scan.
