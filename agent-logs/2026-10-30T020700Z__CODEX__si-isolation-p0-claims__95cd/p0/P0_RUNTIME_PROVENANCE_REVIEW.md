# P0 historical base and tokenizer: targeted read-only evidence review

**Finding: useful saved-tokenizer evidence exists, but no newly located contemporaneous launcher/runtime or exact historical base-model/tokenizer HF revision.** A cache snapshot existing today, even one with matching files, is not sufficient to identify the snapshot actually loaded in 2026-08. Lack of a receipt is not evidence of non-exposure. This is neither an experiment nor a model-pretraining corpus audit.

- Historical Git commit `7b731576bba1924d17227583df65e9728e9d24d1` (author timestamp 2026-08-28T22:59:34Z, a recorded timestamp rather than a trusted external clock) contains `reports/sft_policy_bootstrap_summary.json`, SHA-256 `455eff6aa9d65ad3ade56fb0b257893e993d139075b21b2efca4d87eabfcf767`. It records adapter directory digest `6e403d85b150a74dfcc176f1f180ce4baf6fdacd922d2f96b3ceef0a21100f11` and training-result hash `e6a47124200cacba4d1f3eaf97fdf79657d7df04f072a4d5446c2bec677c399e`. Recomputed from the 11 current files using the historical project directory-hash algorithm and from current training-result bytes, both match the historical declarations. This supports byte continuity of the saved final adapter directory including tokenizer files, conditional on the saved historical Git record; it does not attest which base weights the historical process loaded.
- The final adapter and selected `checkpoint-2354` each contain seven named tokenizer artifacts; each pair's bytes match. The final adapter is bound to the historical report by its directory hash. Checkpoint equality is a present-byte comparison, not a separate contemporaneous checkpoint receipt. Exact individual file hashes, missing entries and source paths are recorded in `FILE_COMPARISON.json` and `check_files.py`. `trainer_state.json` SHA-256 `fe725cc8b9fd30c137f6cbb67fbfb5c195316f075c6017a953a70a24ecdbd3d2` records global step 2354 and the selected checkpoint path; this is saved trainer-state evidence, not a launcher or full runtime receipt.
- Git source `src/sft/training.py` at the report commit SHA-256 `0c722ca6ff17aa50da6fb294b632619f65f99936ce41e61ec0dab6288c7b584e`, equal to the same file at reported **pre-inference** commit `f44ec40b2e12d34cb709b32eca591bae7b39d45d`, loads tokenizer and model by configured model identifier without an explicit `revision` argument, and saves the tokenizer into `final_adapter`. This is inspectable implementation evidence, not proof that this exact source was used for training. The recorded pre-inference Git revision is not itself a pre-training launch receipt. The adapter config has `revision: null`; the saved training result names Qwen/Qwen3-8B but no top-level revision/commit field.
- Current local cache `models--Qwen--Qwen3-8B/snapshots/b968826d9c46dd6066d109eabc6255188de91218` and current `refs/main` identify that snapshot now. Three historically bound final-adapter artifacts (`tokenizer.json`, `vocab.json`, `merges.txt`) match the snapshot bytes; saved `tokenizer_config.json` differs, and the other three saved artifacts are not present as separate names in that snapshot. Differences do not by themselves establish a tokenizer functional mismatch; serialization and save formats can differ. These present-day byte comparisons cannot establish the old process's loaded revision or base weight identity, and no model was loaded.

## Scope and missing evidence

Inspected the saved full/smoke model-artifact directory file inventory, bootstrap runtime directory names, its visible filename patterns for logs/launch/receipt/manifest, saved training result and selected trainer state, historical reachable Git report/source history, earlier raw audit and later reproducibility matrix, plus a bounded search of local research-note markdown/JSON/log filenames for SFT-bootstrap identifiers. No contemporaneous process command, authenticated supervisor receipt, loaded HF snapshot/commit, or complete tokenizer/base runtime inventory was identified within this search. This is **not** an exhaustive search of all filesystem paths, inaccessible services, external logs, deleted data or remote Git objects; absence from this inventory cannot prove a receipt never existed, or that any data was unexposed. The historical Git file's reported `git_revision_before_inference` does not bind the earlier training process. It remains valuable to search operator-held process logs, archived shell session provenance and deployment-specific runtime receipts if available, verifying identity and timing before relying on them.

This check read metadata, saved code and current tokenizer bytes and streamed hashes of the 11-file adapter tree. It did not load models, tokenizer libraries, CUDA or ALFWorld; it did not inspect candidate task results, rerun training or modify historic evidence. The binary adapter was hashed as bytes, not opened as a model. Current cache equality is explicitly weaker than historical execution binding.
