# One-generation guard v4: raw token-ID capture candidate

Status `SYNTHETIC_ONLY_REVIEW_PENDING`; no real model, adapter, GPU or environment was loaded or called. The earlier v3 guard remains unchanged. V4 adds capture of the exact input IDs presented to the guarded `generate` call and generated sequence IDs returned by it, in the local started/returned generation ledger events. It verifies integer types and counts, copies the IDs to CPU and forwards the original model arguments unchanged. A copy failure before the call rejects it; a copy or ledger failure after a physical call leaves that call consumed and possibly unknown, never automatically retryable. CPU copies may add synchronization and timing overhead in a real CUDA run; actual PEFT/CUDA behavior and cost remain untested.

Twelve fake-edge tests passed in the pinned-Python subprocess, exit zero; they cover raw ID capture, input/output copy errors, invalid IDs, token/decoding/attention limits, existing ledger refusal, production P0 policy with fake runtime, simulated journal failures and killing one own fake child after start with a second child refused. Thirteen selected source/test inputs matched before and after; this is not a complete runtime or import closure. The same limitations as v3 remain: the claim is per trusted directory, not a global no-retry mechanism; code retaining another model reference can bypass the guard; arbitrary filesystem mutation is not prevented. Guard logs need an externally stored raw-byte digest and final anchor, and incomplete or failed fsync after physical work remains uncertain. The candidate has not been bound to the real loaded Qwen/PEFT model, model loading budget, device monitor, core-event journal or a reviewed supervisor. Its token files and receipts may contain local paths or prompts and must be retained locally or sanitized before publication. Independent exact-byte review is still required before a real probe.
