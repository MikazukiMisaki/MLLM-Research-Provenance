# 中性子目标与必要回退：开发试验结果 V1

## 结果

依[事前方案](PROTOCOL.md)，完成 8 个人工题面 × 3 种子目标条件的 **24 次贪心动作生成**，退出码 0，无缺失、截断或格式无效。模型和第二阶段提示固定，每个题面只改变即时子目标。所有动作均按事先由研究者编写的集合分类，未运行环境。

| 子目标条件 | 预定题面数 | 选入事前可接受集合 | 选研究者指定的局部冲突动作 | 其他／无效／未知 |
|---|---:|---:|---:|---:|
| 相容的具体动作 | 8 | 8 | 0 | 0 |
| 与当前进度冲突的具体动作 | 8 | 0 | 8 | 0 |
| 不指定具体动作的中性任务指令 | 8 | 8 | 0 | 0 |

六类结构分别包含第二件可见 2 题、第一件脏需取回清洗 2 题、第一件阻挡入口需取回 1 题、第二件已持有 1 题、目标已完成 1 题和第二件位置未知 1 题。相容、中性条件在所有六类中均选择了事前可接受动作；冲突条件在每类中都选择了被明确要求的局部冲突动作。不能把六类当作各有多次独立重复。

中性与相容条件在 6/8 题选择完全相同；另两题选择不同，但都在各自事前集合内：任务已完成时分别选择 `look` 与 `inventory`，位置未知时分别选择两个未检查位置之一。必要清洗及阻挡场景中，中性条件都选取回第一件；这不是“永远不取回第一件”的简单规则。

## 能支持什么

在这批人工题面和固定执行接口下，**显式局部子目标可以把动作从研究者预定的可接受集合引向局部冲突动作，而宽泛中性任务指令下的选择均落在该集合内**。该对照有助于说明此前行为不只由“取回第一件总是错误”的标签构造造成。

解释需保留四个条件：

1. 第二阶段被明确要求执行给定子目标，服从冲突子目标是该接口下的行为观察，不能单独视作违反指令或证明内部推理机制。
2. 中性子目标是宽泛任务指令，与具体动作子目标的信息量、长度和内容不同；这不是等长安慰剂，也不是撤掉子目标的基线，不能归因于某一个词或单一内部过程。
3. 接受集合与诊断均由研究者根据虚构题面编写，并非独立盲标或真实环境合法动作。目标已完成时的信息动作不等于终止；拿走物体可能可被纠正，局部冲突不等于不可逆失败。
4. 8 题只有 6 套结构，其中两类各含一个词汇变体。这是小规模开发观察，不是独立确认集，不推断真实任务的自然错误率、实际进展、终局成功或泛化效果，也不计算显著性。

本试验不使用存在重复 task/arm 与 UNKNOWN 组合计数风险的 `two_by_two` 入口；没有证据仅凭这项问题说明历史报告受影响。

## 消耗与复算

24 次调用合计 5,702 个输入 token、120 个输出 token（含 EOS）。启动到完成事件约 15.456 秒；用户／系统 CPU 约 11.618／5.839 秒，单次调用最长约 0.584 秒。离散 GPU 显存采样最高 16,200 MiB；不代表峰值、完整 GPU 时间或设备独占，其他进程及人工成本未知。

原始本地日志 SHA-256 为 `d1396fd8a2591c428d2b827f0f5cabda94fcda435e09ddb13b47a631de2cf22d`；[脱敏导出](sanitized_events.jsonl) SHA-256 为 `363e0e6465c9889e95e35f8e6ec0a8d29135c9dd93e429de3408632350e65fbf`。导出移除了设备采样和身份，保留实际渲染提示、输入 token IDs 与逐调用摘要、输出 token、解析结果和完成事件。题面 SHA-256 为 `03a9fee21f68605bb83467c41573e91997220366fe52e1173daf02cb857cc5eb`；执行脚本当时 SHA-256 为 `08d9c7ef2b2ee2b05ac8f689a42d513781599056680395e88121625dafd97365`。

同机核对了全部 24 条题面与映射、实际输入 token 摘要、输出动作映射和 EOS；[分析程序](analyze.py)从脱敏导出重算的 [JSON 汇总](results.json)与原始日志产生的汇总逐字节一致。上述检查验证记录内一致性，不独立认证物理执行、模型权重、来源身份或未保存的全量 logits。
