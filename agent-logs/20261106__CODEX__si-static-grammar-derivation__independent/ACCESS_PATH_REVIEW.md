# Direct-path access: bounded static evidence

This is a read-only source review, not complete file-access tracing or an execution approval. The actual user constraint is to avoid accessing protected or unknown historical tasks. Full operating-system isolation is a stronger sufficient control proposed in the earlier design, not a user-stated requirement in itself. Its absence should be reported as uncertainty, not reworded as proof that such access necessarily occurs.

The installed `textworld/envs/pddl/pddl.py` `PddlEnv.load` first attempts `open(filename_or_data)`, catches `TypeError`, and treats the argument as the task mapping. With the explicitly constructed built-in dictionary used in the prior self-authored witness, its PDDL domain, problem and grammar come from in-memory mapping values; this code path does not pass a historical task pathname to that `open`. `PddlEnv.reset` reconstructs state from that same mapping. The inspected `fast_downward/interface.py` `pddl2sas` parses the supplied domain and problem strings using `split("\n")` and serializes the result through `StringIO`. `load_lib` copies the installed shared library to a temporary directory and loads the copy, so a real run has filesystem effects beyond the own task and the public domain/grammar; temporary and native runtime access must not be described as absent. Imports and native libraries are not fully closed or audited by this static inspection.

By contrast, the separately inspected `src/sft/environment.py` factory calls `AlfredTWEnv(configuration, ...)` before it replaces `factory.game_files`. Its constructor is known from the adapter review to collect task files. It must not be pointed at an unknown or protected historical pool, and the prior direct-engine evidence does not establish factory equivalence. An owned empty configuration narrows the intended scan but, without a verified confinement/audit mechanism, does not itself prove a complete filesystem boundary.

A future bounded direct test may be considered on the basis of exact source review and explicitly pinned own inputs without claiming kernel-enforced isolation. It must never invoke the standard scanning factory, must document the explicit data path and temporary-library effects, and must treat undocumented reads/import behavior as unresolved rather than assert a complete access allowlist. Preparation alone provides no evidence of model accuracy or task independence. This record does not waive the protection of historical tasks or authorize execution of any unread or unreviewed runner.
