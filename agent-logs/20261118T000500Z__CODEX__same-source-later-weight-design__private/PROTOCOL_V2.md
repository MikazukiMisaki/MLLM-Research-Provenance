## Question, treatments, and limitations

On this agent and source pool, does uniform self-imitation improve exposed-DEV success relative to no continuation, and does mildly emphasizing later trajectory decisions change success relative to uniform self-imitation? Labels are recorded selected actions in ten ultimately successful trajectories; they are not proven optimal, corrective, efficient or independently verified expert actions. A later position is not a validated measure of progress or causal contribution. Success-only sampling is selected and can include detours. One training seed and 12 exposed development parents do not establish generalization, reproducibility or significance.

- C-quarter: original verified product, no additional training.
- Uniform: continue once from the exact same C-quarter initialization using each selected row weight 1.
- Mild position: continue independently from the same initialization and with the exact same ordered rows, token IDs, completion-only masks, optimizer configuration, schedule and seed; only per-row weight differs. For zero-based position j in a parent of length n, w_j = 0.5 + (j+1)/(n+1). Exact sum over that parent is n, so mean weight is 1. For n>=2, weights are not all one and 0.5<w_j<1.5; n=1 gets 1. Parent row totals match, but the effect of weighting on completion tokens, per-update gradients and clipping need not match, particularly when completion lengths differ.

The candidate source is precisely 99 eligible rows from the 10 successful parents of completed exposed-DEV ledger a1ab34fb287372be582648295eb7a506a8ed70174b1689e0f7c2cfd7d4e4a799. Freeze parent index and within-parent sequence, exact row-to-weight mapping and source provenance. Fixed 99 rows x4 epochs =396 microbatches, accumulation 12, 33 optimizer steps per arm; no sample dropping, truncation, best-checkpoint selection, or retry. Peak LR 2.5e-5 is a proposed fixed parameter, not an optimized value. For each example, compute the mean causal cross-entropy over its active completion tokens. For each update, take the mean over the 12 microbatch example means after multiplying each by its fixed row weight: L=(1/12)*sum_i(w_i*(sum_t loss_it)/T_i), with T_i the number of active completion tokens and T_i>0. Uniform w_i=1 therefore gives the mean of 12 per-example means. This differs in general from the historical objective that divides total completion-token loss by total active completion tokens. Validate the actual causal shift and masks against the frozen implementation, and compare values/gradients with an independently calculated reference using this same per-example-mean objective; do not claim native historical token-mean gradient equivalence. Both arms process the same raw token and target-token counts; their effective token coefficients w_i/(12*T_i) generally differ, and parent row-weight conservation does not imply equal token contribution, gradient or clipping. Report actual token counts, per-example lengths, weight distribution, effective weighting and per-update clipping and gradient norms when available.

Original generation token IDs and full rendered chat bytes were not persisted. Reconstruct prompt text from frozen production renderer and source observations/history, then encode prompt, selected decoded action and EOS as a newly created training encoding. Freeze tokenizer identity/config and bind the resulting immutable row artifact identically for both arms; never claim it reproduces original generation token bytes. Validate full prompt+completion<=2048, prefix consistency, nonempty masks, logged action/transition/sequence, source and model identity for every row. Fail closed on any ambiguity, missing row, identity mismatch, truncation or conflicting labels. The assigned implementation must establish custom per-example weights and the 99-row schedule, with independent validation of the same per-example objective, accumulation, optimizer continuity and final checkpoint.

## Do not train if

Any of the following holds: fewer or more than the bound 99 eligible rows, no trustworthy action/source binding or required prompt/mask/length reconstruction, effective weighting not independently verified, disjoint evaluation parents cannot be demonstrated, safe operation and complete budget cannot be bounded, absolute wall-time no longer fits, a new output or any prior effect cannot be isolated, or current hardware use conflicts with the permitted shared-device policy. These are feasibility gates, not evidence that the scientific hypothesis is false. Alternative if the position question is not worth two training runs: uniform continuation vs unchanged on the same 12-parent DEV panel; this costs one training arm and 24 episodes but cannot test position weighting. Equal-parent weighting is a different question and requires its own frozen design and incremental budget.
