# Injected device-generic stateful SFT research operator — HOLD

`device_core.run_injected_core` is an isolated candidate with an externally constructed model, fresh optimizer, token rows, effect owner and final checkpoint callback. It locates the single model device through parameter objects and creates tensors there; it has no device-specific loader or CUDA-specific calls. The only executed tests used a fictional CPU model and token rows; GPU / PEFT / Qwen behavior is untested. `dispatch_real` unconditionally raises. The generic Python API is not a security sandbox and cannot establish whether caller inputs or callbacks are genuine or authorized.

The operator checks 16 ordered rows, full prompt + generated token lengths <=4096, <=16 completion tokens, exact completion-only mask, vocab and EOS/pad. It reuses the same injected model and *fresh* AdamW for 4 epochs, four row microbatches per step, 64 forwards/backwards and 16 optimizer steps; it checks matching initial optimizer parameters/config and continuous parameter/optimizer identities. Shifted CE uses `logits[:-1]`, `labels[1:]`, float logits and sum loss divided by the four-row total of active target tokens. A single final checkpoint callback runs only after the 16th step. The result is a claim; it does not implement an actual checkpoint, readback, reload or best selection.

For the injected owner the operator calls `reserve(kind,request)` before each validation/model-mode, zero-grad, forward, backward, optimizer-step and final-checkpoint effect; it calls `returned` on normal return and attempts `unknown` on an exception after reservation. No internal retry is made. The owner here is only an interface: its implementation, authentication, durable write/ACK, global budgets, failed reservation semantics, monotonic/no-resume rules, actual physical accounting and process ownership are not provided or verified. Failure during reservation may leave an unknown durable reservation; failure after step or checkpoint may leave mutated state or I/O. If owner `unknown` itself fails, the operator preserves the original exception but does not establish durable UNKNOWN. No rollback or cleanup is claimed.

Initial trainable parameter values, losses, gradients and post-update trainable values / optimizer tensor states receive finiteness checks. This is NOT a full scan of frozen parameters, and before/after device work inside checks is merely a claimed owner effect. Actual task provenance and alias checks, exact P0/LoRA identity, RNG control, mixed-device/sharded models, CPU/GPU resource limits and monitor, optimizer persistence, full checkpoint integrity and independently reviewed execution are not implemented. The single-device assumption is explicit. Software max_length 4096 is not evidence of real model context or GPU memory feasibility. The selected input rows are untrusted objects; externally mutating code/objects is not prevented.
