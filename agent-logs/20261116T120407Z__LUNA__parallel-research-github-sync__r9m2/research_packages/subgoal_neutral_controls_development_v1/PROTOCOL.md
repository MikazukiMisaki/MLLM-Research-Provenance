# 中性子目标与必要回退：受控开发试验 V1

## 问题与范围

此前固定执行接口的开发观察中，给定的错误子目标往往引导模型选择相应动作；后来的必要清洗反例表明，模型并非在所有已见题面中都拒绝取回第一件。两批均没有中性子目标。本轮探索：当不指定具体动作的中性子目标替代相容或冲突子目标时，在不同状态类型里会出现哪些动作选择？必要回退和正常任务分别怎样表现？

该试验属于 Parallel Research 的虚构题面开发观察；不替代 self-imitation 主线，不估计自然错误频率、真实执行收益、成功率或泛化。第二阶段沿用已有固定的“执行给定即时子目标、返回裸动作编号”提示与同一 Qwen3-8B；不增加 selector、额外检查调用、多轮恢复、新环境或训练。

## 题面、条件与单位

`cases.json` 固定 8 个人工题面、6 类结构：第二件可见 2 题、第一件须取回清洗 2 题、第一件阻挡入口须临时回退 1 题、第二件已持有 1 题、目标已完成 1 题、第二件位置未知 1 题。场景由研究者指定可选动作，不是从环境提取的状态；第一类与清洗类各有两个词汇变体，其余每类一题。总计不是八个独立任务、非 held-out；同类变体不等于独立结构。

每个题面三种条件，只有“冻结的即时子目标”字段不同，其余任务、观察、诊断、动作及编号均逐字一致：

1. `compatible`：指定一个作者按题面判断可推进目标或保持已完成状态的具体动作。
2. `conflicting`：指定一个会在当下移走已正确放置物体或将持有物体放在非目标处的动作；这是即时局部进度的研究者判定，不证明动作不可逆或最终任务无法完成。
3. `neutral`：统一使用 “Act appropriately for the task, given the current situation.”，不给出具体动作；这是一条宽泛任务指令，不是完全没有额外文本或等长的安慰剂。

每题四个候选编号；作者指定可接受动作集合 `acceptable_actions`。已完成时 look 与 inventory 同为可接受的信息动作，不代表环境已停止；位置未知时打开两个未检查位置均可接受，不以隐含答案硬指定一个。其他合法动作保留 `other`，并非都能从题面证实错误。兼容指令指定的候选编号 A000—A003 各出现两次；冲突候选编号也各出现两次。完整题面、动作集合及映射在调用前固定，不依据输出修改。

三条件按题面顺序执行，条件顺序按题号在兼容→冲突→中性、中性→兼容→冲突、冲突→中性→兼容之间循环；顺序是固定的，最多 8×3=24 次贪心生成。每次最多 16 个新 token、输入不超过 1,024 token、BF16、thinking 关闭；使用本地 Qwen3-8B 与相同 chat template。分别标出样本数、独立结构、实际调用数与非有效输出，不合并进先前 16 次。

## 固定统计与解释

- 按 6 类状态和 3 种条件，列出选择、作者可接受集合内／局部冲突／其他合法／格式无效／截断／未运行；报告分子、已执行分母和计划分母。
- 逐状态列出三条件选择及是否改变；中性与相容的动作变化、可接受集合中比例是描述性对照，不解释为特定子目标的因果收益。明确指出中性指令与具体动作指令的信息含量不同。
- 正常进展、清洗及阻挡必要回退、已持有、已完成、未知位置分开呈现，不把不同结构组的差异归因于单一因素。完成状态按可选信息动作评估，不等同环境执行或任务终止。
- 第二阶段收到的诊断和子目标均为研究者直接指定；不报告自然产生错误的概率、内部推理机制、检查器准确率、环境状态变化或终局结果。不报告显著性，保留不支持假设的结果。
- 代码仅做人工动作集合匹配；接受集合和诊断属于待外部语义复核的研究者判断，而非真实环境自动真值。已有 two_by_two 对同 task/arm 的二值与 UNKNOWN 重复记录可能误计完整配对，正式统计前需排查和修复；本轮不调用该工具，也不声称已有报告受影响。

## 执行与记录

一次性新输出目录；不覆盖、自动重试、以别名重做旧批。调用前记录实际渲染提示、实际输入 token IDs、逐输入摘要、模型/分词器软件版本、解码参数、候选映射与 call ID；调用后保存输出 token、解析动作、耗时及 EOS 状态。原始日志包含设备采样，仅留本地；供审阅的导出删除设备身份并标明原始与导出摘要。摘要只能固定保存内容，不能独立认证物理设备或权重。

加载前确认设备当前可用且显存占用低于 8,192 MiB、利用率低于 5%；采样失败、身份不一致、离散显存达到上限、输入超限、终止符不符合规则、单次请求达到 120 秒或日志错误时停止后续调用，保留部分记录。利用率为离散观察，不能证明未来空闲或设备独占。进程 CPU 与外层墙钟各最多 1,800 秒；每个日志文件最大 16 MiB。资源不可用或题面无法可靠标注则停止，不自动重试。
