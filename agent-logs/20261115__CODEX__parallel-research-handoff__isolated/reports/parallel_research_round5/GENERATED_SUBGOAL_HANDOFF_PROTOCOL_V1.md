# 恢复主线：模型子目标与动作选择的配对观察 V1

**首次生成前的固定方案。** 在八个人工构造的文字状态中，第一件已放好、第二件已持有且目标位置可用。问题是：两阶段恢复的第一阶段实际提出什么子目标，第二阶段是否选择完成第二件的命令；在同一状态与诊断下，把第一阶段子目标替换为人工明确子目标后，选择是否不同？这是隔离文字链条的开发观察，没有 ALFWorld 环境执行，不说明真实第一件／第二件机会或终局。

## 单位、对照与指标

八个场景全由脚本内手写；每个场景有一个明确的第二件放置命令、一个撤销第一件的命令和 `look`、`inventory`，四项按场景编号循环移位，避免固定正确动作编号。各场景固定执行：

1. 用项目两阶段恢复的第一阶段指令生成一次诊断和子目标，最多 40 个新增 token。按两行 `Diagnosis:` / `Subgoal:`、每行不超过 12 词且不含动作 ID 的契约分类；截断或无效保留。
2. 第一阶段格式有效时，用其诊断及子目标进行一次第二阶段动作编号选择；无效时该条件标记未执行。
3. 用同一诊断和人工给定的明确放置子目标进行一次第二阶段选择；若第一阶段无效则使用固定中性诊断，此时不构成与模型子目标条件的有效配对。

第二阶段采用项目两阶段 V2 的裸 ID 指令，最多 16 个新增 token；两个条件对同一场景使用完全相同的动作编号和顺序。计划第一阶段 8 次、模型子目标条件最多 8 次、人工子目标条件 8 次，共最多 24 次模型生成，不重试。每个场景记录第一阶段原文和解析、每个动作条件的原始输出、语义选择及明确目标命令。第一阶段的语义是否支持观察、子目标是否指向第二件，由研究者对八段实际输出逐条核对；事实不充分或有歧义时记未知，不把格式有效当作语义正确。

主要描述指标：第一阶段格式有效数 / 8；模型子目标和人工子目标条件各自选中第二件放置的数量 / 8，另列未执行、格式无效、截断及未知；两个条件都生成有效 ID 的配对中，选择是否改变及正确性转变数。不得把无效或未执行当作错误动作，分母为零时比例未定义。人工条件使用已知正确子目标，差异只描述该组题面上替换子目标的效果，不能把它归因于真实环境、完整诊断或终局。八个便利场景不是留出样本，不做显著性检验。

## 运行与停止

使用项目配置指向的本地 Qwen3-8B 缓存、单张 GPU、BF16、本地加载且禁用远程代码和自动下载；不重复五分片摘要。设贪心、输入最多 1,024 tokens，保存提示、原始输入 token 数、输出 token IDs、解码文本、阶段与动作映射；实际 EOS、模板摘要、库版本及生成配置记日志。模型和日志身份依赖可信主机、项目缓存与无不可见替换。阶段一生成结果缺少明确 EOS 且达到长度上限记截断；其他终止异常停批。格式无效与截断保留，第二阶段按上述条件处理。

单批外层墙钟 1,800 秒触发停止，进程 CPU 上限 1,800 秒、单输出文件 8 MiB；请求超过 120 秒停止后续调用，阻塞调用由外层总时限终止。加载前后及每次请求前后查询同一 GPU 的整卡显存；任一有效样本 ≥43,008 MiB、查询失败或设备身份不一致即停。采样是软停止，可能漏峰，不等于硬峰值限制或设备独占；实际适用设备规则若更严格须遵守。异常、输出或设备记录失败、超限则保留已完成/部分记录并停，不续跑、不自动重试。

输出保存在唯一新建且 Git 忽略的运行目录，日志逐事件追加并同步；分别记录模型请求数、输入和输出 tokens、程序墙钟、进程 CPU、RSS 与显存采样，未知成本不记零。该批不读取受保护任务、方向 2 受限窗口包及其三份输入，不修改冻结基线或联合算子，也不重启旧 120 状态重跑。
