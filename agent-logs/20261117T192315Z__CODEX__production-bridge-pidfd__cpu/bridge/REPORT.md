# Pair parent / held-worker CLI bridge candidate: synthetic only

**Real execution DISABLED; BUDGET_SUFFICIENCY_NOT_VERIFIED.** This is an isolated candidate for review, not a real experiment or launch gate. `bridge.launch_production()` unconditionally raises, and `fixed_product_dev/worker.py` retains its unconditional main-entry `RESEARCH_HOLD`. No real task, model, tokenizer, environment, GPU or historical batch was run. Code and previous frozen records were not edited.

`bridge.run_synthetic_bridge` is derived from the reviewed v4 fake scheduler. For each fixed-order synthetic arm it builds an in-memory worker config through the static adapter, writes fictional config and manifest, starts the fixed `fake_cli_worker.py` as an independent child with the real worker's `--config`, `--config-sha256`, `--budget-fd` shape, and passes the socket via `pass_fds`. The fake CLI uses the actual held worker's `read_bound` to read and hash the config and manifest. It then uses the existing candidate arm stage, actual pinned original episode / generation / parser / projection, original EffectOwner/Controller/Journal, candidate StageBudgetChannel, and one parent GlobalOwner. Parent journal records config hash, child argv hash and fd as `synthetic_worker_cli`; each child records `synthetic_cli_config_verified` and explicit fictional scope. This is a software protocol demonstration only: **the real worker main is never invoked, and the fake child adds a `synthetic_test_context` config field.** Therefore it does not establish a real production worker end-to-end connection. `v4-to-bridge.diff` contains the exact scheduler, worker-boundary and test changes.

The persistent fake positive run has 4 fake materializations and 8 fake resets, loads, generations and steps, and 8 completed child claims; the second-arm mismatch run stops before its load after one first-arm fake generation and step. The raw chains, configs, fake input files and stderr are under `synthetic_evidence/`. `python -B -m unittest -v test_bridge` exited 0 (two cases, one test process: `test-output-final.log` and `.exit`); separate `python -B preserve_synthetic_receipts.py` exited 0 (`synthetic-receipts-final.log` and `.exit`). The intentional mismatch is caught and reported, not treated as a science result. `synthetic_evidence_before_scope_record/` is the prior test-only version before the explicit scope record was added.

## Independent unknowns / required work

Fictional budget numbers only allow exercise of a test interface. Prior audit identified static adapter's zero-additional-budget hole: equality against declared ceilings does not show that a proposed batch has sufficient budget. This bridge does **not** cure that defect and never interprets it as permission. `synthetic_scope` and `STATUS.json` explicitly preserve these boundaries.

Future work would first retain owned Popen and coordinate its fsynced UNKNOWN, pidfd handoff and no-retry state with the global ledger under the candidate's single-thread/default SIGCHLD/SIGINT/no-external-reaper assumptions, then independently review that combination; it would still not prove hidden descendants or GPU cleanup.
