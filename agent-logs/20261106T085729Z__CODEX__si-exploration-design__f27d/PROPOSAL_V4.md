# Minimal self-improvement exploration — working proposal

Status: DESIGN ONLY. No data object, new scientific run, gate, or budget is established by this document. The user has instructed the team to advance and run suitable experiments; the remaining requirements below are research and execution evidence, not a request to repeat general authorization.

## Question and treatments

On a lawfully usable and explicitly bounded development surface, do fixed self-experience continuation recipes improve task success relative to the same starting P0 agent, and does a fixed targeted-weight recipe change outcomes relative to uniform continuation? Compare P0, newly trained uniform C1 and newly trained targeted-weight C4 on the same prospectively fixed development tasks. Use one chosen learning rate, same initial checkpoint, examples, order, dose, optimizer and seed policy; only the prespecified loss weighting differs between C1 and C4. Fix how weighting is normalized and its application to supervised tokens before seeing results. Do not assume historical 312 examples or target-family counts apply to a future dataset. Preserve all raw outcomes and costs under applicable access controls; publish only allowed summaries. No sweep or automatic retraining.

Existing P0 65/82 and self-experience 67/82 are an exposed historical TRAIN panel; net +2/82 is not a confirmed effect or independent generalization. Historical P0 outcomes may be reused only if identical task identities, runtime, treatment, and provenance are verifiably comparable; otherwise run a new P0 on the fixed surface. Do not sample by known outcomes. The size N, eligibility, parent grouping, schedule, comparability and allowed input/loader scope must be established and frozen before launch. One training product per arm tests the fixed products and does not estimate training-run variability.

## Prospective exploratory decision rule (proposed, not yet frozen)

For each continuation X versus P0 record wins W, losses L and D=W-L, the complete permitted paired 2×2 counts, point differences and suitable uncertainty descriptions without implying independent inference on a selected panel. Consider a further bounded investment only when D >= ceil(N/50) and L <= floor(N/50). Consider C4 a development signal for an incremental weighted recipe only when C4 meets that rule and its paired net gain over C1 is at least one. These are resource-allocation preferences, not significance, equivalence or safety criteria; they must be frozen before outcomes. Report all planned arms, aggregate results and failure states in full; keep task-level matching and trajectories in appropriately restricted storage. Missing technical outcomes are INCOMPLETE, not task failures; do not decide using completed cases alone. Stop without automatic retry or parameter sweep on input integrity, prespecified technical, access or resource anomalies, budget breach, missing receipts or unaccounted cost.

## Bounded budget proposal

For H=50, three paired arms, at most one generation and one environment step per action and one reset per episode: when N denotes the actual episodes per arm, at most 3N episodes, 150N generations and 153N environment operations including resets. If and only if the actual frozen runtime has 8192 input and 16 output tokens per generation, token maxima are 1,228,800N input and 2,400N output; otherwise recalculate from actual binding. N=16 is arithmetic only: 48 episodes, 2,400 generations, 2,448 operations, 19,660,800 input and 38,400 output tokens under those assumptions, not a claim that 16 eligible tasks exist.

A candidate monitored allocation budget is 1.5 device-hours per training arm and 1 hour per evaluation arm, up to 6 device-hours total across a single GPU used sequentially. These are proposed stop thresholds, not forecasts or proven hardware hard limits. Include loading, failed attempts, cleanup and unknown tails, all training input/padding tokens, optimizer updates, CPU/RAM/storage and sourcing costs. Before release, freeze authorized reservations, monitored stop thresholds, counting windows and unresolved-tail handling, and capture physical counters; a prior one-action run does not predict complete episode duration or training memory. Retain full reservation and stop if cleanup or cost is unproved. Previous costs and new costs must both be recorded; no reuse of an expired or consumed one-shot clearance.

If just one separately evidenced development instance becomes safely available, a distinct optional full P0 episode may check the real execution loop and physical cost. At H50 it has at most 50 generations and 51 environment operations; a proposed 0.5 device-hour monitored threshold is separate from the 6-hour proposal. One episode is engineering/exploratory evidence, not a self-improvement effect or generalization result, and is not mandatory if an already verified multi-task path suffices.

## Additional precision from independent scientific review

The 2% rule is an absolute percentage-point investment preference, not a relative gain or statistical significance. With integer episode outcomes, ceil(N/50) captures the threshold exactly. At N=16 the net threshold is one success (6.25 points) and permitted losses are zero. It was chosen after observing historical results; the earlier 3 wins / 1 loss cannot be reclassified as meeting a preregistered historical criterion. No loss-count bound establishes an individual harm-probability guarantee.

Fix the analysis unit before execution. If multiple episodes belong to one parent, record actual episode count T separately from parent count G: budgets apply to T, while aggregation, weighting and any G-level decision rule require prior specification. Record a panel's success ceiling N minus the P0 successes; if it is below the threshold the chosen rule cannot be met on that panel, which does not prove general ineffectiveness or justify post-hoc task changes. Valid but poor actions and ordinary task failures are outcomes under the fixed termination rules, not technical exclusions. Only prespecified input, access, process or resource anomalies trigger technical stop.

If an independently comparable P0 result is reused, specify the whole reuse branch and account for any newly run episodes before launch; do not choose between old and new P0 episode-by-episode after results. If the optional single full episode is also run, add its actual cost and its separately proposed 0.5 device-hour threshold to the six-hour proposal. The total remains a monitored threshold, not an enforceable physical maximum; unresolved or overrun costs remain liabilities.
