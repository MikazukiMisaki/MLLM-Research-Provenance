## Narrow changes against frozen v1

1. **ACK short writes:** frozen v1 already used `sock.sendall` at line 112, not the single `stream.write` described in the preliminary review. It was not shown to have an ACK short-write defect. v2 uses an explicit `send` loop as a new testable design choice: it rejects zero/invalid writes and sends until the full ACK is written. The deterministic test forces every socket send to one byte while two original protocol clients complete. This demonstrates that fixture, not all possible system errors or deadlines.
2. **One-shot ledger:** if `parent-ledger.jsonl` exists without a claim, new ownership is refused without altering it; the new ledger is exclusively created after claiming. This is not kernel-enforced protection against all same-UID directory races.
3. **BaseException:** caught exceptions including synthetic `SystemExit` latch the owner failed even when the caller catches the returned error; the outstanding reservation and count are retained. Logging failure is also latched, though its physical ledger contents need offline reconciliation.
4. **Independent per-arm limits:** parent-bound A/B model-load and generation caps are one each, independent of the client `allowed` dictionary and the aggregate caps. A synthetic client that permits itself two generations is stopped on its second request.
5. **Claimed receipt lifecycle:** the full child JSONL line including newline is hashed as in the production client. Chain, owner sequence and operation-specific started/returned or started/unknown ordering are checked; unrelated ordinary journal events between start and return are permitted. Missing starts, mismatched operations and repeated earlier starts fail. These are checks of **child claims only**, not proof of a supervised process identity or actual physical work.

`python -B -m unittest -v test_bridge` reported 12 tests passed with actual exit 0; `test-output.log` and `test-receipt.json` retain evidence. The first v2 run had one failure and one error because synthetic negative cases reused the same O_EXCL child journal path and an inherited test expected the former exception class. That raw run is kept as `test-output-initial-failure.log`; fixes were confined to the test fixture, then all tests passed. `v1-to-v2.diff` gives the exact complete changed sources.
