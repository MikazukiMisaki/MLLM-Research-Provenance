## Reproducible limitations and mitigations

1. **No cross-directory duplicate prevention or append-only inventory** (`create`, lines 131–138). Synthetic probe patches only `inspect_case` with fixed fake strings, calls `create('open_at_sink', ...)` into two distinct temporary directories, and both identical fake problems are accepted. The pre-existing case is independently refused, but other case repeats are not; parent directory exclusivity is not global dedup. A coordinator-maintained append-only list of the three permitted new case identities and raw/canonical hashes, checked before any actual write, is necessary for the limited decision above. A failed/partial output is retained and recorded incomplete, not silently re-created.

2. **Supplied overlap signatures are not authenticated against traces** (`compare_overlap`, lines 103–128). A synthetic record pair with identical supplied `trace` but changed role facts and one arbitrary well-formed subpath hash receives `NO_MATCH_INCONCLUSIVE`; the code validates shape and hashes as strings rather than recomputing them. This is not a false *independence* claim because result remains INCONCLUSIVE and `independence=UNKNOWN`; however, it can miss a positive overlap when metadata is inconsistent. Independently derive signatures from trusted source-bound canonical trace/graph before using any match as an operational filter; reject or classify inconsistent metadata UNKNOWN. Tests validate same-schema matching and length checks but not trace-to-signature authenticity.

3. Fixed-role graph comparison and contiguous subpaths flag only exact matching canonical roles/operator sequences. With omitted open or extra initial navigation, shared subsequences can match, but non-contiguous matches and altered roles may not. Goal-blind initial graph match is intentionally conservative; `NO_MATCH_INCONCLUSIVE` never establishes distinct provenance, no leakage or independence. Cross-family transport adapter, reference comparisons, protected-set custody, semantic near-duplicate detection and transitive group assignment are not implemented. The same group must not be split across any later development/assessment partitions; no future assessment can be claimed without a separately reviewed procedure and independent custody.

4. No model/CUDA/real engine is called by the constructor or the reviewed fake tests. However, candidate creation alone does not check actual grammar/action uniqueness or physical solvability and cannot confer scientific or statistical evidence. It also does not provide a comprehensive runtime dependency closure or hardened sandbox. Independent review, physical budget and fail-stop protocol are required for each separately authorized CPU witness. Nothing in this review authorizes a new witness or experimental run.
