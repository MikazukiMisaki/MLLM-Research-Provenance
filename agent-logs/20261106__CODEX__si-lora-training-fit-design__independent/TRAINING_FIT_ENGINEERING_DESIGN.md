# One-window LoRA training-fit engineering check: proposal, not release

**Purpose:** determine whether the actual Qwen3-8B + frozen P0 adapter, one-example native forward/backward and one disposable LoRA optimizer update can complete under a specific shared-A40 resource envelope. The existing real probe did one 189-input/5-output-token *inference* and a `look` action; it did not build an autograd graph, retain 2,048-position activations, allocate optimizer state, backpropagate or update weights. It does not establish training fit. This design is read-only planning: no model, tokenizer, GPU, environment, protected task, trajectory or seed was accessed or run.

## Preconditions and identity

Before execution, freeze an independently reviewed exact source/runner version, the base revision, model configuration, local weight/adapter/tokenizer file identities, PEFT/Transformers/PyTorch/CUDA/optimizer versions, dtype and training settings, plus an exclusive new run ID, claim, scratch output and independent owner/child lifecycle. The source **P0 adapter and base weights are read-only**: load a private in-memory trainable LoRA instance, construct a fresh optimizer for trainable adapter tensors only, and do not write to the original adapter, baseline or production worktrees. This is an isolated implementation check; any disposable weights, optimizer state and synthetic inputs are never a research checkpoint or treatment.

The inference loader's adapter is not automatically proof of a trainable PEFT adapter. The implementation must explicitly request/verify trainability in its isolated load, prove each optimizer parameter is an intended trainable LoRA parameter, verify base parameters remain frozen and show no optimizer reference to them. Bind exact adapter-target layers, gradient-checkpointing setting, model `use_cache` behavior, attention implementation, autocast/dtype, LoRA config, optimizer type, LR, weight decay, epsilon/betas and clipping before the test; none of these values may be silently selected or tuned after seeing a result. Proposed setting: BF16 base/compute and one C4-normalized update under the already reviewed native-loss contract, subject to actual hardware support and exact implementation review. If actual training chooses checkpointing or another dtype later, this fit check does not establish that other configuration.

The previous five-shard historical scan has an aggregate failure (exit 1), and present metadata matching is not a fresh byte hash or upstream identity proof. A release decision must explicitly choose an acceptable verified model-byte/custody policy. If a full one-pass shard scan is required, it is a **separate** filesystem/CPU operation with its own time, read-byte and failure budget and no hidden repeat; its historical 16.38 GB/488 s observation is not a performance guarantee. Do not claim verified model bytes based solely on metadata. The runtime must also pin the resolved source/asset identities used in the actual process; hashes do not create independent scientific task custody.

## Synthetic input and objective

Use **no ALFWorld task, trajectory, rollout, generation or teacher**. Create a fixed, non-sensitive synthetic training fixture in the isolated scratch area, encoded as valid vocabulary IDs and attention/label tensors with exact digest and no protected content. To stress the proposed sequence ceiling, each executed example has post-tokenization tensor length exactly 2,048 with nonempty shifted supervised labels; enforce that the model's verified context limit permits it. Reserve any tokenizer load/preprocessing separately; do not misclassify it as generation. Avoid writing any user/task text or model weights into the results.

Exercise one complete optimizer window with **eight consecutive one-example forwards and eight backwards**, a single initial zero-grad, a single post-window clipping operation and a single optimizer step. A one-example forward, not an eight-example microbatch, is required. To exercise both coefficient branches using only synthetic metadata, define a synthetic distinct-record universe `M=16, K=4` and select a deterministic mixed first window containing four target-labeled and four non-target rows. Thus `alpha=16/(16+3×4)=4/7`, target weight `16/7`, other weight `4/7`; the remaining eight synthetic records need not run. This M/K is a fixture, not a real pool count or discovery. Use native shifted mean loss with ignored `-100` labels, active counts `n_i`, whole-window `A=Σn_i`, per-example backward scale `w_i n_i/A`, and **no** weighted denominator or extra division by eight. Check no active count is zero and that masks, input IDs, shapes and dtype are valid before model work. Fake-only differential tests must verify the arithmetic—including unequal lengths and a partial final window—before a real fit candidate is even considered; this single full window alone does not validate the complete training algorithm or a partial window on real hardware.

Acceptance requires: actual model and P0 adapter load returned once; exactly eight forwards and backwards returned in order; finite losses and intended gradients; frozen base remains without gradients/optimizer membership; at least one intended adapter gradient is finite and nonzero; optimizer state is created for intended LoRA parameters and one clipping/step returns; at least one intended adapter parameter changes and all inspected values remain finite; immutable original adapter/config hashes match before/after; and direct child exit, durable ledger and cleanup checks are complete. Do not report failure as a scientific negative result; OOM, timeout, nonfinite loss, invalid labels, contract discrepancy or partial optimizer mutation is a technical stop. Do not retry or resume the window; retain a started/unknown optimizer liability and a discarded scratch model. One update with dummy data is not self-improvement or an efficacy estimate.

## Provisional numeric envelope, to be independently frozen

These are conservative **proposals**, not measured fit, reservations or current authorization; they may be adjusted only by a separately reviewed resource policy before launch:

| Resource / action | Proposed ceiling or admission |
| --- | --- |
| Work identity | One fresh supervised direct-worker attempt; auto-retry 0; one GPU; do not touch/kill unrelated workloads. |
| Device admission | Two fresh samples at least 5 s apart, target exact visible A40 UUID and name, each at least **36,864 MiB free**; host available ≥32 GiB and output filesystem ≥2 GiB. Shared utilization is recorded; sharing is allowed and high utilization alone is not a prohibition. |
| Runtime stop | Stop owned process if sampled device-wide free memory <**6,144 MiB**, host available <4 GiB, known applicable cgroup headroom below independently reviewed floor, direct-worker RSS >**28 GiB**, sample gap >20 s, device identity drift or monitoring/ownership becomes unobservable. Proposed sampler cadence ≤2 s with bounded query; every stop threshold is best-effort between samples. If cgroup applicability is unknown, mark it UNKNOWN and require an explicit reviewed risk disposition rather than declaring its capacity safe. |
| Model and optimizer | ≤1 base/model bundle + ≤1 adapter attachment, ≤8 single-example forwards and ≤8 backwards, ≤1 zero-grad + ≤1 clip + ≤1 optimizer step; generation calls 0, environment construct/reset/step 0. |
| Training tokens | ≤8 × 2,048 = **16,384** sequence positions actually forwarded; count actual padded, nonpadding and shifted supervised positions separately. Fixture preprocessing/tokenizer calls and any extra model warm-up are not hidden inside this cap; declare/enforce their own maxima. |
| Time | Proposed 600 s work deadline from immediately before worker spawn through load, forwards, backwards and step, including sampling; maximum scheduled device-work interval **600/3600≈0.167 device-hours** for one device. Setup/source checks and cleanup must be measured and separately budgeted. SIGTERM/SIGKILL delivery, kernel/I/O stalls, final fsync and descendant cleanup do not have a proved hard wall bound. |
| Storage / host | Reserve ≥2 GiB free; ≤256 MiB raw logs/scratch metadata, no checkpoint output; direct-child CPU time and peak RSS monitored/limited with exact units and separately report any descendants or unobserved tail as UNKNOWN. |

These floors do not prove training fits. `torch.cuda.max_memory_allocated()` and `max_memory_reserved()` are self-reported PyTorch allocator peaks for the instrumented worker, not all native allocations or independently verified process ownership. Device-wide NVML free/used/utilization is not worker-attributed, especially when the host PID is hidden by namespaces. Collect both sets with timestamps and coverage, plus CPU RSS/cgroup applicability and direct child identity; do not present sampled maxima as continuous or prove another workload was unaffected. Set the actual training-wide device-hour and memory budget from these measurements plus an explicit tail, not from a single inferred point.

## Execution evidence and fail-stop

An independently owned supervisor must verify unchanged source/input identities and unique claim/output **before any model load**, observe two admission snapshots, retain exact argv/cwd/environment, and release a known direct child once. Record real started/returned/failed-or-unknown events for process creation, model/base/tokenizer/adapter load, each of the eight forward and backward operations, zero-grad, clipping, optimizer step, synchronization and cleanup; use append-only hash-bound events and external custody where available. A completed update is charged once, not once per nested wrapper. Save actual model/optimizer device placement, trainable parameter counts, gradient and parameter-change aggregate checks, finiteness, per-example sequence/active counts, loss summaries, allocator peaks, elapsed/CPU times and authentic exit status. Avoid saving synthetic prompt contents, weights or task records. Track prior SI-E2 started/open load, the one-action P0 inference, and CPU witnesses as separate cumulative records; selected historical campaign subtotals are not the full project total.

On mismatch, bad source, any budget crossing, loss/gradient NaN or infinity, invalid label/mask, unexpected base gradient, output write/persistence error, OOM, failed sampler, parent loss, unsafe shared-device condition or timeout: stop; use only the pidfd-bound own child for termination, never numeric-PID broad kill. Preserve preexisting and partial outputs, operation starts and observed metrics. A missing return is an open/UNKNOWN physical effect; do not repeat or resume automatically. A valid negative result is `FIT_NOT_ESTABLISHED`, not a demonstration that no setting can work. If source, telemetry or cleanup is unavailable, report `INCOMPLETE_UNKNOWN`.

**Release dependency:** build an exact frozen runner with fake-only tests of real call contracts, operation-order prefixes, counter overruns, malformed masks, optimizer isolation, partial writes, early death and resource-monitor failure; independently review its source and the separate experimental budget; obtain current resource admission and one concrete engineering release. The proposed settings are not a launch command. A successful bounded window supports only fit for the tested configuration/length/window and observed environment; it cannot prove full-epoch stability, other lengths, two-arm equality, statistical power, independent tasks or scientific improvement. No new training or experiment is authorized by this document.
