# One-action core with synthetic runtime edges

Status `SYNTHETIC_ONLY_REVIEW_PENDING`. This isolated candidate has no standalone runner or environment/model initialization and is not a scientific result, sandbox, durable journal or permission to launch. It does not modify the frozen policy or scientific repository.

For a supplied direct-environment state, the core checks a single initial goal marker, a false initial `won` value, consistency of public and underlying action lists, and the normalized task text returned by the real production extractor. It constructs one P0 request without hidden facts, calls a supplied policy once, preserves the raw output and prompt/action-map hashes in the supplied event sink, and permits a single supplied environment step only when the production selection metadata is consistent and the chosen public command has one underlying grounding. It checks the returned grounding identity and terminal-field types; an unexpected post-step state is recorded as unknown, not success. A failed selection produces no step. The event sink and supplied environment/policy are dependencies, not implemented durable or trusted boundaries.

Eight synthetic tests passed in an isolated pinned-Python subprocess, exit zero. They use the real P0 policy, production prompt/extractor/parser and the v3 guard, with fake tokenizer, model, torch and environment edges. Cases include valid action, invalid model output, ambiguous underlying command, incorrect goal/action order, initially won state, grounding mismatch after a step, a failed event write after generation, inconsistent metadata and a hidden-fact prompt sentinel. No real tokenizer, model, adapter, GPU or environment was loaded or run. The real P0 tokenizer/model/PEFT path, actual engine observation types and grounding objects, device limits and full import/native closure remain unverified.

The guard and core can be bypassed by code retaining other model or environment references, and their per-object/one-directory state is not a global no-retry control. A trusted, independently reviewed supervisor and durable event sink must enforce one run identity, provenance, full resource limits, fail-stop and uncertain-operation accounting. A callback failure after a model call or a step may leave an incomplete record even though physical work happened; it must never be treated as zero cost or retried automatically. A successful synthetic test does not establish real execution readiness, dataset independence, training yield or scientific efficacy.
