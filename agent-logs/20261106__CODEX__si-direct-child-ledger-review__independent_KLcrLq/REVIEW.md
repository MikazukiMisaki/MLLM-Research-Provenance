**Path and crash boundaries:** The independent probe confirms a parent directory symlink is followed. This is consistent with the README's explicit trusted-directory assumption, but the code does not defend against hostile path components, replacement races, or an attacker controlling those directories. `O_EXCL` only prevents the same claim name from being recreated in the same directory; it is not cross-directory, cross-ID, or distributed one-shot. Parent death or machine crash can strand the direct child or leave a started operation with unknown outcome; no parent-death signal, watchdog, handshake, durable recovery service, external anchor, or descendant cleanup is provided. This was evaluated by code inspection and is not claimed as a physical crash experiment.

Pidfd availability, reaping and wait timeouts are observed only for these fixed synthetic children and the test environment. Failure to open a pidfd is handled by bounded waiting only; a child still present after that wait is unobserved. A signal, wait, or close failure can leave cleanup uncertain. The timeout is not a hard wall for claim, fsync, process creation, cleanup or kernel stalls. Hash chains and fsync do not authenticate records or guarantee physical persistence. No GPU/resource monitor, model/training semantics, protected input or real-work release is implemented or verified.
