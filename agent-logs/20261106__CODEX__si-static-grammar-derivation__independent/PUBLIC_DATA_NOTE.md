# Public ALFWorld task availability and remaining provenance gap

The [upstream ALFWorld dataset documentation](https://github.com/alfworld/alfworld/blob/master/alfworld/data/README.md) describes 3,553 training games and 140 seen / 134 unseen validation games for its stated dataset. These are published dataset-level figures, not a verification of the files or histories available to this project; different packaged versions and filtering policies can yield different usable counts. This note did not enumerate, download, inspect, hash or open any project historical or reserved task instance, trajectory, manifest or association list.

The existence of an upstream `valid_unseen` partition is not evidence that the project's prior model, researchers, prompts or model pretraining never encountered it, nor is it proof that particular available instances are disjoint from prior project development. The visible prior 82-task panel was used for development. An upstream split would require separately documented custody, use history and a defensible assignment before it could support a fresh evaluation claim. When use history is unavailable, explicitly report that uncertainty rather than claiming independence or attempting to inspect protected assets to resolve it. A fresh self-authored generator similarly permits documented within-project construction, not proof of historical or pretraining non-overlap.

For scale only, suppose 134 genuinely independent paired units, with a prespecified discordance probability of 0.20 and an approximately zero paired difference. A normal approximation gives a 95% half-width of about 7.6 percentage points; this is neither a power calculation nor a guarantee, and it fails as an independence argument when tasks form correlated families or clusters. A conservative two-sided Hoeffding bound for differences in [-1,1] is about 23.5 percentage points for 134 independent samples. A fixed constructed set can instead report its exact finite-set paired contrast, without presenting these population intervals as established. Model/product training variance is separate.

The [official generator source](https://github.com/alfworld/alfworld/blob/master/scripts/alfworld-generate) uses the installed ALFWorld/TextWorld machinery and a task-description helper. The [upstream helper](https://github.com/alfworld/alfworld/blob/master/alfworld/agents/utils/misc.py) inserts a task description into the grammar placeholder. This supports the plausibility of the current one-task static grammar approach, not correctness of our derived grammar, task semantics, production wrapper equivalence or runtime behavior. Real compilation and bounded direct validation remain outstanding.
