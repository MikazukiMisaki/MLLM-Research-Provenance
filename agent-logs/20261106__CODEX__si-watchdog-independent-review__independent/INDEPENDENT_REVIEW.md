## Blocking interface and containment gaps

1. **Failure can look like successful supervisor termination.** In `watchdog.py:185–205`, timeout, lost control pipe, failed sample, wrong device/value and low free-memory conditions set stop reasons or enter exception handling. In `:220–222`, all of these can return status 0 when the worker is reaped and the journal functions. `test_watchdog.py:63–87` confirms this is expected even for low memory, malformed device and sampler timeout. A real controller that treats zero as successful completion would misclassify failure. The outer interface must unambiguously propagate reason and distinguish successful child completion, safety stop, technical failure, and unknown cleanup; reserve 0 for independently defined, actually complete success, not merely successful cleanup.
2. **No admission gate before worker creation.** `watchdog.py:177–192` spawns the worker before polling the control pipe or taking its first device sample. `test_watchdog.py:63–68` shows even an already-closed controller triggers worker startup first. A real worker could load a model or consume device resources before an unavailable controller or wrong/overloaded device is noticed. Establish and bind prelaunch checks and a worker start handshake, including controller liveness and telemetry, with the check-to-start race explicitly handled; live launch and per-use monitoring are separate requirements.
3. **Watchdog death, hanging and process trees are not contained.** Parent EOF is watched only by the watchdog's own loop (`:189–191`). SIGKILL, SIGSTOP, runtime crash, `fsync`/process creation blocking or a leaked writer can prevent that loop from stopping its worker. `stop_own_worker` (`:80–106`) waits only for the leader and explicitly marks descendants UNKNOWN, so a leader exiting after TERM does not prove all processes have ended. Identity check followed by `killpg` (`:88–92`, `:99–103`) is non-atomic; group reuse, descendant escape or namespace ambiguity preclude a general no-mis-signal proof. A real design needs independently supervised, bounded containment with safely identified owned processes, robust supervisor-death behavior, and verification of descendants/cleanup. Do not signal an unrelated shared-GPU process or claim unknown tails ended.
4. **The stated monotonic deadline is not a strict wall-clock cap.** The deadline is initialized only after worker creation, identity reads and event fsync (`:177–184`). It is checked at the top of the loop (`:187`), not during a sampler's initial timeout and subsequent kill/communicate timeout (`:117–144`), journal fsync or cleanup wait (`:94–105`). Any blocking operation or scheduler delay can overrun it; child cleanup can itself take additional time and can remain unknown. An outer, independently enforced deadline and budget for stop latency/in-flight calls are necessary, without claiming arbitrary OS stalls can always be bounded.

## Device and evidence limits

`parse_sample` (`:36–48`) enforces exactly one row, the expected A40 name, canonicalized UUID, integer metrics and a one-MiB arithmetic tolerance. These are useful fake-input checks; actual telemetry collection is absent (`:117–155` is explicitly fake), and the fixed fake 24,576-MiB free threshold (`:198`) is not measured model-fit evidence. GPU utilization is parsed but not used as a stop trigger. A shared device can change between check and allocation, and device-wide free/used cannot prove process ownership, realized CUDA placement or remaining future capacity. No host RAM, device placement, physical call/token budget, or production input binding is monitored.

Bad or inaccessible `/proc` identity prevents signaling (`:88–89`), which avoids deliberately targeting an unknown process but leaves cleanup and resource usage unresolved. The PPID/starttick/UID/PGID tuple describes the visible namespace and may fail after reparenting; it does not establish a host-side GPU PID match. The candidate correctly labels escaped descendants and effects UNKNOWN, and preserves timeout fragments rather than concatenating them. The local event/summary files do not provide an independent immutable anchor or guarantee durability after common-filesystem failure (`:203–219`).

No model, CUDA, real GPU telemetry, environment, real research worker or historical/reserved task data was accessed in this review. All listed blocking points concern promotion of this fake candidate to a real supervisor, not an assertion that a real run has already occurred.
