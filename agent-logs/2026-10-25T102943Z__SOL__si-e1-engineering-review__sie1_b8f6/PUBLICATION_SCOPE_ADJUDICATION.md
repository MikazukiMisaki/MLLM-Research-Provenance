# SI-E1 provenance publication ruling

The scientific repository must not receive server-specific paths, credentials, weights, adapters, cache or dataset contents. The separate research-notes provenance repository requires actual worktree/input/module paths, command argv, exit receipts and hashes under AGENT_TASK_RECORD_PROTOCOL.md. These are different repository scopes.

Luna's frozen inventory conservatively labels several original receipts, RECORD, input bindings and helper files LOCAL_ONLY solely because they contain local paths. This is an author's publication proposal, not a human prohibition. The coordinator may include those unmodified provenance-safe original files after a targeted secret/content/size review. Preserve the author's inventory as written; this ruling explains any broader coordinator selection without changing her bytes or claiming that she published them.

Small authentic captured stdout/stderr named `.bin` are text process evidence, not model binaries. If included, stage only explicitly enumerated exact paths after inspecting content, sizes and hashes; do not force-add wildcard bins or directories. Full prompts, training rows/token arrays, weights/cache files and unrelated historical untracked fixtures remain excluded. Author inventories may bind local-only fixture trees that are not remotely published; the coordinator rolling inventory binds the actual published set.

Only the three unique SI-E1 directories, their own INDEX rows and rolling root inventory may be included. No changes to prior records, scientific trees or another agent's files are authorized by this publication ruling. No collection, model/environment, training, evaluation, preflight or runtime release follows from publication.
