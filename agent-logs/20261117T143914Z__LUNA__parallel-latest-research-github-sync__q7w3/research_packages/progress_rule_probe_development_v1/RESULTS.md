# 进度规则单步探针：完成调用，但正式动作全部格式无效

## 事前规定的结果

按照[固定方案](PROTOCOL.md)，本批完成四个人工情境 × 两个子目标 × 两种契约，共 **16 次模型生成**；进程退出 0，事件中有 16 个准备、启动、原始结果和分类以及完成事件。没有调用 ALFWorld 或执行动作。

**16/16 个输出都带有方括号，例如 `[A000]`；预设解析器只接受裸编号，因此 16/16 都是格式无效，0/16 是有效动作选择。** 两个子目标条件下各有 4 个契约配对，按预先定义的有效动作标准均不可比较。不能由这次正式结果计算进度规则遵循率、有效动作变化率、预算内可达率或任务成功率。不能移除方括号后将这些输出追认成已执行动作。

这里的预设解析器是本探针自定义的研究规则，先去除解码文本首尾空白；它不是冻结 H4 基线解析器的完整模拟。事后同机将输出 token 未去空白地解码，16/16 文本均没有首尾空白变化且仍为方括号形式。冻结 H4 的 `Action-ID:` 前缀要求与当前两阶段裸编号解析器的区别详见[接口澄清](INTERFACE_SCOPE.md)；该核查没有调用实际 baseline 或两阶段 parser。

这个结果也使原拟定的机制问题没有得到有效动作层面的答案；它不是证据表明两种契约的有效行为等价。四个情境只有三种基本结构，紧／宽预算共享状态结构；均为虚构开发题面，不是留出集。

## 事后对原始字符串的限定描述

模型输出和候选行均使用方括号，但这只是同时出现的事实，未进行有无方括号或提示措辞的对照，不能断言其造成格式无效。为保留原始输出中的可检查信息，研究者在看过结果后新增 [文本描述脚本](analyze_bracketed_exploratory.py)：它只检查每个无效字符串是否恰好是包在方括号里的已列编号，**不改变原始解析结果，也没有执行对应动作**。

在这项事后描述中，16/16 个无效字符串都恰为单个有映射的方括号编号，且其内部编号对应提示中指定的即时子目标；同一情境、同一子目标的两种契约下，8/8 对的方括号编号相同。按作者指定的三个可判断情境，`progress` 契约下相容指令的三个字符串所指编号均对应作者期望动作，而另一指令的三个字符串均指向作者列出的非期望动作；未知情境不计进这一标签分母。

这些只是**不符合预设输出格式的字符串**所包含的编号信息；编号到动作文本的事后对应关系不代表有效解析、模型意图或已执行行为。这项描述属于结果已知后的探索，不能称为事前主要分析或独立确认。可能的解释包括从即时子目标文字匹配或复制候选行，而非规划后选择服从；子目标位置和标题显著性也可能产生影响，但这里没有控制这些因素，不能确定原因。各题两个不同子目标对应的编号都随之改变，因此单一固定编号也不能单独描述所有输出。结果不能证明模型理解、忽略了特定规则，或说明单个措辞、编号／位置、训练来源导致了什么。未知情境里先拿 A 在两种未观察状态中均存在完成路径；“必要性未知”不等于没有稳健选择。

格式合规在此批为 0/16，不是环境任务成功率为零，也不证明模型在其他提示中无法生成裸编号。无有效配对的语义指标保持不可估计。Astra 独立只读审阅了上述解释并提出这些措辞与替代解释；它没有复算日志或认证模型身份和调用。

## 成本与可复核性

16 次调用共记录 **5,920 输入 tokens、96 输出 tokens**（含 EOS），单次最长约 **0.629 秒**。程序内部开始至 `complete` 约 **13.602 秒**；进程自报用户 CPU **10.453 秒**、系统 CPU **5.648 秒**。离散整卡显存样本最高 **16,256 MiB**，不是峰值或设备独占证明；人工、系统 I/O 和其他进程成本未完整计量。环境为 Python 3.10.20、PyTorch 2.6.0+cu124、Transformers 4.56.2；实际权重和物理调用仍依赖本地配置、主机及记录可信性，未独立认证。
