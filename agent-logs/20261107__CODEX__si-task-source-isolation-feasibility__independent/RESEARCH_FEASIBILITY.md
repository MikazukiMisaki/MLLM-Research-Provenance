# Same-environment task sourcing and confirmation feasibility

**Recommendation.** A prospective, independently custodied, self-authored task pool using the already installed ALFWorld symbolic domain and TextWorld PDDL backend is the most concrete route available without opening protected assets. It can support a *conditional, newly generated same-environment* comparison if generator, disjoint family splits, custody, policy selection and budget are frozen first. It is not the official ALFWorld held-out benchmark, not embodied transfer, and does not establish historical or model-pretraining non-overlap. No currently identified public source is shown to be independently unused in this project. The existing four cases are already exposed development examples and cannot enter the confirmation pool.

This investigation used only public project documentation, installed package metadata and two already public domain/grammar files. It did not open, enumerate, download or identify any protected test tasks; no model, parser, environment or GPU ran. All recommendations are a design, not an authorization or a claim of available confirmed independent data.

## Source, version and rights

* The [official ALFWorld repository](https://github.com/alfworld/alfworld/blob/master/README.md) describes TextWorld/PDDL games aligned to ALFRED, with ALFWorld and TextWorld code under MIT and Fast Downward under GPLv3. [ALFWorld 0.4.2](https://pypi.org/project/alfworld/0.4.2/) is an official package release. Locally installed distribution metadata reports ALFWorld 0.4.2, TextWorld 1.7.0; Fast Downward standalone distribution metadata was unavailable. These version labels alone do not establish package provenance or identical compiled dependencies.
* The local public `alfred.pddl` SHA256 is `f1473041ed01da514de1f87adfd7ef0804862361f83ccf63c75e43633b0eb280`; public `alfred.twl2` SHA256 is `c5b22f0f73309a7fd7c8e5b71de42ad4803b60766ab4a51cc2feb34162be036b`. A future study should pin the complete actual runtime/compiled library and dependency graph as well, not infer reproducibility from these two hashes.
* The [official ALFWorld generator](https://github.com/alfworld/alfworld/blob/master/scripts/alfworld-generate) traverses existing ALFRED trajectory metadata and reads an existing initial PDDL or copies an existing game; its optional seed influences generated text choices. Therefore invoking it or changing its seed does **not** independently establish a newly sampled task population or lack of overlap. We did not enumerate its data. Existing public train/validation archives are candidate sources only if a separate, lawful and authorized provenance audit proves access and historical non-use; that proof is currently absent. [Official ALFRED data documentation](https://github.com/askforalfred/alfred/blob/master/data/README.md) describes the data; repository code licensing must not be assumed to settle all data, annotation, pretrained-model and downstream redistribution rights. Check each exact asset's terms before use.
* [TextWorld's official project](https://github.com/microsoft/TextWorld) documents generating games and lists component-specific licenses. Generic TextWorld-generated games are not automatically equivalent to the ALFWorld PDDL task distribution or current agent wrapper. The proposal here is instead to generate explicitly specified PDDL problems/grammar under the same pinned ALFWorld symbolic interface, subject to a separate compatibility audit. Code MIT notices and GPLv3 obligations when distributing applicable components must be respected. Do not infer a legal opinion about third-party datasets or model weights from an MIT code license.

## A testable isolation design

1. Freeze a bounded typed task grammar over public action schemas, a semantic canonicalization algorithm and version, generator source hash, candidate population, randomized sampling/split procedure, rejection/solvability rules and separate action bounds before generating or inspecting the confirmation instances. Construct tasks without copying any protected examples. Generation alone is not evidence of solvability or distinctness. Planner/witness access stays with a blinded curator, never model-facing input. The recent D conditional-effect / exposed-state discrepancy blocks unqualified assumptions that a source-level PDDL witness predicts actual runtime behavior.
2. Assign **canonical semantic families** before outcome-dependent selection: include role-normalized typed initial state, goal predicates, action dependencies, object/hand constraints, causal graph, and known derived-parent lineage, not just filenames, instance seed, hashes or object renaming. Keep all variants/parents in the same split. Run collision/isomorphism checks over the restricted supported grammar and reject ambiguous or uncanonicalizable candidates as UNKNOWN; such a bounded checker is not a general semantic-equivalence proof. Stratify and randomly assign eligible families to development versus confirmation before releasing instances. This enables a prospective split across the defined generator population; it does not prove independence from unknown historical data.
3. A separate custodian should generate/validate the confirmation set in a sealed environment, freeze complete file/content and semantic-family manifests, count commitments, generator/version and filter logs, then disclose only aggregate eligibility/collision results and commitments. Conceal task content, trajectories, walkthroughs and instance identifiers from developers until the chosen policy, hyperparameters, prompts, analysis and stopping rules are frozen. No per-case selection/tuning after outcomes. Training examples, acquisition, hyperparameter search, negative examples, prompts and parser diagnostics must be exclusively development; confirmation task data must never be used for any of them. Keep immutable access logs. If a valid unseen custodian or enough independent families do not exist, halt confirmatory claims and report exploration.
4. Compare the new set against **permitted, complete, provenance-documented** prior development/training signatures under a predeclared procedure; do not inspect or enumerate protected tasks or identities to fill gaps. An authorized independent data steward could, if separately permitted, perform private overlap checks and disclose only aggregate pass/fail without contents, but that permission and capability are not established here. Any uncheckable lineage remains UNKNOWN, and do not label a task globally fresh or uncontaminated. A hash proves byte identity, not semantic or statistical independence. Public release before evaluation can itself contaminate use; retain confidentiality through freeze.
5. Predeclare comparable paired episodes on the same frozen task set, initial state, action schema, horizon and decoding; randomize or counterbalance evaluation order and commit failure/UNKNOWN accounting. Aggregate at the independent sampled family level or use a predeclared cluster-aware method; repeated paraphrases/seeds in a family do not increase independent sample size. The data warrant a conclusion about the sampled self-authored symbolic task distribution only. Fresh trained-policy seeds measure a different source of variability and cannot replace fresh task families.

## Precision and resource implications

Illustrative two-sided 95% normal/Wilson calculations, assuming independent sampled units and no filtering after outcomes, are **design illustrations, not achieved precision**. At n=100 independent tasks, a single success rate near 50% has a Wilson half-width about 9.62 percentage points; at n=400 it is about 4.88 points. A paired success-rate *difference* has worst-case normal half-width about 19.6 points at n=100 or 9.8 at n=400. If the (unknown) paired discordance fraction were 20%, illustrative half-widths are about 8.77 and 4.38 points, respectively. Family clustering, small discordance counts, adaptivity and missing cases can worsen these approximations; use an appropriate exact/score or cluster-aware prespecified interval.

A 5 percentage point improvement has rough two-sided alpha=.05, 80% power requirements of ~621 paired independent units if discordance q=.20, or ~1,562 if q=.50, using variance `(q−delta²)/n` and normal approximation. Real power depends on discordance, outcome direction, exact test and clusters; a 5.56-point oracle headroom observed elsewhere is an upper bound in that setting, not an assumed achievable effect in this experiment. The available four development cases are nowhere near enough for such a claim. Before committing resources, set a practically meaningful effect, interval target, maximum sample size and acceptance/stop conditions, then simulate the exact planned test and cluster distribution.

Budget must separately include generation/validation of all candidate tasks including rejects, pilot, acquisition and replay, training, all checkpoint/seed selection, confirmation for both policies, first-attempt failures, offline analysis, parser/compiler/descendant work, telemetry and cleanup. Illustrative H=50, 100 tasks, two policies, one actor generation per step gives an upper bound of 10,000 actor generations, 10,000 step starts and 200 initial resets **for confirmation alone**; if each episode permits up to R=5 two-generation interventions, add up to 2,000 recovery generations and any replay/reset/step costs under separate explicit caps. Real implementation must account for every additional call or replay, real token limits, actual measured GPU/CPU hours, storage and cumulative prior costs; no evidence here establishes actual throughput, device fit or a complete monetary budget. Repeated model seeds multiply paired evaluation work. There is no confirmatory launch until exact resource caps and sufficient task-family supply are established.

The next authorized research step is thus a generator and custody design review with bounded synthetic tests, followed by a small development-only runtime compatibility check and a cost measurement under a separately reviewed budget. It should explicitly stop on unsolved tasks, leaked plans, uncertain isolation, scientific contract mismatch or unbounded resources; no confirmation-set access or model experiment follows merely from this memo.
