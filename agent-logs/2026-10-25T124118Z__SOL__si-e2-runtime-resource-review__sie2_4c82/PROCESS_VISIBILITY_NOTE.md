# Resource visibility limitation

Root's tool execution context and Luna's native execution-host context see the same physical A40 UUID GPU-b08bc603-ebdb-787d-b5b6-ec796ea3022a. At 2026-10-25T12:47Z root saw a container-style PID1 entrypoint and could not resolve Luna-observed graphics PID5364; root nvidia-smi showed14MiB use and no process rows. Luna also could not resolve that PID. Later root read-only proc metadata showed Docker cgroups and one namespace-local NSpid. Whether NVIDIA's observed graphics PID is outside the visible namespace is unresolved; distinct root/Luna namespaces are not established. This is not proof that Luna's graphics observation is false or that GPU ownership is exclusive.

Luna must capture the actual execution-host process/ownership evidence. Root's initial read-only snapshot provides independent hardware metadata only. A known small persistent graphics process can be recorded as shared baseline in a later bounded engineering release, with no process termination or exclusivity claim. Foreign compute is a stop condition. A later authorized worker should create/check its single CUDA context and prove its own visible NVIDIA PID before full8B allocation; inability to resolve ownership is an honest cheap stop, not permission to ignore unknown processes. No release has been issued at the time of this note.
