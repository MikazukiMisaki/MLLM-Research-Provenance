# Four-pair prospective budget arithmetic: isolated candidate

`budget_contract.validate_budget` replaces the earlier insufficient `history + proposed <= ceiling` check and is wired into the copied static adapter. Both remain non-executing research candidates. This directory does not modify the earlier adapter or any scientific worktree or evidence. It does not start worker processes or access actual task/product/model/environment/GPU data. No experiment is authorized.

The proposed maximum must exactly include generation 400, step 400, reset/model-load/env-construct/env-init 8 each, materialization 4, input tokens 1,638,400 and output tokens 6,400. The separate `environment_operations=408` upper bound counts the 400 steps plus 8 resets; construction and initialization have distinct counters. The code conservatively reserves the full 4096 input + 16 output bound for each proposed generation. These are candidate forward bounds, not evidence of available funds or a reissuance of an old budget.

Each resource is represented separately in `known_completed.amounts`, `unknown_reserved.amounts`, `new_limits` and `combined_ceiling`; each historical entry also requires a SHA256 ledger claim. Unknown reservation fields cannot be omitted, even when their claimed value is zero. Unknown generation reservations require the full 4096 + 16 token allowance per unresolved generation. Component arithmetic enforces known + unknown + prospective <= total ceiling. Environment operation totals must include their reset and step components. A consistent result is always `BUDGET_INCOMPLETE`, with authorization false: training, device, time and I/O are explicitly `NOT_MODELED`.

The ledger digest and amounts are **claims**, not independently authenticated here. The code cannot establish that a supplied count includes every previous run, that completed and unknown entries do not overlap, or that their owner uses identical accounting semantics; a caller able to lie can submit zero unknown amounts. Verification against the actual append-only ledger and trusted snapshots, all-resource budgets, correct admissibility and independent review remain necessary. A purported all-zero new budget, any individual shortfall, an absent unknown component or omitted unknown-token reservation, and any excessive total are rejected; none of this implies the historic batch's allowance resets or authorizes a new run.
