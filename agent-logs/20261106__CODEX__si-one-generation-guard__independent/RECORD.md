# One-generation guard: synthetic policy integration candidate

Status `SYNTHETIC_POLICY_EDGE_ONLY`; independent exact-byte review pending. This is not a runnable model probe, a supervisor, a durable ledger or a scientific result. No actual tokenizer, model, adapter, GPU or environment was loaded or called. Project source was not modified.

The candidate `guard.py` accepts a model-like object and forwards a single call unchanged after checking the actual `input_ids` batch shape and length, greedy setting and requested new-token limit. It records start through an injected callback before the model edge, checks the returned sequence shape and generated-token count, records return or failure, and forbids a second call on that object. The proposed 4,096 input / 64 output values are engineering guards, not evidence of the P0 model's context limit or original experimental protocol.

Eight tests passed in an isolated pinned-Python subprocess, exit zero. Three exercise the real `SFTP0QwenPolicy.act`, real prompt and real selection parser with synthetic tokenizer/model/torch edges. They verify that the actual tokenized fake input passes through the guard, an over-limit input causes zero fake model calls, a valid selected ID maps to the intended command, a fabricated invalid ID remains invalid and a second call is refused. The remaining tests cover malformed shapes, non-greedy/oversize parameters, model failure, output-count mismatch and failure of the start callback. `stderr.log` is the original test-run output, SHA256 `f9c04afca182facea533e1a82e67dacd18610dc20955b8e0e3f6dd7c91d6020e`; the authentic subprocess receipt is retained locally with machine-specific paths, SHA256 `807689055f4c62c861c9e4ea4fe634b9c2b1312f7ae7dbe231a24504d6f888f0`. Ten selected code inputs matched before/after; this is not a complete import or runtime closure.

Candidate SHA256: guard `a65a045ed722621a064b313d0629ee1976cf2b058a9ea51d9815b5c1213c8419`; unit tests `de61520d6e5401671f6c50dbc8f651a71a5f8328dd42fd6672d772cb6747bc50`; policy integration tests `b2e99b5c6ccfb7c550fb6fda4862b483961c67db381134d20ef76f95b8336232`.

The fake backend does not exercise real `QwenPolicy._load`, tokenizer encoding, LoRA attachment, CUDA, production logits or resource accounting. The guard can be bypassed unless a reviewed runner binds the actual loaded P0 policy model to it; its one-shot state is only in memory and cannot enforce no restart across processes. The callback is not a durable append-only ledger. A callback error after generation starts or returns leaves completion/cost uncertain; that uncertainty must be retained. Post-return shape validation detects an overrun only after the model has already run. The guard does not reserve memory, enforce device-hours or prevent a model/runtime from ignoring requested limits, nor establish a shared-GPU ownership boundary. The production model, adapter and exact runtime identities, worker/supervisor, access restrictions and full budget remain to be bound and independently reviewed before any real call.
