# Static adapter contract (unreleased)

`STATIC_PAIR_ADAPTER_V1` is an in-memory review object, not a runnable config and not authorization. `validate_plan(plan, frozen_product_bytes, product_digest)` needs an independently authenticated product-record digest; product JSON has `base_path`, `base_tree_sha256`, and `products` containing exactly `P0`/`CANDIDATE`, each with `adapter_path` and `adapter_tree_sha256`. Only declarations and record bytes are compared; no product file or tree is read. Caller supplies and must independently authenticate the expected digest.

Other plan keys used: `cases` (exactly four unique case names, counterbalanced P0/CANDIDATE ordering, nonempty `public_goal`, and `input_sha256` claims); integer `env_seed`; exact `limits` in `static_adapter.LIMITS`; and `budget` with `historical_ledger_sha256`, `historical_used`, `prospective_ceiling`, `proposed_additional`. Each last three budget mapping has integer `generation`, `environment_operations` (including reset), and `materialize`. The ledger claim must be nonzero and each historical + additional must fit the proposed ceiling; these are declarations only, not audited cost or new budget. This adapter does not assume the old materialization allowance is replenished.

`draft_arm_config` additionally consumes the frozen manifest bytes and SHA, case/arm and previous public reset claim, lexical absolute output/input/pair/code paths, code claims, and runtime declarations. It returns the held worker's in-memory config shape and canonical digest, never a file or command. Manifest bytes must match their digest, have `FIXED_PRODUCT_FOUR_PAIR_DEV_V1`, matching cases/seed/limits and horizon 50; the draft enforces code digest claims for each pinned candidate file. First arm requires no previous reset; second requires a dict. Every path remains a claim and will need independent no-follow binding, file identity checks, safe creation and runtime rechecks. `expected_eos=[151645,151643]`, `expected_pad=151643` are declarations and actual model settings have not been observed here.

`check_source_contract` hashes the exact v4 worker, arm stage, episode, StageBudgetChannel, owner, fake scheduler and cleanup source bytes; it checks basic AST interface shape and unconditional initial raise in worker main. It does not execute imports. `launch()` unconditionally raises RESEARCH_HOLD. The existing candidate scheduler is `scheduler_synthetic.py`, which launches a fixed fake worker; there is currently NO production parent scheduler and NO actual worker launch bridge.
