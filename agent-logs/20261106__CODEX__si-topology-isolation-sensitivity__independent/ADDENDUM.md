# Constructed topology split: near-duplicate sensitivity

This addendum extends the previously published topology design SHA256 `690eb501f8f7c816c0c56dfcf1d1d1354fc303a98ae22bd81ae7e92c1f30e7ef`. It is a mathematical design observation, not an engine run or study result.

The twelve proposed symbolic configurations form the Cartesian product of binary source state, binary destination state, and distractor counts 0, 1 and 2. If a prespecified near-duplicate relation links any pair differing by one source/destination open-state flip or addition/removal of one distractor, all twelve vertices are connected by paths in that graph. Connected-component isolation would put them into one component, making the proposed 6/6 component split impossible. This is a conditional example, not a claim that this particular near-duplicate definition is mandatory or already frozen. The previously proposed six-per-partition factor balance is only a tuple allocation until a scientifically justified grouping rule and its resulting components are frozen and validated before any model outcome is seen.

Twelve distinct role-labelled toy graph signatures establish only exact syntactic differences under that representation; they do not prove independent tasks, authentic benchmark disjointness, valid executable examples or held-out evaluation. A different grouping might support a narrower transfer claim, but cannot honestly be described as the same strict near-duplicate isolation. If strict grouping collapses the small grid, either obtain or predeclare more meaningfully varied task structures within the same domain, revise the estimand and explicitly report weaker isolation, or treat the exercise solely as engineering without a comparative efficacy claim. Actual grammar, goal and production adapter compatibility, full costs, valid task counts and statistical precision remain open.
