## Independently reproduced defects

1. **Partial sampled bytes lost after repeated timeout.** `snapshot_once` catches a first TimeoutExpired, kills, then calls communicate again (`monitor.py:59-67`); if later communicate also times out, `raw`/`err` stay empty even when the exceptions carry already observed partial bytes. A mocked Popen that returned TimeoutExpired on all communicates, with `output=b'partial-observed'` and `stderr=b'partial-error'`, produced fail status 1, timeout true, rc null and empty saved stdout/stderr. It correctly fails closed on validation, but its byte-exact evidence claim only holds for returned communicate values, not necessarily observed partial output. A robust implementation should preserve bounded partial bytes where available without presenting them as a complete sample, avoid unsafe concatenation/duplication, and explicitly record unknown process state on unconfirmed exit.

2. **Journal failure can bypass cleanup recording and explicit stop.** `fake_monitor` exception handler calls `journal` again before attempting `worker.stop` (`:151-154`). When journal is mocked to raise OSError after worker creation, the OSError escapes, the event file is empty and no cleanup receipt is emitted; `finally` closes stdin. The fixed fake worker exits on stdin EOF; this reviewer explicitly waited for that own fake child, observing exit 0. This behavior does not guarantee cleanup of a production worker. Cleanup must be attempted independently of a failing journal, durable outcomes must distinguish unrecordable/unknown, and the design must account for supervisor death and uninterruptible children. `OwnedWorker.__init__` also closes stdin but does not wait if identity binding fails (`:109-113`).

3. **Model-name check is absent.** `parse_sample` checks only that the name is nonempty (`:45`). Fake row `OTHER MODEL` with the expected UUID and otherwise valid metrics was accepted. This does not invalidate the stored A40 row, but future admission must either enforce the intended hardware model or explicitly justify UUID-only policy and independently verify expected runtime/device capabilities.

## Required real integration conditions

- `snapshot_once` is a single query, not periodic monitoring. The 24,576 MiB fake admission floor is uncalibrated; a real experiment needs a documented conservative fit/margin budget, fresh admission immediately before use, continuous bounded sampling and independent watchdog. Shared GPU use is allowed; device-wide measurements cannot establish exclusive ownership, reserve free memory, or identify another tenant's process. Sudden concurrent allocations remain possible.
- `OwnedWorker` is limited to a specific fake child and its signal checks (`:114-126`) retain a check-to-killpg race and do not establish safe whole-tree containment. Use a reviewed owned identity and containment mechanism, preserve direct-child authentic wait/exit status, do not signal unrelated processes, and treat unreaped/escaped/namespace-unmapped descendants as UNKNOWN. PID namespace/NVML PID equality is not assumed.
- `cgroup_read` deliberately reports unverified mount mapping and unknown ancestor headroom; v1/inaccessible paths are unknown. Literal immediate limits do not prove effective limits. Any real budget must include ancestor constraints, shared members and memory attribution limitations.
- Real monitoring needs durable events, explicit physical operation start/return/unknown accounting, external event anchors, watchdog/sampler death handling, bounded I/O and a no-retry launch identity across process crashes. No local receipt or single SHA provides an external anchor by itself. Preserve model, adapter, tokenizer, task, runtime and exact code bindings; enforce scope and costs rather than relying on the synthetic prototype.

## Minimal next step

Fix the three demonstrated boundary issues, then integrate a separate default-disabled real adapter/supervisor with truthful UNKNOWN states and focused tests for timeout, failing writes, real child exit and safe cleanup. Independently inspect exact final bytes and current device/host budgets before any controlled model call. Synthetic results remain software verification only.
