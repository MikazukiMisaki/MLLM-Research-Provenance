## Adapter-format compatibility

The existing fictional atomic callback only accepts names beginning `fictional.` and writes a scope-marked single `fictional.safetensors`, not a PEFT `save_pretrained` adapter directory. The wrapper extracts the 14 PEFT adapter tensors with `get_peft_model_state_dict`, prefixes their keys, and passes those fake CPU tensors to the unchanged callback. It then reads them through `safe_open`, strips the prefix, inserts them with PEFT `set_peft_model_state_dict` into an identically configured LoRA model attached to a deep copy of the *same initial random base*, and checks all 14 adapter tensors match; eval logits on a fake token sequence agree with maximum absolute difference 0.0 in this run. This is a minimal toy mapping, **not a production LoRA format, PEFT adapter export, or proof of real checkpoint compatibility**.

The unchanged callback's historical metadata scope string is `FICTIONAL_CPU_ONLY_NOT_LORA_NOT_SCIENCE`; the saved values in this integration are in fact *toy PEFT LoRA tensors* under `fictional.` names. We preserve that original scope label as bytes and explicitly disclose the mismatch; it must not be read as a claim about tensor architecture or a production LoRA adapter. The PEFT library emitted a warning that no model configuration file was found and assumed vocabulary unchanged; the full warning is retained in `synthetic_evidence/normal/child.stderr`.
