Status: DESIGN REVIEW ONLY. No production implementation, authorization, preflight, live training, or independent scientific result is asserted by this record.

## Findings

1. **C4 is not connected to the production continuation path.** `scripts/run_si_continuation.py:39–60` invokes `train_from_p0`; `src/self_improvement/continuation/training.py:157–169` carries sample and group metadata through encoding but does not preserve family/weight metadata, and `:363–388` computes the historical unweighted active-token update. It never calls the C1/C4 loss helper.
2. **The existing frozen B/C contract does not authorize C1/C4.** `training.py:75–154` recognizes `SI_CONTINUATION_DATA_V1` only for B/C and binds existing schedule and data review; `:227–233` compares B/C initial conditions. `src/self_improvement/continuation/gate.py:42–48` requires exactly B/C runtime policies; `:51–85` binds the historical dose, LR, order, and family counts; `:95–96`, `:118–136`, and `:159–163` enforce historical authorization, pair review, preflight and clearance. Adding arm names to an old enum would not confer the old evidence or protocol on a new treatment. Retain historical semantics and regression evidence; use distinct versioned schemas and a separately reviewed gate and entry point.
3. **The weighted functions and tests are synthetic evidence only.** `weighted_objective_v1.py:31–82` currently requires 312 label records, 1,248 exposures, four exposures per sample, eight target samples from two parent groups, and batch size one. These are code-level candidate assumptions, not proof that data exists, is isolated, or that a real protocol is approved. `:101–122` uses C1 weight 1; C4 target weight 26/7 and other-family weight 13/14, divided by the unweighted total active shifted labels in an optimizer update. The sample-weight sum is 312 for the stated 8/304 mix, but that does not prove token-level normalization with unequal label lengths or equal gradient scale for each update.
4. `weighted_full_synthetic_v1.py:99–115` compares a fabricated C1 candidate to the historical trainer; `:118–215` implements an isolated synthetic candidate loop, not a production trainer. `tests/test_si_weighted_full_synthetic_v1.py:21–41` checks C1 parity on a tiny CPU fixture and `:73–124` compares synthetic C4 updates against a separately expressed token-sum oracle. No real Qwen weights, production GPU, data provenance, scientific outcome, or end-to-end production C4 path is established by those tests. `weighted_update_synthetic_v1.py:121–151` is CPU-only with an in-memory trace and must not be repurposed as a production runner without a separately designed and reviewed integration.
5. The loss helper assumes the actual model native loss is the mean of shifted, unmasked causal-label token losses (`weighted_objective_v1.py:101–106`). This assumption remains unverified for the target runtime and precision. A small random synthetic model test can test an implementation/configuration, not establish the complete real-runtime contract.

## Software-only acceptance tests

Use invented rows, synthetic labels, small CPU models and temporary output only:

- Test shifted active-label cross entropy independently from logits using sum reduction divided by the full update active-token denominator. Cover variable sequence lengths, prompt masks, EOS, single-active-token rows, mixed family and epoch-crossing accumulation windows. Reject zero-active, malformed, nonfinite and tampered cases before unsafe work.
- Compare C1 with the actual historical trainer on identical synthetic base/adapter, sample order, optimizer, seed and config: check each update's losses or loss contribution, gradients, clipping, parameters, optimizer state, LR, counts and ordered events; any discrepancy blocks parity acceptance.
- Compare C4 against a separately expressed token-sum oracle for mixed family weights, several updates, gradients, clipping, parameters and optimizer state; a non-degenerate fixture must distinguish it from C1. Exercise target and other family exposures, exact windows, and all dose and count bindings.
- With the pinned library version, use a random tiny CPU Qwen-architecture fixture, where available, to compare native scalar loss and gradients with independent shifted-token cross entropy, including masking/EOS and unequal lengths. This is model-free with respect to real weights, but it is still a synthetic model execution. Passing is limited to the tested library/configuration/device/dtype; real P0, BF16/CUDA and production runtime remain unverified. A mismatch blocks integration until the cause is resolved.
- Test new CLI, gate, supervisor and result validator end-to-end on invented inputs. Reject old B/C evidence presented as C1/C4; reject altered map, family, schedule, sample content/exposures, objective, tokenizer/runtime binding, pair binding, authorization, expiration, paths and output reuse. Exercise token/resource/time caps and interruptions before forward, during optimizer mutation and after returned step. Charge started work; do not claim rollback or save a successful adapter after incomplete execution.
- Rerun relevant frozen B/C regression tests and verify that their historical schemas, behavior and artifacts remain unchanged. All new software tests are necessary evidence for implementation review; none alone establishes input provenance, independent held-out evaluation, scientific validity or budget sufficiency.

## Decision rules

- A failed numerical comparison, stale or substituted review/authorization, data integrity mismatch, missing provenance/isolation proof, breached cap or uncertain optimizer state blocks the relevant step and requires preservation of evidence; no automatic retry.
- Synthetic implementation can proceed independently of authentic task availability, without claiming live readiness. Absence of verified independent evaluation assets prevents a confirmatory success-rate claim. A separate exploratory analysis is possible only where data usage, experimental scope and full budget are explicitly justified; exploratory results do not become independent confirmation.
- Formal two-arm execution requires an independently reviewed exact commit, genuine data and pair review, a complete budget and valid runtime checks. If real Qwen's loss differs from the shifted-token oracle, stop and resolve the contract before any weighted scientific run.
- Current review does not grant a launch or prescribe a new budget. Prior single-step inference engineering evidence is not evidence of weighted continuation training.
