# Independent audit: public-domain development PddlEnv load/reset

## Decision

**READ-ONLY ARTIFACT AUDIT: PASS with provenance and scope limitations.** The retained output and matching inspected source support one documented exposed-development PddlEnv construction/load/reset invocation that completed normally. This is an engineering observation, not an agent experiment, success-rate result, task solvability result, policy evaluation, held-out evidence, or approval for a further invocation. This audit did not invoke a model, GPU operation, environment, inference, or test, and did not modify the original evidence.

## Evidence

- The original `FILE_HASHES.sha256` lists 13 preparation files; all 13 independently rehashed correctly at audit time. It includes worker, launcher, supervisor, gate, proposal, test artifacts and all three input assets. The preserved fake-only supervisor test log reports 8 passed, exit 0; it was read, not re-executed.

It reports wall 1.2220 s, user CPU 1.072108 s, system CPU 0.126696 s, and max RSS 68044 KiB. These are supervisor's retained process resource values, not independent system-wide or aggregate child/GPU usage.
- Current native `libdownward.so` SHA256 is `306ee0e2f897c87acaaa50d09644987490a73ea0a40e7e3d6c2eedb02bba07e1`, matching the check in the inspected worker. Worker code verifies the three input hashes and the native library before importing and constructing PddlEnv. The launcher sets `CUDA_VISIBLE_DEVICES` empty and has no explicit model/GPU invocation, but no independent GPU operation trace was captured.

## Identity, uniqueness and limitations

The launcher creates `run_once` exclusively; with this directory present it cannot make a second run at the same location without altering or removing existing evidence. Its receipt states one invocation and no retry. This establishes one retained local record, **not** global proof that no other copy, directory, prior run or transient replacement existed. The proposal is explicitly a preparation-time snapshot marked NOT RELEASED; the subsequent run receipt must be interpreted separately, and no claim is made that the proposal itself authorized execution.

The original `FILE_HASHES.sha256` does not include the later run output files or invocation receipt. This audit records their current SHA256 in `AUDIT_RAW.json` and `FILE_HASHES.sha256`, but cannot retroactively prove an independently authenticated launch-time seal. The receipt is an unsigned local supervisor record, and there is no complete external event trace or cryptographic process attestation. There is no explicit `env.close()` in the worker; the direct child was reported reaped on process exit, which is not proof of exhaustive native/GPU/descendant cleanup.

This was the public domain and grammar with one already exposed synthetic development problem. No held-out task, learned policy, environment step, agent trajectory, successful task completion, solvability, or generalization is established. Six admissible initial commands do not establish a solution exists. Any next experiment requires its own protocol, input separation, resource plan, and independent authorization/review; this result grants none.
