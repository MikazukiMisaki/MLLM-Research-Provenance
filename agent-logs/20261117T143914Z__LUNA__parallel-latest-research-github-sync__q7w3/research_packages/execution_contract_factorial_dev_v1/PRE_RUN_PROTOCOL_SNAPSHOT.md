# 静态执行契约 × 子目标相容性：开发协议 V1

状态：**前瞻方案，尚未执行。** 2026-11-16；与主线 self-imitation 训练／配对评估分开。本方案不读取受保护任务、方向 2 受限窗口材料或其三份输入，不使用已关闭的 120 状态评分批次，不改冻结 baseline、联合恢复算子或生产策略；它只是虚构题面上的一次静态选择研究，不添加 selector、记忆、多轮反思或新环境。

## 问题与比较

已有研究中，固定执行契约要求模型执行即时子目标，8 个已曝光人工情境的 8 个局部冲突子目标均引导了研究者所列的冲突动作。自然问题是：**给定相同情境和相同子目标，当执行契约明确要求优先考虑整体任务时，动作是否改变；这种变化是否也影响原本相容的指令？** 研究者操纵的是两段完整指令，不把任何差异归因于单个词、隐含认知机制或模型是否“真正理解”。新契约属于另设文本处理，不构成项目冻结执行器或实际恢复系统的改进。

逐一使用已有 `research_packages/subgoal_neutral_controls_development_v1/cases.json` 的八个情境，包含六种结构；两个结构各有两个词汇变体。题面、动作映射、诊断、实际子目标、作者预定可接受动作集合和冲突动作均保持其已记录版本。它们是在研究者看过既有输出后选定的便利材料，不是新任务、独立验证或预先注册的原研究。原题目标已完成时将 look 与 inventory 视为可接受信息动作，而非任务终止；未知位置两个待查位置均可接受。阻挡场景的动作顺序有合理解释空间，即使沿用作者既有标签也须单独呈现、不能视为客观真值。

每情境进行四项单次贪心生成，2×2 同状态交叉：

| 契约 | 相容子目标 | 局部冲突子目标 |
| --- | --- | --- |
| `follow`：沿用原提示首句 `Select the one currently available action that best executes the frozen immediate subgoal.` | `follow_compatible` | `follow_conflicting` |
| `task_priority`：只把首句替换为 `Select the one currently available action that best advances the overall task goal. If the frozen immediate subgoal conflicts with the task goal or the current situation, prioritize the task goal.` | `task_priority_compatible` | `task_priority_conflicting` |

其余提示字节、选项／编号、状态、解码和模型相同；新增契约同时改变长度、语义与显著性，不能从结果归因给任一单点。即时子目标与任务状态由作者指定，不声称自然生成错误或真实 ALFWorld 可执行。历史中的 follow 结果只作探索背景；四条件在同一新批次中都重新执行，不能把旧输出当作本批实时配对。它们是这八个人工情境的重复提示，不是原 120 状态研究的重跑或分批替代。

## 预先规定的记录和分析

完整计划 8×4=32 次、每次最多 16 个新 token，输入每次不超过 1,024 token；按情境进行，每情境四条件次序采用固定轮转：F相容、F冲突、T相容、T冲突及其 4 个循环移位。轮转只平衡调用顺序，不随机化题面，不消除时间漂移。冻结实际字节和调用顺序后才可运行，不看输出改题或补样。

每次必须保留原始裸编号及解析、语义动作、候选映射、渲染提示、实际 input token IDs／摘要、模型与分词器版本及可核查身份信息、解码设置、call ID、耗时、输出 token 与 EOS。预设四种分类：作者接受集合、作者局部冲突动作、其他有效动作、格式无效／截断；未尝试和运行错误另列。若某动作同时落入两个集合，材料有误，停止，不自行指定优先级。所有标签是作者判断，并在结果中复查题面能否支持；不以未来结果回填或重新标注。

主要开发描述：针对每一子目标条件，列出两契约下各情境语义动作，报告完整 8 个预定情境中可比较数、动作不同数、接受集合内／冲突／其他／无效；尤其记录冲突条件的变化和相容条件的潜在退化。逐结构报告必要回退（清洗、阻挡）和目标已完成例，保留异议、无效、未知与缺失，不把相关题面或 32 个调用当作 32 个独立任务。可附每题四格，但不计算显著性或总体效应。接受集合内动作也不等于实际可执行或成功。

## 资源与停止

只使用此前允许的本地虚构题面模型调用路径，并在其他研究释放共享设备、身份和运行路径得到当前条件下的核实时运行；设备当前空闲的离散采样不证明独占。正式运行前固定模型与配置来源、代码和输入摘要、单次批次目录和资源控制。采用现有虚构题面试验的上限：加载前显存占用低于 8,192 MiB、利用率低于 5%，加载后和调用中显存低于 43,008 MiB；每次请求最多 120 秒，CPU/外层墙钟各 1,800 秒，日志文件最多 16 MiB。上限必须由实际运行方式施行，不能仅在文本中承诺；GPU 采样或资源记录失败、身份不一致、题面／映射不一致、超限、异常终止或日志写入失败即停止并保留已记录证据，不自动重试、补齐或迁移输出目录。记录完整、部分或未启动状态及实际成本，未完成时不汇报为完整 32 次。

事前检查只检查新开发材料和该虚构调用路径；不重复或借此绕过先前遭安全审查拒绝的评价器绑定／暴露检查。无合法且实际可执行的运行条件时，该方案留作未来工作，不声称运行通过。

## 结果可解释的边界

例如，如果相同冲突子目标下两契约选择不同，支持模型对这两段指令敏感；若不变，说明此批具体提示未观察到改变。相容条件的选择和必要回退同时报告，用于揭示可能代价，不可把人工标签当成完全客观或推断最终成功。该结果不说明真实的两阶段系统自然产生了什么子目标、不归因于先前两构型的 direct actor 失败、也不证明任务级改善。
