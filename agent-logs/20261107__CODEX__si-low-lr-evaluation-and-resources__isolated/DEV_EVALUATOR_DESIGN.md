# C-low development evaluation: interface design and access boundaries

**Design only; no model, environment, preflight, evaluation task, row-level historical result or protected input was accessed.** This note proposes two development-only alternatives. Neither is a held-out study, a source-code review, a launch gate, or evidence that the C-low training product exists. The historical fixed products achieved P0 65/82, B 68/82 and C-high 67/82 on an already exposed TRAIN panel; the accepted historical comparisons were inconclusive. C-low has no result. The candidate training protocol and its data-only audit do not themselves create a trained adapter.

## Historical contract that a new implementation must actually respect

At historical evaluator commit `8532275932dabddc498c23a2b6d9a045647542f0`, `si_transfer_eval.runtime_binding.verify_training_receipt` requires an exact-byte bound completed training result, actual supervisor exit, and manifest: result schema/status, training arm and manifest SHA, P0 and base digest, final adapter digest, source SHA and protocol SHA in the supervisor binding, `live` evidence class, authentic return code zero, cleanup established, within time, `EXIT_RECORDED`, and retry false. Full `verify_static_runtime` additionally binds training protocol bytes and dose, actual base files/tree, P0 legacy/tree hashes, current adapter bytes, dataset hashes, runtime packages, environment config/domain/grammar, isolation inputs, games/trajectory inputs, and matching real B/C train receipts and config/dose. The `gate` binds exact clean evaluator source SHA, interpreter/isolated environment, protocol, plan, schedule, manifests, analysis, independent software review, and actual bounded runtime checks. `live_gate` authenticates a separate real supervisor and worker. These are static source observations, not a claim those objects or processes are currently present.

The old `ARMS=('A','B','C')` evaluator, manifest validator, protocol validator and offline auditor all encode three arms and ordered completion. Merely omitting B, copying a B manifest, forging B/C receipts, monkey-patching the constant, or weakening the old verifier would invalidate that contract. A new one-arm evaluator should have a distinct schema and exact source revision, be independently tested/reviewed, and take the **real C-low** product and receipt once it exists. It can reuse or carefully factor the producer, environment port, causal projection, action parsing, reservation/journal and return-audit logic under a separately verified exact semantic diff; no old three-arm audit PASS should be claimed for its new schema. The historical `ProductionProducer` accepts a C arm label, but a reused internal label must be explicitly bound to the C-low digest, new run and new schema, and must never be represented as historical C-high.

Actor equivalence requires the actual frozen code and assets, not a description alone: same Qwen3 base and tokenizer/chat template, P0-initialized final adapter lineage, public-state projection and SFT-P0 action-ID map, last-four history projection, full valid-action list/order and parser; ALFWorld game/config/domain/grammar and seed; horizon 50; `max_new_tokens=16`, `do_sample=False`, thinking disabled, local-only and same dtype/device/adapter behavior. Record rendered prompt/token hashes, actual token sequence and EOS/cap, ordered action map, selected ID and resolved command, state transitions, termination and success. `ProductionProducer` source passes the stated generation arguments but may inherit additional library generation settings; a proposed implementation must capture the effective config/library versions and compare it with original evidence where available. If a required historical effective setting is unavailable, mark cross-run comparability UNKNOWN rather than assert full equivalence.

## Alternative A: the identical historical panel, conditional only

The historical fixed plan code binds a metadata schedule SHA256 `c352a0d708b910bb3703c63009aed3a800b5ba4d40f95021f3bd30db0e4823cd` and 82 ordered rows with deterministic per-index environment seeds. That code also records that 40 of the 82 selected tasks share a parent with a separate unexecuted reserve. This is a **declared parent overlap**, not evidence that reserved task content or semantics leaked, and not by itself proof that the 82 tasks are forbidden. However, the cited prior safe-source audit found no available safe identity/order projection cryptographically tied to the completed historical run, and no demonstrated process boundary that permits the 82 inputs while preventing protected reserve access. A schedule digest by itself is not proof that a prospective projection was produced from the historical executed rows or that the loader cannot discover siblings. Current same-panel execution is therefore **not ready**, not a declaration that all development research is prohibited.

A viable future route needs: an appropriately authorized independent steward or enforceable scoped service to verify original run → exact panel projection, ordered identities, seeds, game and trajectory byte hashes, original config and each historical per-task outcome/receipt; then supply only an authenticated projection and paired results under a process boundary tested to deny reserve traversal, sibling reads and unapproved outputs. Verify commitments without making protected identities or contents available to analysts; use the same panel once and no automatic retry. A file digest alone, ordinary same-account permissions, a directory basename, a synthetic projection, or a mere promise not to read reserve does not provide that proof. If this cannot be done, use Alternative B instead.

For a permitted complete 82-task execution, historical one-arm ceilings are at most 4,100 actor generations, 4,182 reset-plus-step operations, 33,587,200 input tokens, 65,600 output tokens, at most 8,192 input tokens per call and 14,400 elapsed seconds. These are historical protocol ceilings, not a newly validated campaign budget or guarantee of enforceability. Include all actual prior work, new model load/unload, input hashing before supervision, runtime/package checks, cleanup, storage and failed/open operations; independently enforce a prospective cumulative budget for the new run. GPU allocation/free-space observations and allocator limits do not establish exclusive GPU use, total physical process bounds or peak memory.

When a safe exact historical row mapping has actually been proven, join C-low outcomes one-to-one with authentic P0 and C-high outcomes by an opaque approved panel key plus the bound game/seed/contract metadata. Verify no duplicates, missing rows, substitutions or reordered mapping. A historical aggregate such as 65/82 or 67/82 is insufficient to derive paired wins/losses. Classify a complete genuine selected-action failure and horizon exhaustion as historical protocol failure, terminal positive reward as success, and truncation, infrastructure fault, unknown external return or incomplete result as UNKNOWN; stop on UNKNOWN and retain all physical costs. Do not quietly impute it as a model failure or retry. If incomplete, report the scheduled denominator, completed/unknown counts and descriptive partial results only. For n=82 and m unknown comparisons, a crude sensitivity bound for a paired difference is `[max(-1,(S-m)/82), min(1,(S+m)/82)]`, where S is the observed sum of paired low-minus-comparator differences; this is a worst-case bound, not a confidence interval. Do not select favorable tasks or present this exposed-panel comparison as held-out or as an independent replication.

## Alternative B: newly authored development set in the existing environment

Use a separately versioned, self-authored development-only specification under the existing ALFWorld PDDL/domain and production-compatible runtime. As a concrete small engineering screen, prospectively freeze up to six tasks before any new policy output, with declarative goal/initial-state rules, fixed order, matching task/runtime bytes and three actual arms P0, C-high and C-low; validate solvability with independently reviewed, separately budgeted model-free witnesses. The count six is an execution-planning limit, not a claim that six eligible tasks already exist or a sufficient statistical sample. Keep witness/solution and hidden-state files outside every model-facing input. Reject ambiguous, duplicate or invalid tasks under predeclared rules; preserve all attempts and stop rather than swap cases after model outcomes. The recent toggle-state discrepancy requires resolution or exclusion from this draft before assuming that any affected symbolic witness reflects runtime semantics.

At H50 and one generation/step per step, six tasks × three actual arms imply at most 900 generations and 918 reset-plus-step operations; at historical per-call ceilings, at most 7,372,800 input and 14,400 output tokens. This is only the episode envelope: feasibility checks, hashes, model loads, tokenization, compilation, failed work, descendant processes, GPU/device time, storage and cleanup are extra or UNKNOWN. If only two genuinely completed runnable arms are planned, the corresponding episode ceilings are 600 generations and 612 operations; the absent arm cannot be inferred. Secure actual C-low and C-high trained products, evaluate P0 directly, and bind real receipts and separate outputs. Six exposed self-authored examples are descriptive engineering evidence, not independent benchmark performance, sufficient statistical precision or proof of self-improvement. Historical/pretraining overlap and causal family independence remain unknown.

## Minimal implementation and tests before any run

1. `validate_low_training_lineage`: check the real C-low result, manifest, supervisor, source/protocol hashes, completed status, final adapter/base/P0 digests, counts and cleanup as above. Fail closed if any future input is missing, stale, synthetic or mismatched; do not require or fabricate a B **training output**. Separately enforce whichever authentic B **data-manifest** the unmodified historical training gate required for the already completed training, without replacing its evidence.
2. `validate_dev_panel_binding`: for Alternative A require independent historical execution→projection proof plus tested isolation; for B bind only freshly frozen allowed task inputs and development-only scope. Verify seed, order, game/trajectory/config and source/runtime asset hashes with no directory-wide dataset discovery or reserve access. Unknown provenance, duplicate parent or unsafe output is a hard stop. Emit public-safe aggregate counts only; any operational private per-task rows require an explicitly controlled channel.
3. `run_one_arm` plus append-only journal: adapt real public-state projection, producer and environment ports, unique per-task/unit identities, reservation before effects, returned/raw boundaries, actual/completed/token accounting, and stop/cleanup. Separate `synthetic` from real evidence. Capture source SHA, exact argv/env/runtime, baseline/tokenizer/adapter, panel/protocol/lineage hashes, supervisor and worker identities/exit. Preserve original prior runs and fresh outputs; no automated retry.
4. `audit_one_arm` independently reconstructs event-chain and external returns, per-task causal prompt/action-map/parser/state/outcome, complete schedule and counts, resource and supervisor evidence; no model/environment calls. `join_historical` runs only within the authorized safe boundary and verifies old outcome lineage and one-to-one key/seed/game joins; `summarize_development` gives all success counts, paired wins/losses and unknowns without identity leakage. Alternative B uses its own completed P0/C-high/C-low outputs; it does not import historical per-task outcomes from unrelated tasks.
5. Unit/contract tests with explicitly synthetic fixtures: reject absent/mismatched/forged supervisor, adapter, P0/base/protocol/source or data binding; reject new source without independent review; verify exact prompt, parser, action-map and decoding equivalence to historical production functions; detect generation/step/reset started-but-unknown, timeout, resource overflow, duplicate units, partial logs, incorrect tokens/EOS, and closure failures; verify no automatic retry and faithful partial costs. Test complete one-arm journal→independent auditor→one-to-one join→descriptive report, with only model/environment edges synthetic; include invalid, horizon, terminal, truncated, absent/duplicate/reordered keys and unsafe reserve-access denials. Test arm-count generalization without mutating historical three-arm fixtures or certifying synthetic output as live.
