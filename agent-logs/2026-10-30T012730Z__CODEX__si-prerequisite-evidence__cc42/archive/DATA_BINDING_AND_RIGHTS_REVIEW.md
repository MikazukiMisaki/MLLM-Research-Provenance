# Read-only ALFWorld historical archive / local data binding review

**Decision: DATASET_LINEAGE_PLAUSIBLE_BY_DIRECTORY_METADATA; COMMON_GENERATION_UNPROVEN; USAGE_TERMS_UNCONFIRMED.** We cannot conclude that the 0.2.2-only game files and local `traj_data.json` siblings were produced in the same generation run, are behaviorally compatible, or constitute independent usable research units. This review adds version and checksum evidence without selecting new tasks or inspecting candidate text/outcomes.

## Newly obtained official assets and constrained comparison

At this review the public [ALFWorld 0.2.2 release](https://github.com/alfworld/alfworld/releases/tag/0.2.2) API returned two assets also referenced in the [0.4.2 downloader source](https://github.com/alfworld/alfworld/blob/0.4.2/scripts/alfworld-download): `json_2.1.1_json.zip` (asset ID 112282473, 72,018,818 bytes, retrieved SHA-256 `25171f16e20ad7b048c47275c45b0babf3aa1cbab29cec97387922350a9844bc`) and `json_2.1.1_pddl.zip` (asset ID 112282926, 34,881,784 bytes, SHA `913942ebed06659ea0da2f8122512d98bc6add30d84961ca803132d8fbcad585`). The API returned `digest=null` for each: SHA identifies downloaded bytes, not an independently authenticated upstream checksum. Full API-derived source and timestamps are in `ASSET_RECEIPT.json`.

These two intact ZIPs were placed separately under `/tmp/si-source-join-archives-20261030/`. No archive member was opened, extracted or decompressed. `archive_local_crc_audit.py` reads only their ZIP central directories and computes CRC32, size and SHA-256 over local files in place. It confirms before/after SHA identity for both new ZIPs and the previously obtained 0.2.2 and 0.4.0 game ZIPs. Task identities and contents were not emitted. Individual local files were checked via fstat during the scan; a separate full postscan file-byte rehash was not performed.

Each archive has 7,080 matching basename members. Across all 7,080 local same-path trajectory files, and all 7,080 corresponding PDDL files, observed local size and CRC32 match the corresponding official ZIP directory size/CRC. The same holds for all 1,207 paths whose game member exists only in the checked old game ZIP. An aggregate digest of the local path/SHA inventory is retained, not the task list. This strengthens the preceding path-presence finding to *consistency with the specific downloaded official source archives' directory metadata*. CRC32 and file length are not collision-resistant and do not prove archive/local bytes match cryptographically. ZIP directory metadata is not an upstream published digest, and a collision or corrupt/forged metadata cannot be excluded. The archived compressed member bytes were not read or verified against their own stored CRC in this review.

## What pairing can and cannot establish

The official [dataset documentation](https://github.com/alfworld/alfworld/blob/aaba6870f86c5be6a08a491f32a50b906227bc3e/alfworld/data/README.md) describes sibling trajectory metadata, initial-state PDDL and TextWorld game files, with PDDL derivable from trajectory metadata and games generable from PDDL. The pinned [generation source](https://github.com/alfworld/alfworld/blob/aaba6870f86c5be6a08a491f32a50b906227bc3e/scripts/alfworld-generate) reads trajectory JSON, initial-state PDDL, domain, grammar and a random seed; it may also copy or modify existing game files. Its game object stores a domain, grammar, problem, solvability and walkthrough, not a cryptographic hash of the input trajectory. These documented relationships describe the intended data pipeline; they do **not** establish which exact input files, source commit, seed or generation event created any retrieved archive member.

The downloader's published version references the 0.2.2 JSON and PDDL assets together with a 0.4.0 game asset. Its `unzip` function skips pre-existing local paths unless forced. Thus the downloader source does not prove a clean historical installation or same-time creation of the current data. It is compatible with a mixed-existing-state history. The current 0.2.2 game ZIP release API metadata says its asset was created in 2024, whereas the JSON/PDDL ZIP asset records date from 2023. These are upload metadata, not generation timestamps; neither equal nor unequal upload dates prove generation lineage. Earlier common-path audits found the locally installed games match 0.4.0, while the retained 0.2.2 game bytes differ at all 4,027 shared game paths. The 1,207 old-only paths have no locally installed game and cannot be equated to a 0.4.0 game.

The local files' CRC/size alignment with the official trajectory/PDDL ZIPs and the game ZIP's same relative paths are therefore mutually consistent with a common public dataset lineage, but establish neither cryptographic per-member identity nor a particular game-to-trajectory generation receipt, prior task exposure, valid environment semantics, solvability or dataset version reproducibility. No original installation log, per-file generation manifest, archive-internal task-to-source checksum, creator statement, or signed upstream asset digest was found in the bounded existing audit records; this is not a claim that no evidence exists elsewhere. A fresh filename search of `/home/lizening/alfworld_data` to depth 2 for manifest/version/checksum/log/readme/archive markers returned no files. This bounded search does not establish absence of old receipts or logs in other locations.

## Data use and redistribution

The project repository's [software LICENSE](https://github.com/alfworld/alfworld/blob/aaba6870f86c5be6a08a491f32a50b906227bc3e/LICENSE) states MIT terms for the repository. The independent [issue #132](https://github.com/alfworld/alfworld/issues/132) expressly asks about the separately distributed task archives' terms, academic use, derived identifiers and redistribution; at the API read for this review it was open and returned zero comments (`issue132.json` and `issue132_comments.json` are snapshot-hashed). The question is not authoritative legal guidance and does not itself establish a prohibition or permission. In this bounded review no authoritative archive-specific grant or maintainer clarification was located. Keep the raw ZIPs in private temporary staging and do not redistribute or publish task contents based solely on the software LICENSE; seek an authoritative terms/source determination through an appropriate channel if the intended use requires it. No external message was sent in this task.

## Remaining evidence to seek without running or migrating tasks

1. Dated archive acquisition/generation manifests or upstream creator records that bind the exact game member to trajectory/PDDL content hashes, grammar/domain commit, seed and generation context; search historic private installation/provenance records and source history without disclosing task IDs. A same-release label, ZIP path, upload time or CRC32 is insufficient.
2. Once there is a separately reviewed scope permitting archive member reads, stream decompressed member bytes only to compute cryptographic hashes and compare local files—this would strengthen current CRC evidence but still would not alone establish the game-to-trajectory generation event. This review does not authorize or perform that extra operation.
3. Preserve distinct version fingerprints and source disclosure. Review a version-specific compatibility and immutable input-binding approach before any runtime inspection; do not patch the source tree or replace frozen assets. The current frozen SI-U1 evaluator is bound to another set/version and is not interchangeable.
4. Continue historical-use, unique-unit/layout, statistical precision and resource-feasibility reviews independently of checksum matching. The 1,207 file paths and 556 parent-name strings are not a certified task sample. This work is source investigation, not a prospective evaluation protocol or science-run authorization.
