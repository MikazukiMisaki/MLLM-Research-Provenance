# 动作编号格式试验的独立记录复算

Astra Main，2026年11月16日。独立标准库算法复算通过，未发现分类或计数差异。科学输入仅为获准的 `cases.json` 与 `sanitized_events.jsonl`；未读取或调用包内 `analyze.py`、未读取其结果 JSON 作为计算输入，也未运行模型、分词器、环境或 GPU。本次只创建这份审阅包，源文件字节保持不变。

## 事件与固定题面

32个计划调用键互不重复；每个键恰有一条 `prepared`、`call_start`、`raw_result`、`decision`，没有缺键、重复键或额外调用键。各阶段顺序与计划一致，每键满足准备、启动、返回、分类的先后顺序；唯一完成事件位于全部分类之后，并记录32次调用。

日志的提示文本、有序候选映射、case/family/行格式/输出格式均与固定题面一致；渲染提示包含对应题面原文。题面中的候选行、指定子目标与输出要求也分别对应其结构化字段。加载记录中的题面哈希与输入文件一致。这些是记录内绑定检查，不独立认证历史冻结时间或实际物理执行。

## 独立分类结果

算法直接使用保存的 `decision.decoded` 字符串，先自行判定形状和当前映射，再与原 `category`、`action` 比较；原分类不参与得出新分类。裸格式为完整的ASCII `A`加三位数字；括号格式为完整的同类编号外包一对ASCII方括号。不得裁剪空白、修改大小写、移除不符合要求的括号或提取子串。形状合规后，编号还必须存在于该调用的映射。

全部30个有效编号对应指定子目标，即有效输出内30/30、全计划联合计数30/32。两条格式不符为 `unknown-01-bracket-bare` 的 `[A002]` 和 `unknown-02-bracket-bare` 的 `[A003]`；它们继续是无效输出，没有恢复为动作。独立分类与原记录的分类、动作字段均无差异。

固定裸编号要求的8个同题行样式配对中，6对双方有效且编号及动作文本均相同，2对仅裸候选行有效。固定方括号要求的8对全部双方有效，编号及动作文本均相同。配对按case和输出要求连接，不按日志相邻位置连接。有效配对子集不能代表所有情境的语义反应。

## 复核边界

`raw_result`保存返回token IDs，解码字符串保存在 `decision.decoded`。本次独立性在于**分类、连接和汇总算法**，不在于重新解码：仅凭这两个文件，没有独立验证token IDs到字符串的转换或输入分词、模型权重和真实调用。每键返回记录齐全也不是对物理执行的独立认证。未新增合成测试或重复模型试验，未改判之前研究中的无效输出。
